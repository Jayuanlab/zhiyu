# 工程视角的智能体进化论

智能体的可用能力由任务目标、模型能力、可观测信息、工具与授权、状态管理、执行机制、验证与反馈共同决定。YAML 或 prompt 可以表达组合，但不能创造不存在的数据、工具、权限、运行稳定性或判断能力。补错层通常比继续增加提示词有效。

## 五个区分

1. **适应与进化**：本轮改写计划是临时适应；跨轮保留经验证且可恢复的方法变化才是系统进化。
2. **记忆与规则**：记忆保存带来源的状态和经验；规则改变未来行为。一次记录不应直接变成永久规则。
3. **候选与选择**：模型可以生成改动，选择需要真实行为证据。生成者自评分不能代替独立检查或可复现评估。
4. **能力与权力**：更高任务正确率不授权更多工具、外部动作或自主更新权限；权限变更按独立授权机制处理。
5. **配置与权重**：prompt、skill、数据路由、记忆、工具和执行器更新属于工程系统更新。模型参数训练是另一个过程，需要独立的数据、训练、评估和部署条件。

## 进化循环

```text
观察真实行为 -> 建立原因假设 -> 生成有限候选
-> 在匹配条件下检验 -> 按约束选择版本
-> 授权上线与观察 -> 保留条件性经验或回滚
```

环境变化会使旧改进失效。经验需记录生效条件、反例、来源和复查触发点；不要把某一业务的规则变成所有智能体的共同目标。不同任务可以共享更新流程，同时保留不同的成功标准。

## 上限与停止

- 观测缺失：补数据与状态，不以推断补造事实。
- 执行缺失：修工具或运行机制，必要时提出新能力方案；不能让配置假装实现它。
- 判断不足：改任务分解、证据或验证方法；必要时评估其他模型，不能只靠角色措辞。
- 反馈失真：先修验收和指标，否则系统会优化“看起来完成”。
- 不确定性过大：保留未知、限制行动、人工接管；不断重试不能解决所有问题。

当候选没有足够改进证据、越过边界、增加成本超过收益或损害其他任务时，不采纳或回滚是正确的进化决策。健康智能体不必每轮更新。

## 防止自我优化失控

保持观察事实、解释、候选变更、执行回执和评估结果分层。不要允许被评估者自行降低评分标准、删除失败样本或改授权规则。共用方法可以修订；保护、验证和发布机制应由外层受控过程管理。

通用知识保存“为什么在什么条件下有效”，业务技能保存“这类任务具体怎样做”。这让后续智能体能够更新其他智能体，而不把自己的一套习惯强加给所有角色。
