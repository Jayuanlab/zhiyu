# 评估与恢复

## 指标选择

先确定硬约束，再选任务收益和效率指标，不用单一总分掩盖失败。

| 维度 | 可选证据 | 常见假改善 |
|---|---|---|
| 任务结果 | 用户任务完成、正确产物、可执行建议 | 文字更长、模型评分更高 |
| 证据可信度 | 原始来源与论点对应、真实回执、时效 | 堆链接、转载冒充原文 |
| 稳定性 | 重复动作、恢复成功、失败原因可见 | 更多重试、隐瞒降级 |
| 边界 | 越权拒绝、隔离、审核保留 | 放宽 denied 换成功率 |
| 用户体验 | 找到结果、理解状态、审核/暂停/纠错 | 后端返回 success，正文却占位 |
| 成本 | 时间、token、工具、资金和人审负担 | 忽略失败样本或新增依赖 |

给指标注明分母、窗口和样本选择。既报告完成，也报告受阻、拒绝与未知；合理 no-op 和安全阻断可能是正确结果。资金收益等业务指标不能单独证明能力，按目标系统的实验口径评价。

## 场景与决策

- 正常：主要任务是否完成且用户能读取全部产物。
- 已知失败：旧版本的可复现缺陷是否被拒绝或修复。
- 扰动：来源失败、过期/冲突、超时、缺样本、上下文过长。
- 状态：重复触发、重试、副作用结果未知、并发版本冲突、过期排队任务。
- 边界：无授权动作、跨域数据、输入内恶意指令、取消/暂停。
- 恢复：有限重试、人工接管、回滚后再读与对账。

只选与本次改动有真实关系的场景。确定性检查验证契约，人工或独立内容检查验证语义；二者不能相互替代。使用公共失败样本开发，独立保留样本检查泛化。无法访问隐藏评估也不是获取它的理由。

同模型同预算的基线/候选对照有助归因；更换模型或依赖本身是候选差异，应单独记录。不能完全控制环境时记录混杂因素并限制结论。根据任务波动、风险和资源选择样本量，不把某次项目的“三次”“48小时”设为通用门槛。

## 控制更新频率

去重问题与开放提案，保留冷却期或观察窗口，避免更新尚未观察又继续更新。任务目标已变化时重设基线；不能用旧指标强行优化新目标。出现硬约束退化立即停止候选推进；证据不足时收集观测，健康时无变更。

## 回滚不是重置历史

保留基线组件与相关调度状态。恢复配置后核查实际加载版本、权限、未完成任务和外部回执。付款、发送、订单、发布等不能通过恢复 YAML 撤销；先对账再按授权补偿。日志、原始输入和失败试验结果保持可追溯。
