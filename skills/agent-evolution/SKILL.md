# 智能体进化

把智能体视为带状态、执行器与反馈的版本化系统。进化指在明确任务与边界下，可验证地改善行为；增加提示词、技能数量、工具权限或自评分不构成进化。此 skill 提供更新方法，不提供任何目标系统的写权限。

讨论进化上限、设计更新机制或解释“为什么 YAML 修改不等于变聪明”时，读 [工程进化原理](references/principles.md)。这是工程框架，不是模型权重自动训练方案。

## 先确定更新方式

- **分析**：盘点、诊断和提出可检验改动，不写目标配置。
- **已授权更新**：执行用户授权范围内的具体更新；已有授权不重复确认，仍遵守目标系统强制的审核和保护规则。
- **自主进化**：默认产生候选或提案；只有已配置且可验证的授权机制允许它执行特定更新。不得自行改变权限、审核规则、验证标准或自身更新权限。

目标系统没有隔离评估、版本化命令或自动回滚能力时，降级为可审阅文件差异、人工对照与明确的恢复步骤。不要声称不存在的能力已运行。

## 盘点真实系统

确认任务、目标用户、控制对象、成功条件、不做事项、授权范围和预算。读取**实际加载**的配置与技能、有效工具集、记忆权限、运行版本、任务状态及反馈；模板不等于运行配置，文件存在不等于已装载，声明 allowed 不等于实际可用。

批量分析时列出全部发现的目标，标明纳入、暂停、归档或不可访问，不把暂停当失败，不自动启动或恢复任务。记录观测时间、抽样窗口、证据缺口与覆盖范围。脱敏保存，避免把私人数据或密钥复制进通用 skill。

## 找对改动层

| 层 | 核查对象 | 适合的更新 |
|---|---|---|
| 目标与角色 | 控制对象、业务收益、职责冲突 | 缩清目标、接口与交接 |
| 观测 | 来源覆盖、新鲜度、真实性、失败状态 | 改采集与证据对应 |
| 状态与记忆 | 来源、版本、有效期、冲突、处理游标 | 可追溯状态与适用范围 |
| 规划与上下文 | 缺步骤、冗余、超窗口、无停止点 | 分阶段、收窄读取、预算与恢复 |
| 工具与执行 | 注册、参数、权限、幂等、真实回执 | 修接口或执行器；权限问题走授权机制 |
| 验证与交付 | 字段、语义、证据、完整产物、用户可用性 | 用失败实例增强独立检查 |
| 调度与环境 | 排队、租约、心跳、依赖、超时 | 恢复运行机制；别靠 prompt 掩盖 |
| 更新治理 | 候选、版本、审核、回滚与回归 | 完成更新闭环 |

区分观测事实、原因假设与未验证项。单个可复现的确定性缺陷可以支持修复；行为趋势需要任务匹配的多个独立样本。没有数据是未知，不是健康。一次用户编辑先作为局部偏好；验证适用性后才提升为共用规则。

## 提出最小有用候选

选择一个主要原因，写出“在条件 X 下，改动 Y 应使行为 Z 从基线 A 到目标 B；若结果 C 出现则否定假设”。包括被影响层、具体差异、来源证据、收益、退化风险、预算、停止条件与回滚。

更新应匹配原因：工具没注册就修注册，验收漏检就修验收，资料缺失就补观测。不要在每次失败后叠加长 prompt。联动更新必要时明确归因限制。健康系统允许保持原状。

构造候选前读 [变更记录契约](references/change-contract.md)。不要修改原始观测、历史回执或基线成绩；新版本可以重算理解层并保留关联。

## 用行为选择版本

基线与候选使用匹配的任务、数据快照、工具契约、模型条件和预算。结合正常任务、已知失败、边界与扰动场景，检查真实结果及产物，不只看工具次数和自评分。随机性较大时重复运行并报告不确定性；不足则 inconclusive，不能包装成通过。

硬边界与证据完整性先于综合分数。不得降低验收标准使候选胜出，不得把发现测试答案、隐藏评测集、私人信息或增加权限当改进。模型自审可提供意见，但不能独立证明自身事实正确。

按 [评估与恢复方法](references/evaluation.md) 选择与风险成比例的检查。简单可逆修改用针对性验证；高影响持续系统需要隔离对照与受控上线。没有用户授权的真实发送、资金、删除或业务写入不能充当测试。

## 更新并闭环

按目标系统实际机制保存基线与候选，使用版本校验和幂等命令，按授权发布或保留待审状态。回读实际装载内容、结构与工具边界；维持任务的暂停/归档状态。共享技能要核查所有受影响者；检查覆盖优先级，不要只改未被加载的副本。

上线后观察约定窗口中的任务结果、边界、数据缺口、成本及用户反馈。触发回滚时恢复受影响组件；配置回滚不等于撤销外部副作用，已有动作需对账和获准补偿。保留失败版本与证据。

最后分别报告：**分析发现、已编辑、已保存、实际加载、评估结果、生产验证、遗留项**。将有效经验保存为带条件、证据、版本、反例和复查时机的规则，而非泛化口号。避免重复提案和无反馈的无限更新。

## 通用经验与平台适配

跨领域复用上述流程；领域专属规则留在原智能体，例如交易约束、文档格式或新闻窗口。通用规则可因新证据修订，系统保护与权限边界由外层机制控制。

用于 Zhiyu 车间时再读 [Zhiyu 适配](references/zhiyu-adapter.md)。不要要求其他平台具备该文件中的工具或名称。
