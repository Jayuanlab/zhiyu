# 记忆系统治理实施计划

状态：首批已完成代码与隔离验收，完整体系仍按阶段推进。2026-10-20 用户授权后，适用性、读取降级、L2 增量投影、legacy 原子命令、连续任务绑定及桌面解释链路已实施；34 文件 474 项回归、完整类型检查、真实 PG、开发模式桌面与最终生产构建/桌面均通过，见[首批验收](../verification/memory-system-governance-2026-10-20.md)。日常实例装载和长期生产效果未验证。执行仍沿用现有审核、角色和 denied 边界。

方法依据：[工程控制论指导思想](../architecture/engineering-cybernetics-guiding-principles.md)、[agent-evolution](../../skills/agent-evolution/SKILL.md)。配套主记录、身份和 legacy 合同见[记忆数据归属](../reference/memory-data-authority.md)。范围是桌面 Web 及必要后端；不扩展到手机、原生客户端、市场性能比较、真实外发或交易试验。

## 1. 控制目标

让持续运行的 Work / Loop 在当前权限、业务状态和证据条件下接续任务：可解释地读取、保存、失效、纠错与恢复，不把消息、笔记、业务完成状态混成一份“长期真相”。

八项工作及优先级：P0 明确项目 / Work / 权限与适用性；P0 确定业务主记录；P0 统一读取失败；P1 统一证据身份与防循环准入；P1 L2 增量状态；P1 两类 checkpoint 与精确纠错；P1 桌面可见性；P2 渐进退出多余 legacy 双写。完成条件按每项独立判定，不将一次 LOG 成功概括成全部完成。

## 2. 被控对象

被控对象包括：原始观测与读取回执、Brain 候选及生效记忆、L2 场景状态、workingMemory、业务 checkpoint、召回与证据 reader，以及桌面审核和解释页面。控制量是记录版本、准入/失效、召回选路、当前主记录读取和可见状态，不改变车间使命或工具授权。

当前证据与缺口：

- 微信处理器已有 L1 note / task、L3 Brain 候选；实施前 L2 只聚合单批 items，首批增量实现见 §13 及验收记录。[processor.ts](../../apps/web/lib/interactions/processor.ts)、[scenarios.ts](../../apps/web/lib/interactions/scenarios.ts)
- Brain 主库是 SQL 条件 / 关键词筛选与规则加权，交互图谱是有界文本评分；不能以本计划推定已具备向量或成熟多跳图能力。[repository.ts](../../apps/web/lib/brain/repository.ts)、[context.ts](../../apps/web/lib/brain/context.ts)、[graph.ts](../../apps/web/lib/interactions/graph.ts)
- 主记录分散在 interaction_tasks、directives、chat work items、run、review、outbox；未发现独立正式 commitment 或项目注册实体，项目展示分组不能当注册表。[数据归属盘点](../reference/memory-data-authority.md)
- 工作记忆已经有版本、来源目录、审计与连续性门槛；2026-10-19 的样本模型保存 3/3、业务 2/3，只证实受控未决问题接续，未证明任意历史事实继承或长期稳定。[生产复测](../verification/memory-approved-final-production-2026-10-19.md)

## 3. 观测输入

观测来自不可变原事件、实际工具结果、源文档版本/网页快照、业务实体当前状态、用户纠错与审批回执。每次记录来源身份、时间、覆盖范围和 provider / detail / warning；“有引用”不等于“已读取”，“已读取”不等于“已证实”。

源内容不得作为高优先级指令；模型推断与用户明确断言标识不同。尚无可靠来源身份、过期、冲突或降级时保留 unknown / unverified，不自动以旧摘要补齐当前事实。盘点仅用源码与脱敏聚合信息，不为开发复制私信或业务正文。

## 4. 状态模型

### 4.1 项目、Work 与 scope

将 host 归属、访问权限和业务适用性作为三项独立结果：`ownership`、`accessDecision`、`applicabilityDecision`。沿用现有 user / Work / Loop 与 grant；项目标识必须从可靠主记录或 host 绑定解析。项目名称、提示词、目录、图实体别名只能作为查找线索，不生成授权。

跨 Work：先验证当前来源授权，再判断项目/任务适用性；同项目不自动允许跨 Work，已获准的跨项目历史证据也不自动成为当前事实。无法解析稳定项目身份时显示“项目未确认”，保留全局偏好和合法历史读取，不猜测归并。第一阶段可用带版本的 host 绑定适配已有存储，若需要正式注册表另留明确迁移步骤；不得先造一个模型可写 projectId 再用它做安全依据。

### 4.2 原文、派生与业务主记录

原始观测 → 候选理解 → L1 / L2 / 工作笔记 → Brain 投影之间保留根来源和派生关系。当前任务完成、履约、审批及外发状态以业务主记录为准；Brain 保存历史估计和 authorityRef。无法绑定正式承诺实体时标“未纳入履约跟踪”，不得声称已履约。

### 4.3 L2 完整目标与首批边界

首批已实现 `revision` / `previousSnapshotId`、`sourceRange`、批次 hash 的全谱系幂等、规范化场景 key 和事务锁；正式任务状态通过同事务投影关闭未决项。下面的显式游标、expectedVersion 接口、有效期与 confirmed / inferred 等完整字段分区仍是目标，不能整体当作现状。

稳定 key 包含 owner、实际权限范围、可靠场景身份与适用项目绑定；对每个 key 保存 `version`、`previousVersionRef`、`sourceCursor`、已处理来源集合/幂等摘要、`observedAt` / `computedAt`、`validUntil`、来源根及规则版本。状态拆为 confirmed（注明确认权威）、inferred、openQuestions、conflicts、历史失效项，不将综合 summary 写成已确认 currentState。

更新输入必须是上一合法版本 + 新增/纠正事件。使用 expectedVersion 与事务游标提交；重复事件不增事实权重、不重复创建任务，并发版本冲突重新加载，不最后写入覆盖。晚到事件按业务发生时间重算受影响状态；主记录变化更新对应引用；冲突无法解决时保留双来源和待核验项。失败不前移 cursor，不用空快照覆盖旧合法版本。

### 4.4 两类 checkpoint（保持分工）

| 类型 | 职责 | 继承边界 |
|---|---|---|
| 工作记忆 checkpoint | 运行中接受的 facts / hypotheses / openQuestions / nextAction 与版本、来源和原文投影回执 | 同范围、成功前序、有效期、策略、审计与当前权限检查；仍未核验，不重放 transcript 或旧业务动作 |
| 业务报告 checkpoint | 保存完整原报告，提取下一轮问题、待核验项、复查条件和时间窗 | 不继承事实断言和执行动作，不替代工作记忆保存回执，不自动批准 Brain |

现行兼容性见 [working-memory-continuity.ts](../../apps/web/lib/workshops/working-memory-continuity.ts)、[business-checkpoint.ts](../../apps/web/lib/loops/business-checkpoint.ts)。当前 `correctionsPresent` 的广义抑制不能直接称为精确依赖失效。后续将纠错绑定到实体 / 来源根 / 项目 / 字段 / 时间及依赖版本：只抑制匹配的旧事实、假设、行动；保留无关合法内容与未决问题。无法判定依赖时保留当前保守抑制并告警，不能为提高继承率绕过纠错，也不能删除历史保存事件。两类 checkpoint 独立呈现，不能把宿主从报告提交进度计为模型主动 LOG。

## 5. 控制器 / 智能体角色

host 负责身份、权限、版本、来源绑定、幂等、主记录读取、事务和审计。模型提出候选、说明假设与冲突、按获准工具整理进度。记忆平台生成召回计划和受权限过滤的 ContextPack；需求方处理 warnings。用户负责既有审核、纠错、暂停和范围调整。

图谱与摘要是派生索引，不独立授予事实可信度；质量管家只用聚合脱敏遥测，不读取其他车间正文或替其他车间行动。

## 6. 控制动作与工具矩阵

| 动作 | 输入 / 准入 | 幂等与审计 | 权限与回滚 |
|---|---|---|---|
| 解析项目适用性 | host 身份、合法项目绑定、版本 | 保存解析结果与不确定原因 | 不改变 grant；可退回 unknown |
| 读取业务主记录 | 已授权实体引用及当前版本 | 保存实际读取回执 | 不通过记忆修改任务或审批 |
| 读取记忆 / 证据 | requester、scope、目的与格式 | 类型化 outcome、provider、coverage | denied 无宽化回退 |
| 写入候选 | 原始根来源、派生链和准入结果 | commandId、requestHash、canonicalGroup | 同源去重；仍按既有审核 |
| 更新 L2 | previousVersion + delta + expectedVersion | 游标与快照同事务，事件可回放 | 可切回前一合法投影，不改原事件 |
| 保存 / 加载 checkpoint | 原回执、版本、策略与有效期 | 保存和装载分开事件 | 不续期、不重跑旧动作 |
| 失效受纠错影响的投影 | 精确依赖与纠错版本 | 受影响 / 未影响集合、原因 | 保留历史，误杀可按原版本重算 |
| 停止 legacy 双写 | 调用者清单、主写回执对照 | 每入口阶段开关与观察记录 | 保留历史，先可逆切读再停写 |

## 7. 边界与审核

denied 优先于 allowed；范围、读取格式与证据源缺失不能通过换表绕过。读取成功不授予动作权限，候选被召回不等于获准执行。审批、配置、发送、交易、删除仍走原工具与审批服务。本轮不自动恢复暂停任务、不创建真实业务副作用测试、不通过 SQL 绕开审核。

用户纠错保存为可追溯断言与修订；模型推断不得覆盖明确纠错。若纠错涉及主记录，则先展示受影响主记录与拟变更，再走既有业务修改流程，不能只改 Brain 使页面看似一致。

## 8. 反馈与评价

收集脱敏聚合：读取 outcome、scope 拒绝、项目 unresolved / 不适用、主记录版本不匹配、同源去重、循环准入拒绝、L2 cursor/version 冲突、checkpoint 保存/加载/跳过、纠错影响、legacy 路由和部分双写失败。现有 too_broad / too_narrow / missed_boundary / wrong_scope / stale_state 反馈继续保留。

下一轮用当前业务主记录、有效投影与失败原因决定重读/等待/人工接管，不把失败改写为零结果。指标按分母、窗口、调用者和版本报告；合理拒绝与无变化 no-op 不算故障。先验收边界和证据，再评价任务结果、用户理解与效率，不用一次模型自评证明改善。

## 9. 异常、扰动和降级

统一 outcome 见[数据归属合同 §4](../reference/memory-data-authority.md)：ok / empty / denied / not_found / unsupported / unavailable / degraded 分开。先迁移核心调用者，再保留明确的 legacy envelope 适配；旧调用者不能因新结构误判全部成功。

数据库故障、来源不可用、解析格式未知、引用无权、版本冲突和零命中分别给可执行恢复说明。获准独立回退保留原错误及 provider，不将摘要变原文或 candidate 变 confirmed。事件/审计落盘失败时不返回保存成功；游标不推进。预算不足整项跳过并解释，不能把截断的 checkpoint 当完整状态。

同源循环、非法项目标签、越权 ref、已过期授予、旧授权与新拒绝冲突、晚到纠错、重复重试、取消及租约变化必须作为扰动场景。失败恢复有界，仍服从原工具/请求/时间预算。

## 10. 页面可观测性

桌面 `/memory`、车间记忆页、工作记忆面板和运行详情使用同一术语，按需展示：内容属于原文 / 理解 / 候选 / 生效记忆 / 派生索引；项目身份与适用性；来源版本和已读范围；当前业务主记录链接；审核状态；纠错版本与影响原因；召回 selected / pinned / omitted / denied / warnings。

把“已保存”“已审核”“本轮已装载”“下一轮实际使用”“业务验证通过”分开展示。checkpoint 卡片注明类型、来源运行、有效期、版本、继承/跳过原因；不把版本零显示为没有历史笔记。失败或项目未确认有明确文字，不用空白与“暂无”掩盖。只展示获准脱敏原因，不通过 denied 提示泄露另一项目内容。

用户从现有审核入口纠错/批准候选，从现有 Work / Loop 入口暂停或调整；不增加与任务无关的重复确认。验收包括桌面主要流程、窗口缩放、键盘访问、长来源可读性和失败恢复。

## 11. 数据模型与兼容策略

先在现有结构化事件 / metadata 和服务层建立版本化 contract，再根据查询与唯一性需求决定是否增加一等列/索引；不可用自由 metadata 代替安全约束。拟记录 project binding、applicability、authorityRef、typed evidence identity、read outcome、L2 dependency/cursor、checkpoint dependency 与加载回执。

保留旧 ref aliases、canonicalGroupId、旧审核/修订版本、原事件和来源快照。历史缺字段按 unknown / legacy 标注，不能批量猜测后标已验证。迁移含 PG / SQLite schema 声明、实际迁移、回填 dry-run、冲突记录和检查命令；任何未执行步骤单独列为未完成，不把本地 schema 定义当目标环境已迁移。

Legacy 初始清单详见[数据归属合同 §6](../reference/memory-data-authority.md)。特别先处理 interaction legacy 成功而 Brain mirror 失败的部分成功语义。retention cleanup、embedding dream 与 short/mid/long 晋升引擎分别记录，不能因为都叫 memory 就一起关闭。

## 12. 测试与验收

测试应验证行为与边界，不只镜像实现。每阶段保留基线、候选、实际命令与结果；下表是完整目标，首批实施结果另列验收记录，不能把部分通过概括成整行完成：

| 验收对象 | 必须覆盖的反例 / 扰动 | 合格证据 |
|---|---|---|
| 归属与适用性 | 同名不同项目、同项目无授权、跨 Work 合法授权、项目未知、全局偏好 | 服务测试 + 实际 ContextPack，权限不扩大，原因可解释 |
| 主记录 | task 已完成但 Brain 仍旧；run completed 但待验收；未绑定 commitment；审批撤回 | 从正式实体版本得出状态，不靠模型覆盖 |
| 读取语义 | 真空结果、数据库故障、unsupported ref、越权 ref、部分 provider 失败 | outcome 独立；denied 不回退；UI 不混成空 |
| 来源准入 | 同原文多摘要/窗口、裸 UUID 歧义、文档新版本、派生自证、源读取失败 | root 去重与循环拒绝；原文/窗口身份不变 |
| L2 增量 | 重复事件、晚到纠错、并发版本、cursor 保存失败、跨 owner 场景同名 | 重放同一事件集合得到同一版本状态；失败不推进游标 |
| 两类 checkpoint | 错范围/过期/失败前序、原回执缺失、匹配/无关纠错、版本冲突 | 保存/加载分别可核对，不重放动作，未决项合法继承 |
| 桌面 | 查看来源、当前状态、纠错、召回解释、保存与装载、失败恢复 | 开发模式针对性浏览器证据；桌面缩放与键盘可用 |
| legacy 退出 | mirror 部分失败、重复调用、旧 ID 读取、切回旧 reader | 逐入口不丢历史、不重复长期投影，开关可恢复 |

程序检查按实际变更选取单元/集成/类型检查；不以全部绿替代生产语义。完整业务阶段及最终交付执行必要生产验收，在同一合法任务链核对主记录、原始事件、已保存回执、后续真实模型输入及用户可见结果。记录全部失败和降级，不通过重试挑选最佳成绩；生产验证不包含未经授权的真实发送、删除或资金动作。
