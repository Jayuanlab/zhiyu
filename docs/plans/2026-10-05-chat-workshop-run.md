# 对话内直接运行智能体车间

本阶段只补桌面普通聊天到既有车间执行器的一次运行入口和结果反馈，不改车间使命、周期调度或交易策略。

## 观测与原因

主人要求对话页直接运行“强化学习前沿学习者”。实际对话 `7829b37d-6050-4a27-95de-9fcf4040180c` 的持久用户消息 `e31ac0a2-4cef-495e-9e8c-b7fc8ea7d009` 是“运行一下强化学习前沿学习者”；助手只搜索和列出自动任务，称没有启动权限。

当前生产 review43 中车间 `b6e7ddb1-c699-4898-afa5-3d1804d6edd1` 为 active、autonomyLevel draft，尚无运行记录。两个周期 Loop 为 paused。只读观测有时间与来源记录，没有把暂停当失败。

实际 Native 工具集缺少车间运行能力。真实 Harness SDK 回放显示工具 unavailable；只添加合成同名工具，又被普通聊天外层权限队列拒绝。被控对象应为已有车间的一次执行，不是恢复暂停的周期 Loop。Loop 接纳、consumer 和 lease 都要求 active，不能用临时激活再暂停规避。

## 有限实现

- 控制目标：主人发出明确运行指令或点击“运行一次”后，由该车间自己的既有执行器按使命工作一次。执行事实与聊天正文分开。
- 观测与授权：普通聊天工具只绑定当前 owner 的持久用户消息和唯一目标，执行前重读。按钮以 owner 点击为动作，服务器核对聊天及车间归属。工作状态与配置版本来自实际数据库，不信任模型自述。
- 状态与动作：复用 `startWorkRun`、`work_commands`、审计和后台 consumer。稳定请求 ID 防止重复入队，版本变化不把同一次重试改成新动作；已有命令回读本轮实际状态。未启用/归档车间明确拒绝，不静默进入无人消费的队列。
- 边界：只普通聊天的合法绑定暴露零参数 `runWorkshopOnce`，Native denied/审核策略、只读证据流程及 Work 角色隔离优先。外层只放行已授权且实际暴露的该工具，非法参数立即拒绝。执行器继续按原 autonomy 和工具边界工作。
- 反馈：创建命令返回排队或实际当前状态，不把命令 succeeded 当业务完成。精确 owner/workshop/run 读取状态、错误和本轮产物，按实际 runId 展示，不以最近其他轮次代替。
- 桌面入口：实际创建、检查和运行回执附近提供“运行一次”。处理中禁用重复点击，固定请求 ID 支持未知结果重试。聊天卡片区分排队、运行、完成、失败、取消和需核对，读取失败保留最后状态并显示提示。
- 接管与恢复：提供真实 `workId/runId` 的车间工作记录链接，沿用现有审核、取消和纠错入口。来源更新、版本冲突、busy、网络中断和 worker 未消费均据实解释，不自动激活调度或重新执行不明动作。
