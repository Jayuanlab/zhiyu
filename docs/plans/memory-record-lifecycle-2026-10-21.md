# 记忆用途与运行记录生命周期治理

本阶段处理历史检查点、验收演练被当作长期 insight 的问题。可信状态（candidate/active/verified 等）、用途分类和当前任务适用性是三个独立维度。已审核不意味着应跨任务长期召回。

## 分类与边界

| 用途 | 保存什么 | 获取与生命周期 |
| --- | --- | --- |
| 长期记忆 long_term | 可复用事实、偏好、边界、经来源审核的独立经验 | 维持原审核、范围、来源、版本、有效期和出站校验；分类不会确认内容真实性 |
| 运行记录 run_record | 明确自述的研究检查点、每日审计检查点、阈值复核进度、召回质量运行检查点 | 创建后 7 天标为接续窗口，之后归档；两阶段都不进入长期 ContextPack。实际接续仍由原有同 Work/Loop、来源版本、租约、校验回执和有效期控制 |
| 验收记录 acceptance_record | 有演练标题、正文标记和工作记忆提升命令相互印证的验收样本 | 仅保留审计证据，不作为真实业务事实、策略或边界使用 |

接续窗口是展示与整理规则，不授予接续权限。普通运行记忆缺乏宿主证明时，不能被自动转换成有效检查点。实际 continuity 的运行事件、回执与原有 TTL 不被改写。

自动分类要求来源意图的组合证据；论文或经验提到 checkpoint、某个日期、单独 checkpoint 标签均不足以判定为运行记录。边界类型与 canonical boundary 不允许降为运行或验收记录。未明确识别的历史内容维持原状态，不把其默认长期分类解释为已经核实。

## 存储和控制闭环

被控对象是记忆记录的用途和模型可用性。原始内容、来源、状态、观测时间、创建和更新时间保持不变；新增 `metadata.recordLifecycle`，版本 `memory-record-lifecycle.v1`，包含分类、原因、权威来源、分类时间、接续截止和 `preserve_audit` 保留策略。历史库采用元数据扩展，无新增表或物理迁移。

唯一治理服务执行主人上下文命令：读取当前版本 → 锁定同一主人记录 → 校验 expectedVersion 与 commandId → 保存分类 → 同事务写审核回执和依赖失效账本 → 回读当前版本。拒绝运行中车间冒充主人、跨主人修改、命令身份冲突、过时版本、边界降类。分类变化会使已有依赖版本过期，不能静默沿用。

撤回引用准确审核回执，要求当前版本仍等于该次分类的结果版本，恢复之前的分类和可信状态。它保留原审核与依赖变更历史，不覆盖后续修订。运行记录归回长期用途时进入 candidate，重新核对来源；不会直接复活删除或被替代的记录。

新记录在统一 row 转换处分类，覆盖普通写入、旧写入口和车间镜像；普通模型写入不得指定受保护分类元数据。旧 upsert 不允许覆盖主人分类。ContextPack、最终 pack 重验、独立精确 reader 出站和依赖当前性均独立检查用途；分类异常按不可用处理，不能通过 owner_override 或 includeCandidates 绕过。列表在 SQL limit 前过滤，避免运行记录挤掉长期候选。

## 历史治理与恢复

工程命令 `scripts/govern-memory-record-lifecycle.ts` 先对明确主人准备独立计划，列出逐项 ID、原版本、分类证据规则和稳定 commandId；应用必须给出原计划哈希。应用逐项事务并保留成功、失败和冲突回执，重放不重复修改。不能声称整批全有或全无。rollback 使用相同计划逐项撤回原分类，当前版本有变化则拒绝覆盖。

日常库治理前保留完整记忆行快照、表计数和 worker 心跳。第一次预览扫描该主人 1,671 条（全库 1,740 条），建议 44 条运行检查点及 3 条验收记录。复核未命中样本后补齐带日期与审计标签的每日阻断回执、阈值复核回执、变更提案运行回执和月度研究检查点；第二版计划共 66 条运行记录、3 条验收记录。未应用第一版计划。3 条验收包含 1 条历史 superseded，保留其原状态，不重新激活。只有 checkpoint 单标签、实质为技术研究结论的候选不自动降类。未自动提炼其他研究结论，避免把工具过程或过时源码判断冒充稳定经验。

页面“来源与使用记录”提供按用途查看、生命周期说明、原文、创建时间、接续截止、分类原因、用途更正和撤回。返回长期用途不替代已有候选审核。超时保留同一 commandId 可重试；版本冲突明确提示刷新，不伪装成功。

验收覆盖：新写入分类、旧记录治理、正文不变、观察时间不变、幂等回放、跨主人拒绝、并发版本冲突、精确回滚、过时撤回拒绝、长期候选复审、边界保留、依赖失效、列表/ContextPack/独立精确读取出站隔离。数据库故障测试在随机隔离库执行；日常治理不注入故障、不唤醒 worker 或旧任务。桌面实测与生产装载单独记录。

阶段完成后继续观察新写入是否缺少明确用途信息。更大范围的运行日志结构化迁移、经验人工提炼及保留期限调整另行处理；本阶段不自动删除任何原文、运行事件、验收或备份文件。
