# 成功任务原始证据展开与严格生产补验

## 目标与原因

继续执行主人要求“成功轮次自主展开原始证据，再用生产版本确认严格验收”的新授权。上一阶段正式审计重放仍失败，只有该项未满足；FIX1、FIX2 各轮机制均通过。实际请求里已有完整当前纠错、来源引用、已注册且参数清晰的展开工具；实际工具历史中没有展开调用，因此不是遗漏统计。完整召回后的任务没有把原始观测核验明确列为交付要求，是本次局部候选针对的主要原因。

本候选只为同一受控演练 Loop 补充“采用当前纠错前，核对原始观测和来源类型”的任务要求。工具调用由模型自己选择当前记忆 ID 并发起，脚本不替模型预取、不注入原始正文、不指定答案或私有来源标识。不据此宣称所有普通任务都会自发查证。

## 状态、动作与边界

| 项目 | 本次约束 |
| --- | --- |
| 被控对象 | 同一车间、同一手动 Loop 的记忆来源核验、来源绑定 LOG 与跨轮继承 |
| 观测 | 原生产物理请求、模型工具调用、原始回执、实际下一份主请求、持久事件及终态 |
| 状态 | 原阶段记录不可变；新配置命令、新阶段意图、请求及审计各自保存，旧失败不改为成功 |
| 当前版本 | 复用已验证 review93；生产编译源和资源不变，仅更新版本化任务目标并重启带新阶段只读审计的 worker |
| 控制动作 | 当前 Work 版本下幂等更新 Loop 目标，保留原目标并追加查证要求；依次手动运行 EVID1、EVID2 |
| 权限 | 模型、工具、角色、审核、denied、手动触发、单车间 worker 范围及保存合同保持不变 |
| 反馈 | 原始来源确实由模型调用展开，完整回执到达后续主请求，且同一任务真实成功，才记为满足 |
| 继承 | EVID1 必须继承 FIX2 的确切检查点与原 TTL；EVID2 必须继承 EVID1，并各保存新鲜来源 LOG |
| 异常 | 任一硬边界、来源查证、完整性或任务终态失败，显式保留结果，不自动重跑或追加第三轮 |
| 人工控制 | 桌面完整工作记录可查看调用、来源、LOG、终态；原有暂停、取消、纠错入口继续有效 |
| 回滚 | 用实际当前版本提交幂等配置命令恢复保存的原目标；审计进程可恢复原启动器，记录不删除 |

当前执行器的历史结构化 `loopSpec.context` 有原有持久优先级。本次不修改该语义、不直接写持久状态；将明确的局部查证要求附加到实际读取当前行的 Loop 目标，并在每份实际普通主请求检查其装载。目标发生了有限变化，行为改善不能归因为程序更新或无提示的自发倾向。

## 预算、验证及停止条件

本次新授权最多两次任务、36 次物理模型请求；每轮 18 次请求、14 次工具调用、420 秒、一次任务尝试，无自动任务重跑。原授权实耗三次任务、38 次生产请求不变；更早累计七次任务、67 次请求不变。本次新增单独计数，总累计上限九次任务、103 次生产请求；五次更早认证诊断继续单列，不重置旧阶段预算。

先验证任务补充与命令只改变目标、没有注入记忆标识或答案、可幂等且可回滚；再验证审计能拒绝宿主代读、无模型调用、错误记忆、未返回后续主请求、失败任务、错误继承、缺少新 LOG、超额或来源不完整等情况。原严格标准不降低：至少一个成功任务必须有精确绑定的 typed owner 原始观测展开；两轮其他保存、召回、纠错、继承、辅助终态及运行清理检查继续完整执行。

先逐轮审计 EVID1，机制检查通过才允许启动 EVID2。最终交付区分配置已保存、当前目标实际装载、生产资源已核对、任务实际成功和严格总验收结果；保留上一阶段唯一缺项及所有更早失败。桌面 P2 展示问题本次不扩展改造，仍属遗留。

实际结果见[严格生产验收报告](../verification/memory-evidence-production-2026-10-18.md)：EVID1、EVID2 均由模型展开当前主人原始观测，完整链路及严格总验收通过，共两次任务、21 次生产请求，未追加重跑。保留本轮本地笔记版本与历史继承的模型文字解释不一致等 P2 问题，不以机制通过宣称文字解释也已完成修复。
