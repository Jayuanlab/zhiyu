# Jev 答案充分性第二阶段

## 目标与边界

被控对象是桌面记忆问答的证据覆盖率、充分作答率与等待时间。观测来自真实 owner-scoped 工具结果和单独的逐要点评分，不能用评分标准反向给答题端提供答案。本次不改变交易动作、权限、移动端或持续任务控制流程。

原始答题记录、标准答案、评分估计分别保存。历史金标准不覆盖，修正规则写入评测专用 `memory-answer-rubric-v2.mjs`，输出至独立的 `pi-answer-judge-v2` 目录。新旧回答都使用同一份 v2 规则，不能把换评分口径得到的增分算作实现提升。

## 实现

1. 模拟盘复合键按 `account UUID/record ID` 解析，读取白名单字段。成交关联委托同时限定 account_id 和 order_id，每次 SQL 都重新验证账户 owner_id。找不到、来源不可用明确区分，不接受模型给出的表名或 SQL。
2. 新增账户版本、委托状态及车间心跳统计。统计为当前读取，无法证明历史快照；心跳表为 0 只说明该表当前为空，不能推断持续任务从未运行。
3. 问题驱动的字段提示随真实工具结果返回，保留字段来源、null、空数组、长字段截断状态，提醒回答模型逐项覆盖。它是证据可用性提示，不是生成答案的正确性证明，也不加载测试题 ID 或金标准。
4. 只有架构源返回成功且存在未返回的候选时，才由 Jev 判断是否缺证据。低支持度允许一次相同问题、相同权限下的 architecture 定向扩展，limit 从 12 增至 24；没有循环。Jev 判断失败不补查，源失败不重试；扩展失败保留首轮证据并记录真实失败事件。

自动架构补查的预算为一次，不代表主模型其他工具调用已拥有统一全局预算。不存在可补读路径时明确缺口；本次没有增加逐答案的生成模型自审，避免额外一轮主模型调用。

## 评分规则

逐题保存必要要点，去掉未被问及的上下文字段，例如模型层级、消息内容类型、未询问的置信度和时间戳。长文本按实质要点评分，不要求全文复制。关系题要求正确建立对象关系，不要求背出外键名称。空表判断不得把搜索未命中冒充全表为空。交易员职责按当前角色文档校正，并保留原始金标准不动。

评分器必须为每个必要要点返回 pass/missing/wrong，程序验证要点 ID 和数量并由检查结果计算分类。此机制降低增减评分项的波动，但不能消除模型语义判断误差。真实数据变动及历史问题无法实时还原的限制须单独报告。

## 验收与恢复

已测试复合 ID、跨账户关联约束、错误用户无数据、来源失败、null 保留、最多一次自动补查与补查失败保留首轮证据。生产读取只读，无删除或外部动作。路由和补查继续输出 tool_use/tool_result 与决策审计事件。

开关 `BRAIN_JEV_TARGETED_RETRY=true` 只启用条件式架构补查；false 可关闭。`BRAIN_JEV_ROUTING=off` 恢复原始首轮决策路径。评测工具的 `--rubric-v2` 与服务端配置相互独立。

全量验收将重评上一轮 Jev 替代版的 100 份回答，再评新实现的 100 份回答，比较共同口径充分率和耗时。二者并非同时采样，延迟只能作为回归观察；不能声称严格同时间 A/B 因果结论。
