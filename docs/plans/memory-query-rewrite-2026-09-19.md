# 记忆召回查询改写与有限补查

## 范围与决策

本次控制对象是一次 `buildBrainContextFromMemoryRequest` 调用。默认单次召回，只有首次真正无匹配时，最多执行一次改写补查。较少命中、只有边界记忆、证据读取失败都不等于无匹配。跨问题推理仍由外层智能体负责。

原始 `taskIntent` 始终保留，用于 Brain 排序、审计和最终任务解释。首次 LLM 规划可以附带一个可选 `queryRetry`（query/searchTerms/reason），不增加第二次 LLM 规划调用。不配置模型或改写输出不合法时，保留原单次流程，不伪造别名。

## 状态、输入与动作

- 输入：原始问题、首次计划、实际候选、拒绝与过滤记录、数据源状态。这里只判断检索结果是否为空，不宣称判定答案充分性或事实真实性。
- 启动条件：首次 items 为空、各辅助路线 count 为零、没有 denied/omitted/warning、没有失败/降级/跳过路线，并且有不同的备用关键词。
- 动作：Brain 关键词取原有词与最多 6 个替代词的并集；知识库/图谱使用备用 query。仓库接收最多 18 个词，避免原有 12 个词把新增词截掉。
- 不变项：requester、scope、accessMode、sourceFilters、时间、状态、候选准入、置信度、分类、路线、每次候选量和返回量。改写对象不接受权限或过滤条件字段。每轮仍经过原有检索与权限链路。
- 意图约束：规划提示要求保留实体、日期、否定条件和原始目的，只用已知别名或同义表达。结构约束由代码保证；同义改写是否准确仍需真实样本评价，不能由 JSON 校验保证。
- 边界：首次有边界记忆就直接返回，不替换它、不为寻找更多事实绕过限制。权限拒绝优先终止补查；缺数据或过期证据交由外层说明或补充观测。
- 预算：每次平台调用最多 1 次规划、2 次召回；不会递归规划或扩大单轮 limit。这是单次调用上限，不是整个车间运行的全局 token/时间预算。外层重复调用仍须由既有运行预算限制。

## 审计与恢复

每次检索保留独立 context log，记录原始与实际执行 query。最终日志写入 `queryRetryOutcome`，包含原问题、改写表达、原因、轮数、停止状态和关联日志 ID；同时通过 `queryRetryTrace` 和 `recallPlan.queryRetryTrace` 返回。沿用带用户约束、锁与幂等冲突检查的 context audit 写入机制。

补查抛错时保留首次结果，标记 `retry_failed`，不暴露底层私密异常文本。最终审计写入失败向上报错，不伪装成功。来源返回 unavailable/degraded 时显式传播状态，不能当作正常空结果继续补查。

桌面车间事件与 Loop 召回卡片增加原生 details/summary 展开项，展示原问题、改写原因和停止状态，支持键盘操作。原有记忆审核与反馈入口继续负责纠错；本次不自动更改记忆事实或批准动作。

调用者可设置 `allowQueryRetry: false` 将补查交回外层智能体；运维可通过 `BRAIN_RECALL_QUERY_RETRY_ENABLED=false` 全局关闭，按部署方式重启相关进程生效。关闭后保留首次召回、审计与原有权限逻辑，无数据库迁移。
