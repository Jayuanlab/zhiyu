# Windows 安装包实施与验收

日期：2026-10-03。主人授权开始制作面向非程序员的安装包。范围为 Windows x64 安装、桌面 Web 与必要本地后台，不扩展手机端或重写原生主界面。

## 1. 控制目标

提供一个可以双击安装和启动的知遇工作台。终端用户无需 Git、pnpm、Docker、全局 Node 或手写环境文件。发布产物必须可离开开发目录运行。

## 2. 被控对象

安装版私有 PostgreSQL、Web、单 owner worker 和可选本地组件。只管理安装版自身进程与用户选定的数据目录，不接管当前开发数据库和其他服务。

## 3. 观测输入

发布清单、文件哈希、程序版本、数据库初始化与迁移回执、Web 健康响应、worker 心跳、模型配置检测。配置存在不代表模型可用；进程存在不代表业务已就绪。

## 4. 状态模型

安装目录保存只读程序；用户数据目录保存配置、私有数据库、工作空间、日志、运行状态和控制 token。状态分为首次配置、准备中、运行、暂停、失败和停止，事件保留时间、组件和可解释原因。密钥不得进入日志或构建清单。

## 5. 控制器与角色

轻量本地管理器负责组件生命周期与首次配置；现有 Work/Loop 继续执行各自业务边界。安装器和托盘不授予车间额外权限，不创建默认自动外发或交易任务。

## 6. 控制动作

安装、启动、初始化、迁移、暂停、恢复、备份、退出和升级。重复启动应复用现有管理器；数据库创建与 owner 初始化应幂等。管理操作写本地事件。迁移前备份并明确失败位置，不在失败后伪装就绪。

## 7. 边界与审核

所有服务仅绑定回环地址。管理接口使用私有 token 与同源检查。配置通过用户提交保存，沿用 denied 优先和既有审核；用户可暂停任务和退出后台。默认按当前用户安装，不改系统全局开发环境。卸载默认保留个人数据。微信必须在登录的桌面会话运行。

## 8. 反馈与评价

以真实安装、首次打开、健康状态、重启恢复、工作器回执和用户可用结果验收。区分代码已写、产物已构建、组件已启动、程序验证和干净机器验证，不用退出码代替端到端成果。

## 9. 异常与降级

端口占用自动选择空闲回环端口；组件失败显示原因和恢复入口。模型未配置或未检测时明确提示。可选组件未安装显式说明，不当成可用。停止按 worker、Web、数据库顺序；未知副作用不盲重试。

## 10. 页面可观测性

首次配置页使用中文，显示真实数据库、Web 和 worker 状态；提供打开工作台、修改模型、暂停/继续、备份和退出。后台运行、浏览器关闭、休眠和关机行为须说明。

## 11. 数据与发布模型

发布目录包含 Web standalone、独立 worker 与迁移入口、Node、私有 PostgreSQL、管理器、托盘和许可证清单。发布文件清单带 SHA-256；明确排除开发 .env、用户记忆、原始消息、数据库、缓存和日志。Python 等组件按实际打包状态标识支持范围。

## 12. 测试与验收

验证配置保密、管理接口越权拒绝、重复启动、路径隔离、数据库初始化幂等、模型断线、端口占用、停止顺序、工作器失败和数据保留。生产构建在独立输出目录运行；仅用任务专属测试目录和私有测试库，不启动用户原任务。最终留存安装包、哈希和实际验证记录。当前主机测试不能冒充没有开发环境的干净 Windows 测试。

## 13. 分阶段落地

1. 独立构建、管理器、首次配置、托盘、安装器和包边界检查。
2. 离开源码目录的实际安装与启动、数据库迁移、工作器和 Web 验收。
3. 可选组件的打包验证、升级与恢复故障验收、干净 Windows 回测。

具体状态与未完成项在部署记录中更新，不以本方案文字表示功能已完成。

## 14. 基础安装版之后的优先级

- P1：干净 Windows 主机、真实服务商生成和数字签名验收；升级失败与人工恢复演练。未通过前保留“基础试用版”定位。
- P1（历史基础阶段）：当时管理页明确微信/量化未安装，首页仍包含相关快捷示例，需按安装清单处理未内置组件入口，不能把入口存在当成组件可用。第 15 节完整组件版已实际内置这两项，此处不描述其当前安装状态。
- P2：发布资源瘦身。当前为保留运行依赖完整复制 npm 包，包含其他平台二进制、测试与源码映射，程序约 2.8 GB、清单约 15.7 万文件，安装会较慢。先识别实际动态资源边界，再逐项裁剪并重跑完整性、独立运行和安装卸载，不能以文件扩展名猜测所有运行依赖。
- P2：统一项目内现有“知语/知遇”品牌文案与本地安装场景的 Cookie/外部 SDK 行为；保留现有 CSP 拒绝记录，不通过放宽策略掩盖日志错误。

这些后续项尚未完成，不作为当前已验收基础范围的能力承诺。

## 15. 微信与量化组件封装（用户授权继续，2026-10-03）

本阶段把两条微信链路与量化链路纳入同一安装包，不要求终端用户安装 Python、pip 或手动运行服务。现有基础包及验收记录保留，新增版本重新构建与验收，不能仅修改“已安装”标志。

- 被控对象：私有 Python、量化内部执行进程、微信读取 CLI 与桌面发送进程。后台管理器只操作本安装目录与个人数据根内的组件，退出时先收尾控制动作，再停止进程和数据库。
- 观测与状态：使用固定发布清单、依赖导入回执、实际组件健康、运行 PID、最近请求与失败原因；微信窗口存在不等同已经登录，模拟盘行情须继续显示提供方、新鲜度、范围与降级警告。配置、账户、缓存、原始消息、发送账本与日志分别存于独立数据根；不携带开发机账号、密钥、旧盘或微信数据库。
- 控制动作：用户先保存组件选择，再由管理器初始化与启动。量化以稳定账户和命令 ID 幂等创建初始现金 100 万元、无持仓的模拟账户；专用数据库角色只访问必要模拟盘表。微信读取须用户明确授权并初始化，发送另有开关，仍走既有审核及确认，不自动外发。
- 边界：安装模式只用绝对资源根和私有解释器，拒绝全局 Python、开发 `.env` 与目录回退；关闭自动扫描其它磁盘的行情源。微信私有 IPC 按用户数据目录隔离并认证。`denied` 优先、角色分工、交易仅模拟、原始观察与理解分层等现有规则保持。
- 反馈、降级与接管：管理页展示已安装、未启用、待授权、初始化失败、运行及停止未确认等真实阶段，保留最近检查时间与安全错误码。用户可暂停任务、停机改配置、重新检测或按可见权限提示接管；失败不写假成功，未知发送或交易结果不生成新命令重试。
- 用户审核入口：首次配置管理页启用量化、授权本人微信读取及允许经审核发送；微信客户端由使用者安装登录，必要的系统权限请求由用户点击触发。微信版本兼容、消息读取及送达不能由打包成功推出。
- 验收：私有 Python 和原生 DLL 在仓库外导入；隔离新账户的初始化、身份拒绝、重复命令、暂停、重启和备份；读取 CLI 的版本、配置及 IPC 隔离；发送端用安全夹具验证授权、确认、限流、未知结果禁止重发和退出。最终整包全哈希、桌面页面、实际安装与卸载保留资料重验。打包验证不得读取本机日常微信、发送真实消息、写开发模拟账户或调用付费模型。

真实微信账号和具体客户端版本的读取/发送、干净 Windows、数字签名及真实模型生成仍单独留作生产验收，未执行不得标记完成。
