# Jev 判断替代与耗时闭环

目标是减少端到端耗时，同时记录答案质量变化。原有 evidence check 是召回后新增的一次判断，不能自动等同于省去主模型调用。

## 流程盘点与接入

| 环节 | 本次处理 | 边界 |
| --- | --- | --- |
| Brain 召回计划 | `BRAIN_JEV_ROUTING=replace` 时用 Jev 固定路由及原有规则计划，跳过通用模型规划 | 保留原始问题、ID、范围与规则风险约束；失败退化为规则并记录原因 |
| 桌面 Pi 直接聊天首次召回决策 | Jev 分类后提前执行已授权的 platformRecall，将真实结果交给第一轮主模型 | 只使用原有 owner-bound、guarded 工具；没有授权工具就不调用 |
| 召回后的充分性检查 | 原有 `BRAIN_JEV_MODE` 独立保留；本次耗时实验关闭 | 属于新增检查，不能计作已经替代的一轮模型 |
| 空结果、补查触发 | 保留现有规则及有界补查机制 | 替代模式规则计划目前不生成自由文本 queryRetry，存在复杂问题召回质量损失 |
| 排序与过滤 | 保留现有确定性规则；active evidence check 仍可独立启用 | 不为原本无需模型的逻辑增加 Jev 调用 |
| 权限、拒绝、跨用户边界 | 保留代码硬约束 | Jev 的分类不能授予权限；denied 优先 |
| 最终答案、长文本理解、问题自由改写 | 保留生成模型 | 固定选择分类不能替代生成内容 |
| Pi plan/execute、Claude 和车间持续执行入口 | 本次不加入聊天预取；若调用 Brain 规划，则共享规划替代 | 不自动执行计划，也不改变持续任务控制流程 |

分类输入是当前完整问题，发送前脱敏；输出限制为六种固定类型。Jev 请求有 2 秒上限，低置信度、异常响应或失败会记录 degraded。聊天入口恢复已有工具流程，Brain 入口退化为规则规划，不额外回退到通用规划模型。

提前召回会产生真实 tool_use/tool_result，路由事件记录状态、原因、模型版本及耗时；Brain 上下文记录规划模式与路由结果。返回证据作为不可信数据，不能覆盖权限或写操作要求。模型仍可在缺少具体事实时执行定向读取，不能保证每道题都只调用一轮主模型。

## 验收与回退

以同代码、同问题、同模型、同并发的替代开关 A/B 检查：请求完成率、主模型轮数、端到端中位数与尾延迟、答案充分性及拒绝边界。真实记录会变化，主模型也有随机性；小样本结果不能当作全量稳定提升。

本地开关写入环境配置后需重启服务。设置 `BRAIN_JEV_ROUTING=off` 可恢复原有规划和聊天路径；`BRAIN_JEV_MODE` 仍单独控制充分性检查。无密钥部署保持示例配置 off，不以静默成功掩盖缺失配置。
