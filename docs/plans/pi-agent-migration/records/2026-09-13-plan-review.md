## 3. 修订结果

| 原草案/容易误解之处 | 本次结论 |
|---|---|
| cron仍有Claude执行入口 | 当前是拒绝桩；保留禁用，不能重新开放孤立cron |
| native接口可以排除 | Web Chat使用该接口，纳入P5 |
| 每attempt可换引擎 | 统一为同run所有attempt固定快照，新run才切 |
| 需要另造运行配置快照 | 复用现有Harness，补实际配置、runtime hash和缓存身份 |
| execution guard已覆盖全部权限 | 它主要处理租约/取消，业务授权wrapper必须保留并统一 |
| 内部草稿天然不外发 | 创建outbox草稿可能自动发送，按最终副作用分类 |
| 失租后的结果不能写 | 宿主仍可核对原attempt晚到回执，不能重新派发 |
| 当前build包含迁移 | build已分离，仅build:with-migrations显式迁移 |
| 冻结标签可直接生产回退 | 需兼容新schema/守卫的Claude构建，标签只是源码证据 |
| 换Pi即完成多智能体 | 本次先等价迁移，协作另验权限/预算/恢复 |

另外登记两个待复现的基线风险：Chat实例Map的跨请求计划读取；Harness的原始modelConfig与实际tier/user/env配置不一致。这些是静态发现，不记为已复现或已修复。
