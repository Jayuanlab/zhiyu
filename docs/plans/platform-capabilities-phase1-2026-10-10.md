# 平台能力匹配第一阶段

后续主人已调整方向：以 [先恢复智能体功能，再考虑 Jev 优化](agent-first-functional-baseline-2026-10-10.md) 为当前方案。本文件保留此前阶段设计与验收历史，不再代表当前默认执行策略。

日期：2026-10-10。用户授权开始修改。范围限桌面 Web 对话与必要后端，沿用现有 Work → Loop → Agent → Tool；不增加中央 Runtime、业务状态数据库或新的审批流程。

## 本阶段结果与边界

把 Brain 规划、平台资料预取、平台能力匹配分开配置。默认规则；Jev 只作为可选的候选建议器。对话继续显示普通文本，管理与运行细节仍在车间页面。没有检索重排、异常归组、报告评分、自动关闭待办或新外部动作。

共享目录以本轮实际装载的工具为输入，复用 agent-tools 注册信息补充用途与风险；参数来自实际工具 schema。静态注册不代表当前可用，拒绝和需审核均排除。未知风险明确标为 unknown。返回契约只说明 guarded 业务结果、执行回执与模型内容的位置，不编造每个工具未声明的业务字段。工具或 schema 过大、非 JSON 数据、getter 和循环引用均明确披露裁剪。

`listPlatformCapabilities({ query?, offset?, limit? })` 是只读入口。省略 query 分页查看接口及参数；提供 query 得到建议。建议不填参数、不执行、不授予权限。当前自动接入普通 Pi 对话；共享目录与匹配器可接受其它运行时的实际工具集合，尚未将所有 Workshop／Loop／MCP 运行时接入自动匹配。

## 控制模型

| 项目 | 实现 |
| --- | --- |
| 被控对象 | 本轮能力建议和一次有限的资料预取；长期车间仍由既有控制 Host 管理 |
| 观测输入 | 当前用户请求、实际工具定义、有效 runtime policy、已保存且归当前所有者的对话指令与当前 Host 验证的对象绑定 |
| 新鲜度 | 验证当前消息仍是该对话最新用户指令且文本一致；更晚指令、其它对话、对象不存在或读取失败时不使用该历史上下文 |
| 状态 | 复用已保存的聊天消息、车间关联、reasoning/tool_use/tool_result 和 guarded 回执；不新增事实库 |
| 控制动作 | 匹配仅返回有限候选 ID；预取只调用已有 guarded platformRecall；实际写动作继续使用原始工具与主人绑定命令 |
| 安全边界 | 目录复用实际执行 policy，denied／require_approval 优先；推荐不能解除拒绝或把模型叙述变成授权 |
| 反馈 | 记录规则／Jev、问题版本、脱敏输入 hash、候选及分数、耗时、用量、弃权／降级与真实工具回执 |
| 异常与降级 | 无匹配、缺对象、低分、超大输入、取消、超时、网络或数据源失败均交回普通工具流程；不报告虚假执行成功 |
| 用户纠错 | 主人继续在对话中明确对象和指令；已有车间页面提供运行查看、暂停和纠错；不增加重复确认或工作卡 |
| 页面解释 | reasoning 以普通中文说明能力建议、资料预取与不完整上下文，保留原始事件；候选匹配不显示成“已执行” |

## 调用与配置

```ts
const catalog = buildPlatformCapabilityCatalog({ tools, policy, runtime: "chat" });
const suggestion = await suggestPlatformCapabilities({ question, catalog, context, signal });
// suggestion.capabilityIds 只供主模型参考；实际调用仍走已有 guarded tool。
```

| 配置 | 默认 | 可选值与作用 |
| --- | --- | --- |
| BRAIN_RECALL_PLANNER | rules | rules：本地规划；llm：显式恢复原生成模型规划，失败仍保留 fallback_rules |
| PLATFORM_RECALL_PREFETCH | rules | rules：明确平台对象的有限预取；jev：可选资料来源判断；off：关闭预取，普通读取工具仍在 |
| PLATFORM_CAPABILITY_ROUTING | rules | rules：明确接口／功能请求；jev：只有模糊的功能请求才调用 Jev；off：关闭自动建议，原工具仍在 |

旧 `BRAIN_JEV_ROUTING=replace` 不再同时支配上述三条链路；仅旧的直接 router 调用保留兼容。`BRAIN_JEV_MODE` 证据检查与 `BRAIN_JEV_TARGETED_RETRY` 有界补读保持独立，未扩大使用。代理继续复用 `fetchTypesafe`，未改 `.env`、API 密钥或网络代理。

连续指代只使用服务器上下文：当前轮已验证 control／run 绑定的车间可作为建议目标；否则验证 owned chat、当前已保存消息，取此前至多两条用户文本。最近一次任务接纳的车间关联可能已经不是当前话题，因此不将它直接认作 confirmedTarget。助手的“已创建”、粘贴工具输出或请求 JSON 的 conversation 不用作确认对象。前文只帮助解释当前问题，不恢复旧任务、不授予动作权限。前置预取遇到明确代词时带入当前已验证对象 ID；缺对象或对象不确定交回完整对话与原工具，不自动拼入旧 ID。

Jev 固定版本 `jev-1.13.0`，一次 Choice（含 no_match）与候选独立 fits 判断；检查所选候选本身的 fits、Choice 分布与 confidence。候选、请求和响应均有预算，2 秒内退化，外部取消立即停止。只发送脱敏的请求、有限上下文和接口用途，不发送完整聊天、参数 schema、函数或授权令牌。阈值是保守工程策略，尚未通过中文生产保留集校准。

## 验收与下一阶段

验收覆盖默认不调用 Jev、配置互不影响、静态注册不能虚构能力、禁止／需审核优先、当前工具子集、接口分页、不同模块匹配、代词对象缺失与变化、脱敏、低分／无匹配／错误候选、取消、超时与安全降级。保留原有 YAML 应用、车间运行／交办、权限与资料回执的回归测试。

实现阶段的程序验证见同日第一阶段验证记录；review78 已部署并完成固定条件的真实 Jev 对照及三轮桌面验收，证据见 [部署与真实对照验收](../verification/platform-capabilities-production-and-matched-2026-10-10.md)。生产默认为 rules，尚无证据支持每轮强制 Jev。会话后台刷新中的时间精度缺陷已修复，相关 96 项通过，生产 GET 和新会话的问答顺序、当前问题识别验证通过；三题严格通过 1/3，统计零值和车间最近结果仍有缺口，不标记全部完成。

本阶段到此收尾。下一阶段限定两个方向：一是识别当前记忆统计请求明确列举的原始状态标签，复用完整范围证明及已有 renderer 输出缺席组的零值；二是提供“精确已授权 Workshop → 最近 1 条运行”的只读入口，再复用已有结果分页及验证限定。历史 25 条投递 unknown 单独核对渠道证据及人工接管，不混入能力匹配修复。其它运行时接入、检索重排和报告评分后置，避免长时间扩大改造方向。
