# 量化市场数据源分层与本地通达信改造方案

## 1. 控制目标

把量化系统的数据访问从“前台临时抓外部接口”改造成“本地通达信行情底座 + 本地市场宇宙 + 腾讯实时补价 + 后台慢源补全”的闭环系统。

目标不是找到一个永远不会失败的外部接口，而是让系统在东方财富 502、代理异常、Tushare 频控、问财返回空表时，仍然能稳定回答：

- 当前使用哪个数据源。
- 数据是否新鲜。
- 数据源是否失败。
- 失败后是否降级。
- 页面是否可以快速返回。
- 自选股猎手是否能持续发现候选股。

## 2. 核心结论

本项目后续按“本地通达信优先”路线改造。

```text
本地通达信 = 本地行情缓存、K线、趋势、复盘和板块底座
market_universe = 候选发现主输入
腾讯报价 = 前台实时补价
Tushare = 低频基础信息补全
东方财富 / 问财 = 后台补行业、概念、资金流和主题扩展
```

东方财富不再作为前台主链路。AkShare 的东方财富全市场分页接口不再阻塞页面。

## 3. 当前问题

### 3.1 东方财富链路不稳定

当前机器访问东方财富 `push2.eastmoney.com` 存在两类失败：

- 直连时远端会断开连接，表现为 `RemoteDisconnected` 或 `server closed abruptly`。
- 走本地代理 `127.0.0.1:7897` 时，经常返回 `502 Bad Gateway`。

这说明问题不是单纯代码拼 URL 错误，而是当前机器到东方财富 CDN / 代理上游链路不稳定。

### 3.2 AkShare 封装隐藏真实失败

AkShare 使用方便，但它会隐藏底层分页、请求头、代理和异常细节。`stock_zh_a_spot_em` 需要分页扫全市场，失败后可能表现成 ProxyError、JSONDecodeError、HTML 502 或几十秒卡顿。

AkShare 可以保留为后台补充源，但不能作为前台同步主源。

### 3.3 候选发现需要本地化

候选发现不能每次依赖外部动态接口。之前“电池 / 通信设备 / 贵金属 / 农业”出现过空转，本质是固定种子覆盖有限，而动态全市场源不稳定。

现在应把候选发现主输入沉淀为本地 `market_universe`，再由本地通达信、Tushare、问财、东方财富在后台持续补全。

## 4. 被控对象

本方案的被控对象是“量化市场数据供应系统”，包括：

- 本地通达信数据目录。
- 全市场股票基础池。
- 行业 / 概念 / 主题映射。
- 实时行情报价。
- K 线和趋势数据。
- 候选股发现。
- 市场温度、成交额、市场宽度、行业热度。
- 数据源健康状态。

最终服务两个智能体：

- 自选股猎手：发现候选股，维护自选股池，生成调整提案。
- 操盘交易员：消费当前自选股，做模拟盘交易和复盘。

## 5. 数据源分层

### 5.1 本地通达信层

本地通达信是核心增强源，不是边缘补充源。

| 数据 | 路径 / 方式 | 用途 |
|---|---|---|
| 日线 K 线 | `vipdoc/{sh,sz,bj}/lday/*.day` | 趋势系统、复盘、技术指标 |
| 分钟线 | `vipdoc/{sh,sz,bj}/minline` / `fzline` | 盘中巡检、分时确认 |
| 自定义板块 | `T0002/blocknew/*.blk` | 自选池、候选池、人工观察池 |
| F10 / 个股资料 | 通达信本地或 mootdx | 基础资料补充 |
| TCP 行情 | `mootdx` | 本地文件不足时补 K 线、盘口、F10 |

第一阶段先做本地目录探测和状态可观测。用户安装通达信并下载离线数据后，通过 `QUANT_TDX_LOCAL_PATH` 或 `QUANT_TDX_LOCAL_PATHS` 配置路径。

### 5.2 本地状态层

| 数据 | 用途 | 特点 |
|---|---|---|
| `market_universe.json` | 候选发现主输入 | 快速、可控、可追溯 |
| `watchlist_universe.json` | 自选股 / 候选池历史沉淀 | 本地稳定 |
| seed pool | 兜底主题池 | 覆盖有限，但不会失败 |
| `market_snapshot` | 市场温度、宽度、成交额 | 后台刷新，前台消费 |

### 5.3 快速外部源

| 数据源 | 用途 | 策略 |
|---|---|---|
| 腾讯 `qt.gtimg.cn` | 实时报价、涨跌幅、成交额、换手、PE/PB | 前台可用，批量限时 |
| Tushare `stock_basic` | 股票基础信息、代码名称补全 | 低频后台用，不能高频刷新 |

### 5.4 慢源 / 不稳定源

| 数据源 | 用途 | 策略 |
|---|---|---|
| 东方财富 push2 | 行业、概念、资金流、全市场补充 | 后台串行、限流、熔断 |
| AkShare 东方财富封装 | 临时补充或离线刷新 | 不进入前台主链路 |
| 问财 / pywencai | 主题扩展、语义候选发现 | 后台补充，失败不影响前台 |

## 6. 状态模型

### 6.1 tdx_local_status

本地通达信状态需要结构化暴露：

```json
{
  "enabled": true,
  "available": true,
  "selected_root": "D:/new_tdx",
  "daily_files": {
    "sh": 2200,
    "sz": 3300,
    "bj": 200
  },
  "minute_files": {
    "sh": 1200,
    "sz": 1800,
    "bj": 0
  },
  "block_files": 12,
  "latest_daily_file": {
    "path": "D:/new_tdx/vipdoc/sh/lday/sh600519.day",
    "modified_at": "2026-08-25T01:30:00Z"
  }
}
```

当前已新增接口：

```text
GET /market/tdx/status
```

### 6.2 provider_health

后续需要新增数据源健康状态：

```json
{
  "provider": "eastmoney_push2",
  "capability": "industry_concept",
  "status": "degraded",
  "last_triggered_at": "2026-08-25T11:30:00+08:00",
  "last_success_at": "2026-08-25T10:10:00+08:00",
  "last_error": "502 Bad Gateway",
  "last_count": 0,
  "last_latency_ms": 3021,
  "consecutive_failures": 3,
  "cooldown_until": "2026-08-25T11:40:00+08:00"
}
```

### 6.3 market_snapshot

市场温度、成交额、市场宽度、行业热度应使用全市场快照，而不是只看自选股。

```json

  "generated_at": "2026-08-25T11:30:00+08:00",
  "provider": "tdx_local+tencent",

  "up_count": 3120,
  "down_count": 1890,
  "limit_up_count": 72,
  "limit_down_count": 8,
  "total_turnover_billion": 8420.5,
  "industry_heat": []
}
```

## 7. 候选发现流程

### 7.1 前台同步流程

```text
输入 theme
  -> 生成 keywords
  -> 查询本地 market_universe
  -> 命中股票列表
  -> 腾讯批量报价补实时字段
  -> 本地通达信补趋势/K线摘要
  -> 按主题匹配度、流动性、动量、质量、风险打分
  -> 返回候选股
```

前台流程禁止直接等待：

- AkShare 全市场分页。
- 东方财富行业概念全量抓取。
- 问财语义搜索。
- Tushare 高频刷新。

### 7.2 后台扩展流程

```text
候选命中不足
  -> 记录 shortage event
  -> 提交后台扩展任务
  -> 查询本地通达信 / Tushare / 问财 / 东方财富
  -> 归一化为 market_universe_item
  -> 合并到 market_universe
  -> 更新 provider_health
```

后台扩展不影响当前前台返回。

## 8. 控制动作与工具矩阵

| 工具 / 动作 | 前台可直接调用 | 后台调用 | 失败处理 |
|---|---:|---:|---|
| 读取本地通达信状态 | 是 | 是 | 未安装时显示 unavailable |
| 读取通达信 K 线摘要 | 是，限量 | 是 | 文件不存在时降级为无趋势摘要 |
| 读取通达信自定义板块 | 是 | 是 | 目录不存在时跳过 |
| 读取 `market_universe` | 是 | 是 | 文件不存在时用 seed pool |
| 腾讯批量报价 | 是 | 是 | 超时后返回 stale quote 或无实时字段 |
| Tushare 基础信息 | 否 | 是 | 频控后冷却 |
| 东方财富行业/概念 | 否 | 是 | 502 / 断连后熔断 |
| 问财主题扩展 | 否 | 是 | 空结果记录，不覆盖已有宇宙 |

## 9. 页面可观测性

量化页面和智能体车间需要能看到：

- 本地通达信是否可用。
- 当前识别到的通达信目录。
- 日线 / 分钟线 / 板块文件数量。
- 最新本地行情文件时间。
- 当前市场数据源。
- 最近全市场快照时间。
- 各 provider 最近状态。
- 是否使用降级结果。

页面展示建议：

```text
数据源状态
  本地通达信：未配置 / 可用 / 数据过期
  腾讯报价：正常，最近 180ms
  本地候选宇宙：138 只，更新于 10:17
  东方财富：降级，最近 502，冷却中
  问财：失败，返回空
  Tushare：可用，低频模式
```

## 10. 异常、扰动和降级

| 异常 | 系统处理 |
|---|---|
| 未安装通达信 | `tdx_local.available=false`，不影响前台 |
| 配置目录不存在 | 显示 searched_paths 和 setup_hint |
| `vipdoc` 存在但没有 K 线 | 标记 coverage_low |
| 通达信数据过期 | 标记 stale_tdx_data |
| 东方财富 502 | 记录 provider_health，进入冷却 |
| 返回 HTML | 标记 invalid_response，不当 JSON 解析 |
| 问财返回空 | 记录 empty_result，不覆盖本地宇宙 |
| Tushare 频控 | 记录 rate_limited，延长刷新周期 |
| 腾讯报价部分失败 | 返回已成功报价项，标记 partial_quote |
| requested=0 | 标记 skipped_empty_input，不算 provider_failed |

## 11. 分阶段落地计划

### 阶段一：本地通达信状态可观测

- 新增本地通达信路径探测。
- 支持 `QUANT_TDX_LOCAL_PATH` / `QUANT_TDX_LOCAL_PATHS`。
- 新增 `GET /market/tdx/status`。
- 将通达信状态接入 `/storage/diagnostics`。

### 阶段二：读取本地 K 线摘要

- 解析 `.day` 日线文件。
- 为候选股和自选股补最近 N 日趋势摘要。
- 趋势系统优先读本地 K 线。

### 阶段三：读取通达信自定义板块

- 解析 `T0002/blocknew/*.blk`。
- 将人工板块合并为 `market_universe` 的来源之一。
- 保留来源、更新时间、板块名。

### 阶段四：全市场快照后台化

- 后台生成 `market_snapshot`。
- 市场温度、成交额、市场宽度、行业热度读快照。
- 前台不再临时抓全市场。

### 阶段五：慢源健康状态和东方财富收口

- 新增 provider health。
- 新增 `eastmoney_client`。
- 东方财富只允许后台限流调用。
- AkShare 东方财富链路只允许后台使用。

### 阶段六：mootdx 增强

- 安装并接入 `mootdx`。
- 探测可用服务器。
- 本地文件不足时补 K 线、盘口、F10。

## 12. 验收标准

- 没有安装通达信时，`/market/tdx/status` 明确显示 unavailable 和 setup hint。
- 安装并配置通达信后，能识别 `vipdoc`、`T0002`、日线文件数、分钟线文件数、板块文件数。
- 前台候选发现不等待东方财富、问财、AkShare 全市场分页。
- `电池 / 通信设备 / 贵金属 / 农业` 候选发现仍能从本地宇宙返回。
- 量化页面首屏不被全市场慢源阻塞。
- 数据过期、数据源失败、降级原因都能在页面或诊断接口看到。

## 13. 最终形态

```text
自选股猎手 / 操盘交易员 / 量化看板
  -> 本地通达信 K线/板块/趋势
  -> 本地 market_universe
  -> 本地 market_snapshot
  -> 腾讯实时补价
  -> provider_health 判断数据可信度
  -> 返回结果和降级说明

后台刷新器
  -> 通达信本地数据入库/摘要
  -> Tushare 低频补基础信息
  -> 东方财富受控补行业/概念/资金流
  -> 问财补语义主题
  -> 写入本地状态
```

一句话：

> 本地通达信成为量化系统的行情和趋势底座；腾讯负责前台实时补价；东方财富和问财只作为后台受控补充源。
