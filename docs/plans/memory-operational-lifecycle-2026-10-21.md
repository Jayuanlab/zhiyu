# 行情、日报与混合内容的记忆治理

## 控制对象与分类

记忆系统估计可复用状态，不把一次运行中的市场、账户、工具回执当作长期事实。历史原文、后续理解、审核动作和反馈回执分别保存。

| 内容 | 保存方式 | 使用边界 |
| --- | --- | --- |
| 行情快照、账户与持仓状态 | 运行记录 | 创建后 24 小时的参考窗口，不能替代当前观测，不进入长期召回 |
| 普通日报、自检、数据源异常报告 | 运行记录 | 创建后 24 小时；过期保留原文 |
| 执行过程与学习片段混合的报告 | 整篇保留为运行记录 | 摘录独立提炼，不能把整篇提升为长期记忆 |
| 已有运行检查点 | 运行记录 | 保留既有 7 天接续窗口，任务接续仍须独立校验 |
| 可复用规则、技术理解 | 长期知识候选 | 必须核对来源与适用条件，历史未审核理解重新准入 |
| 独立提炼的经验 | 新建长期候选 | 默认 30 天复查，最多 90 天；待主人审核后才可能召回 |
| 验收记录 | 验收证据 | 仅审计，不进入长期召回 |

分类根据正文、日期和来源信号判断，不只依据 owner 类型；Chat 名下的日报也可能是运行记录。边界记忆不由此批处理降级。

## 可追溯准入

提炼必须提交来源 ID、完整版本、精确摘录及其 UTF-16 偏移、独立结论、适用条件、反例、复查触发和期限。服务端在事务内核对原文。不可改写的 proposal 观测保存绑定，但不声称已经独立验证业务事实。

新候选继承来源的 owner、scope、隐私与场景约束；不修改原报告。当前价格、账户、持仓与交易指令不得作为独立经验准入。稳定候选 ID 和命令回执保证重试幂等；换命令重复提炼也不续期、不重新激活。

候选审核要求版本匹配、明确勾选已核验证据、填写原因。来源版本、来源可读权限、候选期限在召回、精确读取和出站前重新检查。Host 内部 Symbol 绑定当前来源与候选版本，不接受 JSON 自报“已核验”。denied 优先于 allowed；提炼经验不赋予工具权限。

## 反馈、纠错和恢复

记忆中心的“来源与使用记录”展示分类依据、原状态、使用窗口和分页；“提炼与审核”集中展示新经验和历史理解准入，支持查看当前原文、审核、纠错与停用。来源变化和到期显式显示停止召回。分类、审核和依赖失效都有审计与版本保护；撤回分类要求精确匹配回执，不能覆盖新版本。

原文不自动删除。来源不可用、摘录不符、版本冲突、缺失证据或权限不足均停止准入，不伪装成功。审核不通过可拒绝候选；有新证据时通过纠错或重新提炼进入下一轮。真实业务候选由主人审核，不用程序测试替代事实确认。

## 实施与验证

历史计划先预览并固定 hash，再应用。仅允许修改计划内的分类元数据、历史准入元数据及明确退回待审的状态；逐行比对所有历史原文、证据和时间。隔离数据库验证提炼、审核、到期、权限、出站阻断与恢复，桌面验证分页、原文核对和来源变化提示。日常实例只切换 Web，不启动 worker 或调度器，不执行交易或发送消息。构建保留当前版与上一版两套。
