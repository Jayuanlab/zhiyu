# 知识短视频剪辑流程改造

日期：2026-09-12。状态：研究与方案完成，尚未接入运行链路。

## 目标与现状

被控对象是知识短视频的完整观看体验：事实可信、口播顺畅、画面解释信息、音画同步、审核可纠错。生成 MP4 只说明编码成功。

当前 `tools/ai-release-video-agent/src/index.mjs` 的 `captureKnowledgeCard` 将 `scene.visual` 制作说明当成观众文案；流程图按箭头切字符串；字幕按字符权重估算时间。图片存在、字幕条数增加不足以证明可观看。这些缺陷必须先修，不能通过增加特效掩盖。

## 可借鉴的方法及边界

1. **先完成口播剪辑**：先检查论点、表达、停顿和实际语音时长，再安排画面。Descript 的制作流程推荐先完成 radio edit，再增加字幕和补充画面。[来源](https://www.descript.com/blog/article/good-video-hierarchy)
2. **有信息用途的补充画面（B-roll）**：讲功能展示产品操作，讲证据展示可使用的原始材料，讲过程展示流程。不要用无关科技背景填满时长。[来源](https://www.descript.com/blog/article/using-b-roll-a-beginners-guide)
3. **声音跨越画面切点**：J-cut 是下一段声音先进入，L-cut 是上一段声音延续到下一画面；本项目可让连续口播跨越证据画面和图解的切换。[Adobe 官方说明](https://helpx.adobe.com/in/premiere/desktop/edit-projects/trim-clips/perform-j-cuts-and-l-cuts.html)
4. **保留理解时间**：新概念出现后留下阅读和消化时间，不能机械每两秒切镜头。[Descript 教学视频建议](https://www.descript.com/blog/article/making-better-educational-videos)
5. **字幕与动画使用同一时间轴**：Remotion 提供字幕导入、转写、展示及导出能力，也提供场景转场组件；时间戳来源仍需我们接入和核验。[字幕](https://www.remotion.dev/docs/captions/) [转场](https://www.remotion.dev/docs/transitions/)

以下为项目设计判断，不声称是行业统一标准：开头直接给用户关心的变化；每个画面只承担一个解释任务；讲解节点按语义变化，复杂图解停留更久；画面类型交替服务内容，避免全片卡片或全片生成素材。

## 推荐视觉组件

| 组件 | 适用内容 | 实际动作 |
| --- | --- | --- |
| evidence-focus | 官方声明、发布日期、指标 | 显示允许使用的来源片段，突出支持当前结论的部分，保留出处 |
| demo-focus | 产品功能 | 自有或授权录屏，裁切到实际操作区域，按动作聚焦 |
| process-reveal | 工作流程、因果链 | 节点与连线随口播逐步出现，当前节点高亮 |
| comparison-reveal | 两种方法差异 | 显示左右对象，再按相同维度依次对比，最后突出结论 |
| metric-focus | 有来源的数量变化 | 突出真实数字、单位、口径；禁止把推测画成精确统计 |
| takeaway | 实用结论和限制 | 简短行动建议与适用边界，不重复整段口播 |

采用轻量进入/退出、局部聚焦、遮罩揭示和必要的硬切。转场不能遮挡关键文字。音乐与音效为可选授权素材，口播优先；缺少素材时保持干净旁白。

## 运行链路

事实与来源 → 编辑稿 → TTS/实测时间戳 → 剪辑决策 → 素材准备 → 多轨时间轴 → 预览 → 质量检查 → 主人审核 → 发布草稿。

增加 `EditPlan`，明确区分：

- `claims`：观众听到或看到的事实，关联来源及观测时间。
- `narrationSegments`：口播文本、音频、实际起止时间、时间戳精度。
- `onScreen`：仅允许呈现给观众的标题、要点、节点和对比数据。
- `direction`：制作指令，绝不进入字幕或正文。
- `shots`：组件类型、起止帧、素材引用、镜头聚焦区域。
- `cues`：节点出现、高亮、镜头切换与对应语音片段。
- `assets`：来源、许可状态、哈希、尺寸、provider、实际生成/降级情况。

剪辑计划引用经过核验的事实，不能在美化阶段新增论断。大模型输出受限 JSON，不能把任意代码交给渲染器执行。

## 用本次 AI 安全视频说明改法

本例只说明剪辑结构，原稿的攻击范围、数字和“一个人替代团队”等说法必须重新核验后才能沿用。

1. 开场用一条有依据的变化建立主题，屏幕只显示核心短句。
2. 进入官方报告证据，突出原文支持的结论和时间。素材复用须符合现有边界；不满足时使用带来源的自制摘要。
3. 讲到侦察、利用、窃取时，逐步展开三个节点；禁止显示“用红色箭头连接”这类指令。
4. 案例用结构图表现参与者和步骤，画面跟随旁白聚焦，不将整段描述打印出来。
5. 如需要对比，先定义可证实的对比维度，再画左右栏。证据不足则删去夸张对比。
6. 结尾给用户一条可执行建议及限制，保留阅读时间。

## 技术选择

优先评估独立 Remotion 渲染包：项目已经使用 React，适合复用受限组件、多轨时间轴和 Web 预览。FFmpeg 保留用于编码、混音、媒体探测。采用前核对 Remotion 当期许可证与项目实际使用方式；源码可见不等于全部使用场景免费。

Motion Canvas 作为复杂图解备选；Manim 适合数学和算法专题片段。不要同时引入三套主渲染器。AI 视频仅承担明确需要的概念素材；文字、证据、对比和流程仍由确定性组件绘制。

## 分阶段实施与验收

| 阶段 | 修改范围 | 必须记录的回测 |
| --- | --- | --- |
| P0 内容合同 | 工具 schema、EditPlan、现有分镜适配；移除 visual 直接显示 | 制作指令不泄露；对比节点结构化；旧输入无可靠转换时明确退回 |
| P1 时间轴 | 语音时间戳、按句/词字幕、实际时长 | 抽查句首句尾同步；无截断；不同语速、标点、中英混排；标注估算降级 |
| P2 剪辑组件 | 流程逐步展开、双栏对比、证据聚焦、真实演示 | 做三段短样片，逐帧看关键状态，正常速度完整观看；检验裁切、阅读负担和连续性 |
| P3 完整样片 | 组合 45–75 秒视频，审核页预览与版本管理 | 同一核验脚本对照旧版；完整听看；记录用户意见和每项修正 |
| P4 Loop 接入 | 独立渲染任务、取消、失败恢复、发布边界 | 真实 Loop 从输入到草稿；失败不伪成功；批准与视频哈希绑定；必要生产验收 |

开发期间以独立渲染和针对性测试为主，不为每个视觉调整重建整个 Next.js 项目。完成完整业务阶段后再生产验收。

## 状态、反馈与恢复

- 每次保存版本化 `edit-plan.json`、素材清单、时间戳、render-metadata、quality-report 和视频哈希，不覆盖历史已审核成片。
- 渲染动作以输入哈希和渲染器版本幂等；中断后复用已验证素材；产物损坏时只重渲染受影响片段。
- 事件分层记录事实来源、编辑决策、执行结果和审核意见；不得记录密钥。
- 页面展示当前阶段、最近运行、失败原因、预览、来源、重做片段和暂停入口。旧版不能冒充新版。
- 资料过期、无授权素材、语音对齐失败、渲染失败分别暴露 provider/detail/warning。可降级为干净图解，但必须明确记录；不可自动退成旧占位卡还宣称成功。
- 主人意见记录为可追溯的风格偏好和片段反馈；没有发布数据时不虚构完播率。
- 拒绝边界优先。调用外部生成服务遵循费用边界；上传和发布保留人工审核。
- 自动检查覆盖内容泄露、素材完整、时间轴、音频截断、文字溢出；画面语义和观看效果仍须完整审阅。不能再用“文件存在”代替质量验收。
