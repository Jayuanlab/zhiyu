# 记忆所需信息闭环（2026-09-22）

## 对象与边界

被控对象是每次任务可用的证据上下文，不是模型自报的信心。六类信息为平台操作、工具回执、用户关系、任务状态、知识规则、经验反馈。原始事实仍留在各自业务表和 Brain observation 中；本次新增的是读取时的状态估计，不复制全平台数据、不改写原始日志。

## 本次实现

- `BrainMemoryRequest.informationNeeds` 支持调用方提供具体问题、类别、必需标记、关键词和最大年龄。未提供时用确定性词汇规则生成六类清单；这是分类提示，不是对任意自然语言需求的完整理解。
- Brain 返回 `informationReadiness`：present / unverified / stale / conflict / missing / denied / unavailable。present 仅表示该需求分类下找到可读来源证据，不表示最终回答充分或允许执行动作。
- 未知时间、未来时间不能作为新鲜的任务状态。平台、工具、任务类别默认 24 小时窗口，只用于检索提示；真实交易、发送、配置变更仍须使用各领域更严格的实时检查。
- denied 优先于同 ID 的候选。拒绝记录只有 ID 时，不推断其私有类别或内容。外部来源故障与无命中分开；记忆索引命中但来源未读取标为 unverified。
- 必需类别 missing 时可以改写一次查询，与已有补查共用两次总尝试预算。关闭内部补查、过滤、拒绝、来源故障和上下文警告均阻止补查；非查询权限约束保持不变。保留两次有效证据，第二次拒绝/过滤的 ID 从合并结果排除。
- 结果附在 Work/Loop 的记忆上下文和运行 trace，最终清单随 queryRetryOutcome 写入原有的用户隔离、幂等审计。桌面检索详情可展开查看六类状态；旧记录不伪造历史清单。
- Brain 成功返回空集合时不再退回旧记忆掩盖缺口。Brain 整体抛错时仍保留原有显式 legacy 降级，六类清单全部标为来源不可用；旧记忆不能借此获得当前证据就绪状态。
- Loop 重试提示明确要求核对旧动作回执，未知结果不能直接当失败重做。

## 动作安全和人工接管

清单不产生任何新的工具授权。现有 Work 工具执行入口每次重读 Work、检查 owner、当前 boundary、工具许可和 execution lease；领域审批、发送回执、交易账本继续拥有最终裁决权。本次没有新增一个通用动作拦截器，也没有声称所有工具都已具备幂等回执协议。缺口时可继续授权内的只读调查，涉及动作则遵循现有审批/边界；用户可在原有运行详情审核、停止和纠错。

## 反馈与下一阶段

审计记录需求、候选证据、来源异常、补查理由和停止原因，供后续评测定位“没采集 / 没命中 / 来源不可读 / 过时 / 回答没用上”。本次没有把这些计数叫作答案命中率，也没有声称已提升 100 题成绩。

仍需逐域完成：

1. 从结构化 Loop 验收合同自动生成字段级信息要求；当前默认分类不是逐子问题充分性判定。
2. 六类源的增量采集完整性、删除/失效传播、原始日志与结构化状态的对账。
3. 工具注册表声明动作前必读实时字段，未满足时的硬阻断与可恢复回执协议。不能只依赖 prompt。
4. 普通聊天中未经过 Brain 的 platformRecall/直查路径的同构清单。
5. 按真实任务验证最终回答引用了哪些证据及其字段覆盖，再重跑稳定快照的 100 题比较充分率和延迟。

## 验收口径

针对六类推断、来源核验、过期/未知/未来时钟、冲突、拒绝优先、来源故障、复合需求关键词、空结果上下文透传、单次补查预算、权限约束保持、审计透传和桌面提示测试。新增逻辑无额外大模型判定调用。真实平台数据覆盖率和最终答案充分率需要独立端到端评测。

桌面隔离组件验收：`tests/integration/information-needs.browser.ts`，真实 Chromium 验证 1280/1024 宽度、Tab/Enter 展开收起、双倍字号和六类故障状态。报告与截图位于 `.runtime/evals/information-needs/`。这是组件验收，不是生产页面或全量业务数据验收。

本轮执行结果：9 个单元/回归测试文件、101 项测试通过；`pnpm exec tsc --noEmit --incremental` 通过；桌面 Chromium 隔离组件检查通过。本轮未重跑真实 100 题，不报告答案充分率或耗时改善百分比。
