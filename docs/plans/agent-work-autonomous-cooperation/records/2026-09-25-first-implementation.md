# 自主协作首轮实施记录（2026-09-25）

范围：桌面 Web 与 PostgreSQL 必要后端。此记录只描述当前代码和已执行的验证，不代表完整方案验收。

## 已接入

- Work 之间有独立的协作请求和不可变事件流水，支持提醒、咨询、委托及接收、补充资料、回复、验证、拒绝、取消。
- 车间页增加“协作”面板，能查看同伴、配置自身可提供能力与收发范围、发起请求、处理收件和查看双方事件；请求状态每 30 秒刷新，也可手动刷新。
- Work 运行时增加同伴目录、发起请求、读取收发箱、回复工具。自主求助要求当前 run、属于自身 Work 的来源事件、明确能力和双方已配置的允许范围；目标 Work 的受控 run 入队，回复或补充请求会唤醒原 Work。
- 服务器检查同一 owner、Work 状态、来源事件和 run/Loop 归属、双方协作配置及 denied；同一命令幂等。每个发送 Work 24 小时最多十条自动请求，每个接收 Work 最多三个未结束请求。协作触发的运行不能再转派，补充轮数最多两次。
- 原始来源事件只传引用，不自动给另一 Work 原文读取权。请求正文和交互事件可在双方允许的协作详情中查看。

- `tests/integration/work-collaboration-check.mjs` 在独立库验证同 owner 目录、请求创建与重试、不同 payload 冲突、跨 owner 拒绝、错误身份拒绝、接收/回复/验证、提醒确认、补充资料、自动运行入队、回复唤醒、能力不匹配、缺失证据、跨 Work 证据和 denied 优先，共 24 项检查。
- TypeScript 类型检查通过。针对性单测五文件中四文件通过；`workshop-work-model.test.ts` 的两条失败仍期待旧 Pi 工具状态，与本次新增的协作工具无关，未改写其断言。

## 体验与遗留

页面目前是独立“协作”标签，清楚显示谁发起、谁接收、当前状态、处理记录和自动入队 run ID。已在实际桌面浏览器核对页面呈现和窗口缩放；表单提交、键盘全流程与失败后的刷新恢复尚未在真实用户数据环境回测，状态转换由隔离数据库的集成脚本覆盖。

尚未完成：真实模型自动发起并完成一轮求助的在线回测、自动结果的语义质量验证、证据原文的逐条授权展开、重指派和未解决请求的统一待办。现阶段不把“已投递”或“已回复”当作已解决，也不把原生客户端列为验收范围。

## 第二轮：失败与超时可见性

- 0158 迁移为请求增加 48 小时等待期限、需关注原因和首次标记时间。每次有效状态转换重新计算期限并清除旧提醒。
- 受管运行器每 30 秒执行一次按 owner 限定、单次最多 20 条的扫描。接收方运行失败、中断、取消、待核对、结束但未回复，或请求等待超时，都只标记“需要关注”并追加系统事件；不会自动重跑不确定的任务，也不会把提醒改写为已解决。
- 协作列表和详情显示提醒原因、运行状态与等待期限，用户可核对后继续处理或取消。
- 隔离数据库集成检查增至 32 项，包含提醒幂等和取消后清除。150 次迁移、重复迁移及导出模型覆盖检查通过；相关 52 项单测、TypeScript 检查通过。
- 生产构建完成（149 个页面），本地开发数据库已升级到 0158。受管 Web 与运行器重启后，`collaboration-attention` 模块报告成功运行；桌面浏览器在 1440 和 1024 宽度重新确认协作页面可见。

仍需补齐：把提醒汇入车间首页统一待办，允许用户重指派，完成真实模型双 Work 在线回测，以及逐条证据披露和成果回流。当前提醒是在协作页面展示，不等同于推送给主人。

## 第三轮：用户受控投递与重试

- 发起方页面可以把手工创建的请求交给接收智能体的受控 run 队列。服务端重新检查双方归属、目标状态、接收类型、目标工具拒绝规则、执行租约和版本；命令与新 run 在同一事务中留下事件。
- 若请求已有目标 run，只允许在旧 run 为失败、中断或取消时，由用户明确确认没有产生外部效果并提供至少十字的核对依据。旧 run 为排队、运行、完成或待核对时不能重投；有已发送或结果不明的外发记录时，即使用户确认也拒绝重试。系统本身不自动重试。
- 修复补充资料后新建目标 run 未写回请求的问题，避免页面和恢复扫描继续读取旧 run 状态。
- 隔离数据库协作检查增至 43 项，覆盖首次投递、幂等、未结束运行拒绝、缺少核对依据拒绝、成功重试、已发送外部动作拒绝，以及补充资料的新 run 关联。TypeScript 检查通过。
- 生产构建完成（149 个页面）；真实桌面浏览器验证协作页 1440/1024 宽度，模拟失败请求验证异常提示、核对勾选和重新投递按钮。受管 Web 更新后，`collaboration-attention` 模块持续报告成功，页面回测通过。

仍未做真实模型的两名 Work 在线闭环；系统只防止可追踪的已发送和结果不明外发记录，其他工具可能产生的外部效果仍须用户据实核对。
