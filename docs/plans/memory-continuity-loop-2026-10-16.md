# 跨轮与 Loop 记忆接续实施及真实验收

日期：2026-10-16。授权：主人要求接通跨轮与 Loop 记忆，并在同一个车间连续运行真实任务，核对保存、召回和纠错。

## 控制对象与边界

- 被控对象：同一持续任务的历史工作状态、工作笔记进入长期 Brain 的候选，以及下一轮实际模型输入。
- 原始观测：已结束运行的宿主审计、精确来源事件、Brain 当前版本与召回日志、真实模型结果。模型自述不作为独立成功证据。
- 状态：沿用持久运行事件、Brain 版本、Loop 检查点；历史笔记使用单独的未核实 checkpoint，不冒充本轮工具结果，不重建不存在的会话。
- 接续范围：同 owner、同车间、同 Loop，或已验证的显式父运行。无关任务不隐式继承；最近一次恢复清空、失败、截断、过期或策略不匹配，不回退旧状态复活笔记。
- 控制动作：读取 checkpoint、装载历史资料、提交长期候选、主人授权下的审核与版本化纠正；保留幂等命令、版本检查和审计。denied 始终优先，候选不自动成为生效知识。
- 恢复：下一运行可从持久 checkpoint 重建必要任务状态；不承诺恢复原 SDK 会话、旧正文投影或已经发生的外部动作。
- 异常：来源、权限或审计失败显式阻断；不拿最近相似事件替代精确来源，不用错误的零用量或假成功遮盖失败。
- 用户控制：桌面工作记录显示接续来源和阻断原因，Loop 笔记可送交长期审核；审核、修订和暂停权继续保留。

## 本次改动

1. 独立跨轮 checkpoint 解析及只读装载器，处理终态、作用域、策略、有效期、来源和纠错优先级。
2. 普通车间显式父运行与 Loop 执行器接入，在运行审计记录本次装载身份。当前任务意图进入 Brain 召回，避免只按车间长期使命查找。
3. Loop 终态运行的精确 owner 读取，长期候选接口明确区分普通运行和 Loop 运行，桌面开启对应送审入口。
4. 同车间、手动执行、不启用调度的有限真实任务演练；不恢复暂停/归档任务，不外发、不交易、不删除、不扩大角色权限。
5. 研究类 Loop 将真实研究契约传入工具层；网页降级读取仍保存不可变原文快照。纯文本保留其真实媒体类型、提取方式和降级警告，不冒充清洗后的 HTML。长期晋升继续核对精确原文 hash 和读取窗口，不能用工具回包 hash 替代。
6. 同车间回测发现的修复也保留版本与失败证据：完整主人纠错优先于普通上下文片段；typed Brain 原始观测按类型及实际权限展开。正常风险任务的相关、已应用主人纠错不能先被模型规划器的软检索条件挡掉；它仍保留真实置信度、来源警告和使用边界，高风险门槛与权限不变。

## 验收

- 程序：同任务接续、跨作用域拒绝、策略变化、过期、恢复清空、失败不回退、并发版本、重复提交、来源变化、Loop 终态与身份混淆。
- 真实：A 读取实际来源并保存笔记；送审并回读长期版本；B 新运行实际装载与召回；C 通过正式修订链纠正指定验收条目；D 新运行采用新版本并排除旧版本。
- 接续与纠错分别核对：实际事件/数据库回读、模型请求与结果、最终产物。不得将“请求准备”解释成理解正确，不手工把上一轮答案粘入下一轮冒充召回。
- 真实模型调用设置次数/时长/工具预算；保留每次失败、实际 SDK 用量与未知字段。验收条目和来源明确标记用途、适用车间，不写入用户通用稳定事实。
- 独立核验器检查已保存回执，不以智能体自评作为唯一裁判。通过链路验收不等于证明普遍质量或成本提升。
- 每轮单独启动进程；同时核对运行返回、持久 Loop checker/verification 结果、主模型实际发送内容和来源快照。辅助规划失败作为降级信号保留。若机器网络需要临时诊断路径，只允许验收进程对目标域名使用当次探测成功的地址，保留原域名、SNI 和证书校验，不更改系统代理、DNS 或生产提供方。

## 发布与回滚

先在当前开发源码和受限真实执行链路验证，保留原有生产运行及其他 Loop 状态。接续工具/笔记不改变既有权限。代码回退可停用新接续装载；验收记忆通过正式停用/修订机制处理，原始运行和失败记录保留。本次实际装载、运行结果和遗留项在验证报告中分别记录。
