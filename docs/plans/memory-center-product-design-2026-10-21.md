# 记忆中心：产品定位与桌面信息架构

## 产品判断

需要一个全局记忆入口，服务主人查找、核对、纠错和控制记忆的真实需求。后端的“统一”不应成为用户理解产品的前提，也不意味着所有表都要做成首屏卡片。现有 `/memory` 保留为“记忆中心”，不新增一套记忆存储或独立业务真相。

原“个人记忆”入口实际上是消息沉淀、主人知识库和关系整理。导航改为“消息与知识”，保持原路由和工作流。它负责把来源整理成可审核的理解；记忆中心跨来源查询、纠错与追溯。后续若需要合并导航，应保留该整理工作流作为记忆中心的子入口，而非复制相同的列表和控制操作。

| 入口 | 用户来这里完成什么 | 不承诺什么 |
| --- | --- | --- |
| 消息与知识 | 管理微信来源、整理资料与待办、审核沟通理解 | 消息原文不等于已核实结论 |
| 记忆中心 | 查找已保存内容、审核变更、纠错、核对读取依据 | 搜索结果不自动成为当前任务上下文 |
| Work / Loop | 围绕当前使命与任务消费适用记忆、留下运行结果 | 全局记忆页面不替代任务执行、授权与领域账本 |
| 文件 | 日常文件整理与访问 | 文件激活不等于完成知识索引或 Work 授权 |

## 四个用户分区

1. **查找记忆**：默认首屏。问题输入、来源选择、最近更新的真实记忆、查找结果、按任务召回。最近记录只读取 8 条，显示内容预览、原状态、更新时间与已有纠错入口；不把已保存或已审核等同于已核实事实，不推测全量统计。检索示例只填入问题，不自动发送；阈值、数量等放入检索设置。
2. **审核与纠错**：更新提案、待核实修订、依赖影响、最近停用和自动生效政策。沿用现有正式审核机制。列表未读取不显示虚构的零待办；未确认修订和更新提案的恢复提示在所有分区均可见。召回反馈的恢复保留在查找分区内。
3. **文件与接续**：已有私有文件的状态、窗口读取、清理以及任务接续回执。沿用版本、权限、审核和删除边界。
4. **来源与使用记录**：需要解释或排查时核对来源类型、固定版本原文、读取与出站回执。高级字段和来源语义按需展开，不把已准入表述为模型已采用或业务已完成。

记忆详情仍要呈现内容、来源、状态、适用范围、更新时间与纠错入口。已有字段优先使用，不为视觉完整而捏造来源时间、总量、健康度或“已核实”状态。计划的审核执行留在既有计划详情，并由原任务链接进入，不把全局记忆搜索变成新的执行器。

## 视觉与交互

沿用产品玉绿 `#13756f`、现有 foreground / muted / border / card tokens；白色内容面、低对比底色、克制的强调色。标题使用现有中文无衬线 28px / 600，正文 14px，辅助信息 12px，版本仅在详情用等宽字体。签名结构为“消息与文件 → 理解与经验 → 当前任务”，分别对应保留来源、审核变更、核对后使用；不使用虚构流程进度或仪表数字。

四个分区使用可键盘访问的真实锚点导航，支持直达文件旧锚点。首次访问分区才装载对应面板，访问后保留表单和未确认操作，切换不隐式批准、不重发命令。修订与更新提案的恢复提示维持全局可见。页面文案采用摘要与待办、沟通记录、知识资料、关系图谱等用户可识别的名称。三段职责说明不表示所有文件都会自动写入长期记忆。

## 工程闭环与验收边界

- 被控对象是主人的派生记忆及其适用性；消息、文件和领域状态仍属于原始观测或事实来源。
- 观测输入是现有检索、审核列表、文件清单与来源回执；失败、过期和降级继续显式暴露。没有新增后台自动动作。
- 状态存储、幂等命令、权限检查、审计回执及 denied 优先规则沿用原 Memory 模块，不在 UI 重写。
- 用户通过原审核、修订、停用、反馈与政策控制纠偏；待确认状态保留恢复入口，页面切换不构成授权。
- 对分区懒装载、来回切换保留草稿、旧文件锚点和浏览器 hash 变化做行为测试；保留来源读取、权限变化与恢复控件的原回归。
- 先开发模式桌面实测，再必要生产构建及日常入口复核；构建产物总数最多两套，在用版本计入。此文是设计，不提前代表已完成部署或生产验收。

后续优先级：来源/使用记录的可读摘要、候选队列的可核验汇总、按权限的全局记忆目录。需要相应的有界后端查询后再展示统计；本轮不以空占位或全量下载冒充完成。
