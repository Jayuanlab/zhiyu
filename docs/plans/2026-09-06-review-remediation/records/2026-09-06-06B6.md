## 实际改动与状态语义

`startWorkRun` 接入数据库命令账本，将运行保存为 queued，startedAt=null，写 run_queued 事件，返回 202。`addWorkDirective` 将指令、可选关联运行、事件和成功回执在同一事务提交；取消旧的捕获启动异常后仍返回指令成功的路径。任一提交失败整体回滚，原命令保持 queued 供显式重试。

`workCommandChildId` 按 owner、Work、commandId、用途派生稳定运行 UUID。指令引用 runId 时验证其属于当前 Work；无效范围、优先级和 ID 被拒绝。派生运行中的 type/directiveId/content 由服务端写入，调用方自报字段不能覆盖真实指令来源。triggerRun=false 只记录方向。

迁移 `0130_allow_queued_workshop_runs` 放开 workshop_runs.started_at 非空限制，保留历史时间，新增 queued 查询索引。运行列表按创建时间和 ID 排序，避免 null 开始时间干扰顺序。新增 Work Runtime 查询 `listWorkRuns` 与 `GET /api/workshops/[id]/runs`，鉴权后最多返回 100 条；旧详情 runs 固定空数组，不能用它证明运行状态可查询。

注意：命令回执 succeeded 表示接受操作已提交，不表示模型运行完成。新入口目前持久排队，未在本批次接入消费者；旧 Heartbeat/startWorkshopRun 路径还在，06C/09 必须统一。**本批次不能单独切换为日常运行版本**，否则新接受的运行会等待消费者。日常实例未切换。

主要修改：work-runtime commands/queries/child-id，workshops service/types，PG schema/迁移，以及 runs/directives HTTP 路由。
