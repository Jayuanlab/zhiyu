# 11N 反馈刷新恢复与提交前边界

本批完成当前标签页的反馈恢复闭环。保留已有工作区修改，未迁移日常数据库，未切换生产。

## 修改和用户路径

- 发送前读取当前身份，将原反馈完整请求保存到按 owner 分区的 sessionStorage。存储成功后才发送；同页同步锁避免重复点击。
- 页面挂载读取当前 owner 的待确认请求，恢复区域不依赖重新搜索。用户点击“重试原反馈”沿用原 ID 和内容；校验服务器回执 ID 后删除待确认记录。
- 400/401/403/404/409 为明确拒绝，释放待确认请求并提示重新核对登录和召回。网络/503/回执不匹配保留请求供重试；恢复记录损坏或浏览器存储不可用时暂停提交，提供重新读取入口。
- 提交前发现身份变化，拒绝发送旧用户请求，清空旧召回结果及同页 ID 缓存，再读取新用户恢复记录。
- 检查了普通 remote-feedback 写入口：schema 剥离自定义核验字段，来源固定为 web/desktop，未发现该入口伪造 memory_recall 核验标记的路径。此结论限已检索的当前代码，不是共享部署整体验收。

## 剩余边界

恢复范围是同一浏览器标签页刷新；关闭标签页或清除存储会丢失客户端恢复记录，跨标签页不共享提交队列。后端持久回执仍按原 ID 幂等，不能将不同 ID 的独立意见当成重试。共享部署真实身份切换、固定人工标注、跨批次回填与生产/SQLite 支持矩阵仍待完成，方案 11 及整个 12 方案目标未验收。
