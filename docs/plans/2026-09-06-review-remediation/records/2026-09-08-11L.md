# 11L 召回反馈关联与重复请求

本批解决客户端可伪造反馈关联、响应丢失重试重复计数的问题。HEAD 为 a0e94e5f19661895adce29787da85385117f2477；保留已有工作区修改。未迁移日常数据库，未构建或切换生产。

## 修改

- 新增 recall-feedback 服务：关联必须来自当前 owner 的上下文快照，页面提供的 selected/omitted/denied 数组不作为事实。无上下文明确记录 unlinked，拒绝不存在或其他用户的上下文。
- POST 必填 feedbackId UUID；同 ID、同规范化请求重放原回执，不再新增反馈；同 ID 不同内容返回 409，其他 owner 使用已有 ID 返回 404。主键冲突处理和保存都在事务内，反馈保留来源和请求哈希。
- 页面同一次召回同选项在当前挂载期间复用 ID，同步阻止并发点击；增加反馈区域状态，说明未确认时如何重试。服务器不可用返回 503，不透出 SQL 错误。
- 原始记忆和召回快照不被反馈修改；反馈不自动改策略或确认事实。
