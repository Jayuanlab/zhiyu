# 11G：旧边界不被普通新记录挤出候选集

状态：隔离召回样本、相关单测及类型检查通过；方案 11 整包未验收。HEAD：a0e94e5f19661895adce29787da85385117f2477；未改日常数据库。

## 复现与修改

220 条近期普通事实将 2019 年的有效长期边界挤出最近 200 条候选集。评分层无法找回未进入候选集的记录。[修复前证据](11G-boundary-before-postgres.json)明确在旧边界缺失断言失败。

两个上下文构建入口现在为边界保留额外最多 50 条候选，按置信度、更新时间及 ID 稳定排序，与普通候选去重后进入原权限检查和评分。该补充查询不受近期时间/搜索词限制，仍遵守 owner、范围、状态、置信度、显式类型与 canonical 类别选择；明确只查询事实时不补边界。候选日志记录配置配额。最终 maxItems 不变。

同时修正默认范围：work 请求方以 id 指定自己的工作时，必须将本工作范围加入查询，不能因为添加了跨工作授权而只查询授权目标。保持后续 canReadMemory 检查，未授权记录不进入结果。
