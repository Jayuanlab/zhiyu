# 06B3 Work 创建与删除事务

状态：createWork/deleteWork 以及命令审计持久化子步骤已验收，类型检查、隔离回测和独立生产 HTTP 测试通过；06B/06 整包仍未完成。

## 实施内容

- createWork 和 deleteWork 使用专门的生命周期事务。创建前尚无 Work，删除后 Work 已不存在，不能套用必须先读取目标的普通配置命令流程。目标变化、命令回执和审计全部提交或全部回滚，没有需要外部恢复的中间执行步骤。
- 相同 owner/commandId 通过数据库唯一键收敛；创建的服务端随机 ID 不参与意图 hash，两个进程返回同一个 Work。不同 payload 冲突；删除后的同一请求仍返回原回执。
- 重放已经成功的创建命令只返回历史结果，不重新创建已删除对象。命令回执按 owner 保存，不能跨 owner 查询或重放。
- 新迁移 0128 创建 work_command_events。accepted/succeeded/failed 事件引用命令而非 Work，所以 Work 删除后审计仍保留；用户账号删除时按命令所有权清理。普通数据库命令也在原事务中记录这些审计事件。
- 不伪造 0128 前的历史审计：旧回执仍可读，新表不凭空回填“当时已观察到”的过程事件。
- 删除先锁定 Work 和所属 Loop，并检查正在排队/运行/请求取消的运行。若有活动运行返回 target_busy；与未提交 Loop Run 竞争时等待 FK 父行锁，提交后重新检查，防止把刚启动的运行级联删掉。
- 创建 POST、删除 DELETE 接收 commandId/expectedVersion；查询回执 GET 增加事件列表。401 身份入口沿用原鉴权，400/404/409 区分参数、目标和冲突。
- 本轮没有迁移日常数据库、没有替换日常运行产物；候选目录 .tmp/next-review-17，17 仅为构建隔离编号。

## 复查发现与修正

首轮数据库和生产 HTTP 测试通过后，复查发现审计查询将 seq 转为 text 后按同名别名排序，可能发生跨位数倒序。新增实际 PostgreSQL 用例将同命令的 accepted/succeeded 序号设置为 999999/1000000，复现返回 succeeded 在前，见 [失败日志](06B3-order-before.log)与 [失败报告](06B3-order-before.json)。改为 ORDER BY work_command_events.seq，返回格式仍为字符串；修正后数据库测试、重建和包含此边界的 HTTP 测试均通过。

首轮产物及证据保留在 [首次构建](06B3-build-first.log)、[首次生产报告](06B3-production-first.json)和 [首次生产日志](06B3-production-first.log)，不将它们作为修正后代码的验收证据。首轮构建发生 TLS 重试，随后完成；仍有既有 framer-motion 可选依赖警告。
