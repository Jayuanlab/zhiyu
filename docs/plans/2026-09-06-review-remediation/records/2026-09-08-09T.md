# 09T 理解任务与消息状态原子投影

发现原处理函数先改消息 processed_status，再调用带次数校验的任务完成/失败接口。旧轮次任务更新即使被拒绝，消息状态仍可能已经被覆盖。现将消息状态投影迁入领取、完成和失败事务，使用任务持久 eventIds 并再次过滤主人；只有任务状态更新命中当前轮次时才投影。处理函数不再独立修改消息状态。

宿主失效核对的同一 SQL 事务也将关联消息遗留的 processing 转为 failed，任务本身仍为 needs_review，不能把未知结果标为完成。恢复投影不会将已经不处于 processing 的消息改回失败。原始消息正文未修改。
