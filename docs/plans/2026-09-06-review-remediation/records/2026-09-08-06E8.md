# 06E8：旧任务查询、超时核对与调度停止

日期：2026-09-08。集中检查旧定时路径的实际调用者。检索 apps/web/lib、apps/web/app 和 packages，未发现 executeJob / runScheduledJobLoop 的应用调用者；local-scheduler 仍每轮调用旧恢复和清理函数，并在停止/进程退出时全局改写执行状态。本批修复这些活跃路径，不为未使用的旧执行器扩展另一套执行引擎。

## 修改

- getJob 与 getDueJobs 改为纯读，不再按超时或计划时间自动写错误状态、推进计划。due 查询排除运行中、需核对、取消中和未知结果的任务。
- recoverStuckJobs 必须传入主人；无主人不查询/写入。PostgreSQL 事务按主人筛选，锁定最多 100 个旧任务并跳过已锁定任务及已迁移任务，复核超时条件，将原 running 记录转为 needs_review。
- 超时不是执行结束的证据。不新增 running 记录，不删除历史，不伪造 completedAt，不推进计划或计数。保留输出、原诊断及原结果，追加来源、主人、观测时间和前后状态。任务摘要与执行变化同事务。
- cleanupStuckJobs 保留兼容入口，但仅执行同一核对转换，不删除历史；主扫描器不再重复调用 cleanup。
- stopLocalScheduler 只停止自身定时器并取消首轮延迟扫描，移除无租约的全局数据库改写及无效的异步 exit 清理。取消正在执行的 Work 仍由现有持久协议负责。
- 扫描必须有主人并满足启用条件；单轮固定主人，恢复后再次核对停止、禁用与主人变化，避免用另一个主人的上下文继续调度。本批未声称实现 09 的全部停止/模块隔离语义。
