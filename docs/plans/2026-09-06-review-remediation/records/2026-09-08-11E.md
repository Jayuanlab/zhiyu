状态：服务、CLI 和本机模式 HTTP 隔离回测通过；方案 11 整包未验收。HEAD：a0e94e5f19661895adce29787da85385117f2477。无日常数据库迁移，无生产构建。

## 修改

批准、暂停、恢复必须携带 commandId 和查询时得到的 expectedVersion。详情查询在批次共享锁内同时返回条目、统计和最新事件编号 version；控制操作持有批次排他锁，在修改前核对版本。控制动作与持久回执共用原有事务机制，同编号原请求返回原结果，同编号不同参数冲突；新编号但旧版本拒绝。

版本使用事件编号的十进制字符串，避免 JavaScript 大整数精度丢失；不是客户端时间戳。回放优先于当前版本检查，允许响应丢失后的旧请求取回原结果，但不重新执行动作。控制响应现在是操作结果 `{status,processed:0}`，当前详情和 version 需重新 GET。

CLI 的 approve/pause/resume 现在要求 `--command-id=<uuid>` 和 `--expected-version=<canonical-status 返回的 version>`。一次请求重试保留两者；409 后重新读取并审核当前状态，不能自动换新编号覆盖冲突。
