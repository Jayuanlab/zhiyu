# 06C1 车间运行领取与执行凭证基础

日期：2026-09-06，基线 HEAD `a0e94e5f19661895adce29787da85385117f2477`。基础实现已完成隔离回测和生产编译；06C 和方案 06 尚未验收。

## 实现

新增迁移 0131 和对应 PostgreSQL schema，workshop_execution_leases 按车间保存单一活动运行、递增 token、worker、数据库租约时间、心跳、动作意图和终态结果。现有 queued 运行作为领取输入。先锁定主人所属车间，再核对运行归属并修改租约、运行状态和关键事件；迁移不回填或接管历史 running。

execution-lease.ts 集中实现 claimWorkshopExecution、renewExecutionLease、withExecutionWrite、markExecutionEffect 和 finishWorkshopExecution。相同车间的两项运行互斥，过期且没有动作意图的原运行可以取得更高 token；有其他等待项时先返回原运行需要恢复，避免跳过失租任务。暂停车间不接受新的领取，历史无凭证 running 返回 legacy_busy。

withExecutionWrite 只容许数据库内回调，在写入前后检查租约，长事务跨过期限也回滚。旧 token 不能续租、记录动作意图或完成运行。外部调用必须在事务外，先等待动作意图持久化成功；一旦有动作意图，失租或失败进入 needs_review，阻止其他运行盲目接管。完成结果可重复确认，不同结果拒绝覆盖。

这不是外部动作恰好一次的保证。07/08 仍须持久化领域动作与回执，09 和后续 06C 必须接入领取、续租与执行恢复。当前没有把旧执行器直接挂到领取函数后面：旧执行器仍有未带凭证的写入，不能据此声明消费者完成。
