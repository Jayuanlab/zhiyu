# 09W 无宿主关联的旧理解任务核对

旧理解任务没有 runtime_interaction_claims，无法根据租约判断原处理进程是否已停止。此前自动恢复故意不猜测这些任务，结果是部分任务会一直显示 running/applying。本阶段新增本地维护入口，预览后由操作者确认旧进程已经停止，再将未变化的候选转入现有待核对流程；不按运行时长自动认定失败，不自动重跑派生写入。

## 实现与边界

- 新增 `lib/interactions/legacy-reconciliation.ts`、`scripts/reconcile-legacy-interactions.mjs`。预览只返回指定主人的任务 ID、次数、状态、更新时间和事件 ID，以及清单 SHA-256；最多 100 项，hasMore 提示还有后续批次，不读取消息正文。
- 应用必须提供同一主人、唯一 commandId、预览 hash 和显式旧进程停止确认。用与正式宿主启动相同的 owner advisory lock，拒绝尚未过期的宿主租约（包括暂停状态）；锁定候选行并重算 hash，清单变化则拒绝。已经关联正式宿主的当前轮次不属于此维护入口。
- 新增迁移 `0150_add_interaction_legacy_reconciliations`（journal idx 141，总计 142 项）。保存主人、命令、原清单、hash、操作者的停止确认和时间；确认是维护操作者的声明，不冒充系统检测到了旧进程退出。
- 同一事务将任务转为 needs_review、尚为 processing 的同主人关联消息投影为 failed，并写审计回执。已有 seen 等状态不被回退；原始正文、笔记、待办和记忆不删除或重写。审计写入失败则全部回滚。
- 相同命令与 hash 重复提交返回原回执；同命令改 hash 拒绝。转入待核对后旧处理轮次不能继续通过现有写入/完成校验，也不会自动领取重跑。用户可在 `/interaction-reviews` 查看已有证据并使用既有“保留结果并结束处理”。

维护入口只供有数据库访问权的本机操作者使用，不是绕过 HTTP 身份校验的新公开接口。没有证明正在执行中的旧程序被此命令强行停止，必须先完成实际停机核对。

## 操作顺序

在 `D:/zhiyu/apps/web` 中，先核对目标数据库配置和主人，再预览：

```text
node --import tsx --conditions=react-server scripts/reconcile-legacy-interactions.mjs --owner <主人 UUID>
```

确认旧的理解处理进程和正式宿主均已停止，查看预览清单，生成一个 commandId 后应用：

```text
node --import tsx --conditions=react-server scripts/reconcile-legacy-interactions.mjs --owner <同一主人 UUID> --apply --command-id <新命令 UUID> --manifest-hash <预览 hash> --confirm-old-processes-stopped
```

响应不确定时保留并重用原命令及 hash；不要另建命令。清单变化则重新预览；hasMore=true 时当前批次结束后再预览下一批。此操作只解除“处理中”误导，后续仍须用户核对已有结果，不代表任务成功完成。
