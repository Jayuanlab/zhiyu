# 06E3：旧任务明确转换与退休边界

日期：2026-09-07。本阶段为转换核心及旧入口隔离；审核表单/HTTP 参数尚未接入，不计为旧任务用户路径验收。

## 原因与实现

旧任务可使用自定义回调、角色上下文与模型覆盖，原调度器还使用旧聊天历史。把时间配置复制给原生 Loop 不能证明执行语义相同。因此增加明确的 `nativeReplacement`：主人审核新任务说明、原生触发配置并确认替换旧逻辑；继续要求停止旧控制器声明与旧预检摘要，不自动照搬旧执行器。

- 新增 0141 和 `loop_runtime_migrations.legacy_job_id`，唯一绑定保留旧任务身份。转换保持 Loop ID、旧任务行和全部旧执行历史；新车间/Loop 暂停，旧任务 `enabled=false`、`next_run_at=null`。
- 旧任务读取在所属 Loop 与 job 行锁下完成；源不存在、外来主人、未结束执行或重复 Loop 绑定均阻塞。预检只暴露任务/调度信息与配置存在标志，不返回模型凭证；完整源摘要仍覆盖私有配置变化。
- 新任务说明及 manual/cron/interval/once 配置被严格校验；cron 表达式/时区和一次性时间无效时拒绝。原外部动作拒绝规则继续保留。
- 保留状态观测和旧运行引用，清除旧下次时刻/一次性消费标记；原游标可在迁移源快照中核对，新车间激活后使用新触发配置。
- 原来源摘要、替换命令、旧任务退休事件、车间创建、Loop 归属、旧任务停用、迁移记录和成功回执同一事务。事件失败整笔回滚。
- 精确查询替代先列 1000 个 Loop 再查找；退休后的旧 job ID 仍解析到原 Loop。创建旧任务映射在 job 行锁下串行化，并读取当前数据库任务配置，不使用调用者缓存覆盖配置。
- 数据库拒绝退休后改写旧 job、插入/更新旧 execution。旧 `executeJob` 入口要求主人所属、已登记的 running execution；没有持久执行记录不能直接调用处理器。旧 `runScheduledJobLoop` 经永久绑定找到已迁移 Loop，建 Run 时被迁移保护拒绝，回调不会执行。
- 去掉旧执行器日志中的完整 `jobConfig`，避免把模型覆盖凭证写入配置日志。

## 限制与下一步

未更新生产候选，最新仍为 62，不含 E3；未触碰日常数据库。现有 E2 页面仍阻止旧 scheduled_job，下一步必须展示旧任务信息、替换说明、调度编辑及明确确认，并把新参数接入可信 HTTP 和持久重试白名单，再做组合构建与浏览器回测。

审核页面接入时还需统一新 goal 与旧 description 的展示，防止原摘要盖过新任务说明；成功提示应说明“提交时均暂停”，并引导查看当前状态，不能把重放的历史回执当成车间此刻状态。

新保护属于当前版本；不能据此承诺任意旧二进制混跑安全，实际切换仍需停止旧控制器。SQLite/Tauri 不开放旧执行器的新事务准入。正常未迁移旧任务仍是过渡入口，最终执行入口收敛与宿主接管仍在 06/09 范围。全部 12 项目标保持不变。
