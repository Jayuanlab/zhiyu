# 06D4：持久排队入口与独立 Loop 消费者

## 修改

异步 Loop HTTP 请求现在等待接受事务提交后返回 202，响应包含 commandId、Work Run/LoopRun 和当前状态；移除 `void runWorkLoop` 后台 Promise。跨归属、无效命令和接受失败在响应之前处理，不能先声称已排队再只写错误日志。已完成命令的重放会返回实际 completed 状态。

`enqueueWorkLoop` 与同步执行复用相同命令构造。消费者按归属读取 queued / 租约过期运行，再由已有 Work 执行租约裁决领取；数据库读取不等于执行授权。消费的是接受时保存的完整 payload，保留 commandId、版本、触发原因、原生/外层完成模式。普通 Work 消费者仍排除 Loop 关联运行。

`consumeOwnedLoopRuns` 支持有界批次、worker 身份、租约期限和中止信号；暂停车间和暂停的排队 Loop 不领取，已占用 Work 不并行执行。`scripts/consume-loop-runs.mjs` 可单次或串行轮询运行，退出信号中止当前执行并停止后续领取；启动前强制要求关闭旧调度及启动监听。未在日常环境启动此 CLI。
