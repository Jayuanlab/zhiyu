# 06D3：车间 Loop 外层后处理接入

## 修改范围

车间 Loop 外层现在持有执行租约直至后处理完成。先接受、领取，再写开始事件；被 busy 拒绝的请求不会创建假的开始或失败事件。使用本次租约的 runId/loopRunId，不再读取“最近一次运行”猜测来源。

完成事件、旧服务错误审核收敛、建议动作草稿和后处理回执在同一事务提交；草稿保留实际 Work Run/LoopRun 与完成事件来源。重试读取内层结果和外层回执，避免重复执行、重复事件与重复草稿。

报告质量评审在租约内等待执行，模型请求位于数据库事务外，评审/改进提案/审核项和质量回执原子提交。完成后重试复用质量回执，不再通过内存定时器遗失评审。修复了改进提案函数提前 return 导致审核项写入不可达的问题。未开启评审时也记录本次跳过决定。

同步等待的执行 API 传递 commandId/Idempotency-Key 与 expectedVersion，检查 X-Work-Actor；busy、租约与命令冲突返回对应状态码。原生执行和外层完成模式进入命令 payload，避免同一命令被不同入口解释。
