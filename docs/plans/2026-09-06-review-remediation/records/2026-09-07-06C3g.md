# 06C3g：记忆审核事务与明确审核决定

本步骤统一记忆状态、审核流水与受控执行事件的提交。06 整包、11 记忆质量及全部 12 个方案仍未全部完成。

## 改动

- reviewBrainMemory 委托单一事务操作，按会话用户读取并锁定记忆，再根据当前行和事务内读取的授权校验现有审核权限。保留原有 chat 主人审核口径，不在本步骤更改授权产品规则。
- 审核只更新 status/updatedAt，不回写旧的正文、证据、元数据和归属。审核流水记录锁内实际 previousStatus、nextStatus 和证据，避免并发审核各自记录过期前态。
- 状态更新与审核流水同事务；执行上下文存在时沿用租约事务，连同 brain_memory_written 事件及计数一起提交。普通记忆写入也通过同一数据库事务包装，未引入事务中的模型或网络调用。
- 审核 HTTP 不再把缺失、错误或无法解析的决定默认为 dismissed。仅接受 confirmed/dismissed/rejected，其他输入返回 400/invalid_decision，不改状态、不写审核记录。

## 限制与后续

该事务尚不提供用户重复审核的 commandId 回执；重复的显式审核会保留多条审核记录。授权撤销/过期与提交的竞争仍需整体授权事务处理；本步骤不宣称已解决它。非 PostgreSQL 平台未验收。
