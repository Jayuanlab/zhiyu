# 06D5：取消与待核对状态的一致性

## 修改

Owner 取消 Work Run 时，关联 LoopRun、LoopState、活动占用和 Loop 控制事件现在一起提交。没有外部动作意图则 cancelled 并释放占用；有动作意图则 needs_review、保留占用并阻止自动重放。取消尚未执行的队列不会覆盖前一次运行的观察结果，但会记录本次取消来源。

`loop-control-state.ts` 是数据库事务内的共用转换，供 owner 取消、外部动作后租约过期、外部动作后错误完成使用。后两种情况也将 LoopState 置为 blocked，不能继续显示 running。状态 JSON 在数据库中合并，保留已有状态字段；该模块不反向依赖 Loop 服务层。

修复取消已捕获结果后，同步重放可能误返回原 completed 响应的问题。消费者遇到已取消或待核对的真实持久状态会如实回报，不将 owner 取消当作普通运行错误。通用 Work 完成方法不能绕过 Loop 结果协议释放关联运行。

Loop 状态类型补充 queued/cancelled/needs_review；模型评估结果仍限定为模型能够决定的完成、失败、阻断和待批准状态，不允许通过评估结果生成 queued 或 owner 取消。
