## 原因与控制动作

`0077_add_insight_brief_categories_table.sql` 在磁盘上，但未登记到 journal；正式 Drizzle migrator 读取 journal，不会按磁盘文件名扫描执行。把它插回旧序号不能可靠修复已经升级到更晚时间戳的数据库，所以追加正式修复迁移，不修改旧迁移历史。

新迁移在缺表时创建表与索引；已手工执行旧 SQL 的数据库保留分类记录。两个外键分别补齐，避免旧 SQL 中第一个外键已存在时跳过第二个。source 约束允许当前接口实际使用的 manual/auto/unpinned，不允许任意未知状态。迁移不修改现有分类值，不把取消置顶重新变为置顶，不运行日常数据清理。

## 用户体验与验收边界

修复针对首页读取分类以及取消置顶落库失败，避免迁移命令成功但用户使用时才报缺表。此次只验证分类查询/取消置顶路径；没有验证整个首页渲染、所有 Insight 权限入口或共享部署，不把两个 fixture 的隔离检查等同完整多用户安全验收。

未运行日常数据库迁移，也未重启日常生产服务。生产升级需在最终切换时按备份、迁移、核对流程执行；不得在用户继续写入后删除分类表回退。遇到已有脏数据导致约束验证失败，应保留失败并核对，不自动删除用户记录。

磁盘另有未登记 SQL；其中可能已由其他正式迁移实现，不能简单把全部文件补入 journal。12 后续需按现有 schema/实际查询核对覆盖，避免再用少量表存在检查声称完整迁移验收。未改动 pinned/sync/unpin 等接口实现，相关全入口权限及并发审查仍属于 05/12 的未完成验收。

本批结论：空库与旧表迁移及分类 HTTP 子路径通过，日常切换/生产和方案 12 整体仍待验收。
