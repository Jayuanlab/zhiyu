# 06D8：主人核对运行结果的后端闭环

## 控制对象与边界

处理持久租约协议下的 `needs_review` Work Run 及其关联 Loop。只有主人上下文可以提交；智能体执行上下文、system 来源、跨主人目标、过期版本/租约观察均拒绝。不调用外部执行器，也不把主人核实结果写成模型执行成功。

接口 `GET /api/workshops/:id/runs/:runId/review` 提供同一语句下的主人归属、命令版本、当前租约 token、运行状态、待核对发信和最近人工证据。待核对发信先过滤再有界返回 20 项，并明确是否还有更多。读取不解除占用。

`POST` 使用稳定 commandId 与配置/租约基线，进入 `resolveWorkRun` 数据库命令事务：

- `unknown`：追加核对证据，运行和占用继续保持 needs_review。
- `no_effect`：主人核实没有外部效果；已存在的 sent 发信或底层发送回执与此断言冲突，拒绝关闭。
- `effects_recorded`：主人已核实外部效果；保留发信领域结果，不修改消息或重复发送。

关闭要求明确确认执行器已经停止，并填写至少 10 个字符的依据。它是主人的人工确认，不是服务器自动证明进程停止。任何已知 sending/unknown 发信或底层尝试都必须先完成 07 的领域核对；旧投影不能盖过尝试事实。

关闭事务将本轮置 cancelled，递增 fencing token，释放关联 Loop 占用，记录状态快照、原始 completion/error/凭证和人工证据，并通过已有配置更新方法暂停 Work，保存配置版本与事件。不会消费遗留指令，也不会重新执行原 Run。恢复车间仍是主人后续的独立动作，防止关闭瞬间自动执行积压任务。

无持久租约的历史运行不可通过这个入口直接接管；其迁移治理仍在后续范围。
