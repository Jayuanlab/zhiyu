# 11M 反馈评价的可追溯样本口径

本批接续 11L，解决质量报告把所有意见都视为可追溯召回评价的问题。保留历史反馈，不补造关联核验；未改日常数据库、未生产构建或切换。

## 行为与证据

- feedbackQuality 明确 sampled_feedback 范围，分别给出关联已核验、未关联、旧数据未核验、关联字段矛盾数量，以及关联日志在当前日志样本内/外数量。样本为空时核验占比为 null。样本外可能是窗口/上限或删除，不能直接称为丢失。
- feedbackOutcomes 保留全部意见；新增 verifiedFeedbackOutcomes。可追溯评价的可观测性标记和 Loop/Run 关联诊断只使用已核验且存在 contextLogId 的反馈。关联核验率不等于人工标签准确率，更不等于召回准确率。
- 平台记录保留关联状态；原车间事件缺少统一核验路径，保守标为 legacy_unverified。未自动改策略、扩大授权或确认事实。
- 首轮既有测试有 4 项失败，因为旧 fixture 没有核验标记却期望参与可追溯诊断。正向 fixture 明确增加 verified_context，旧平台意见测试改为保留总数但不可评价；另增反向混合样本测试，避免仅放宽原断言。见 [首轮](11M-feedback-first.json)、[13 项针对性测试](11M-feedback-checked.json)。
- 真实服务读取反馈并生成车间质量报告：2 条意见中已核验 1、未关联 1，已删除上下文归入当前日志样本外，核验比例 0.5，全部意见计数 2、核验意见计数 1。沿用跨 owner、并发、写入故障重试保护。21:15:20—21:15:26；146 迁移、131 表、1566 字段检查通过，隔离库已清理。见 [数据库证据](11M-feedback-postgres.json)。
- `pnpm exec tsc --noEmit` 退出 0；全 Web 1426 项中 1422 通过、0 失败、4 原有跳过，见 [全量结果](11M-web-all.json)。本次未改页面，无额外页面回测；11L 的页面证据仍只覆盖其已记录范围。
