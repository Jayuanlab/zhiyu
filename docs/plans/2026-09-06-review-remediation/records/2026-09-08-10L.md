# 10L 运行历史展示模块

## 修改

新增 run-history-view，独立负责对话框、读取状态、刷新/重试/续页和运行索引。父页面仅组合查询结果、解释后的记录和记录卡片；查询仍由 10J hook 管理。索引使用可复制的运行 URL，保留组合键打开链接；刷新和读取时间改为可换行的紧凑操作区，读取时间明确使用 Asia/Shanghai。

## 回测与发现

- 初始类型检查通过；运行定位、隔离、失败重试、2052 条完整分页在 `10L-run-view-checked` 开发浏览器中通过，临时 PostgreSQL 146 迁移/131 表/1566 字段及清理通过。
- 首轮 `10L-run-view` 失败是“续页前最早证据必须不可见”的时序假设：SSE 可以独立补齐证据，失败截图中已合并 2052 条。改为直接验证首段 HTTP 未包含最早证据，保留续页重试、分页数量和最终唯一性断言。原失败报告保留。
- `10L-run-view-checked-mobile.png` 显示两侧裁切，原先只断言 scrollWidth/clientWidth 无溢出，未验证对话框位于视口内，不能算窄屏验收通过。增加实际 bounding rect 与视口边界轮询后，`node scripts/test-isolated-migrations.mjs --workshop-run-location-browser --record-prefix=10L-run-view-bounds` 于 22:22:12—22:23:05 通过；稳定后对话框左/右/宽均在 390px 视口内。人工查看最终截图，刷新按钮、时间和正文完整可见。没有基于非稳定帧盲目修改布局。见 [最终回测](10L-run-view-bounds-postgres.json)、[窄屏截图](10L-run-view-bounds-mobile.png)。
- 开发实例停止后类型检查退出 0；`pnpm exec vitest run --reporter=json --outputFile=../../docs/plans/2026-09-06-review-remediation/records/10L-web-all.json`：1462 通过、0 失败、4 原有跳过。
