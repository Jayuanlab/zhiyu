# 08B：真实交易命令、签名 HTTP 与行情撮合门禁

## 状态与范围

本批在 08A 的正式 PostgreSQL Interface 上实现真实下单、撤单和显式撮合，接入新的 Python HTTP 路由与版本化行情观测；同时将旧账户/订单/成交 GET 改为纯读。隔离回测通过。Web/车间调用仍指向旧写路由，历史恢复基线尚未核对，日常数据库尚未导入，旧 Python 写函数尚未退役，09 调度宿主尚未接入；因此整包 08 未验收。

未执行生产构建，没有重启日常量化服务；当前 8766 旧进程仍可能保留旧 GET 行为。新 GET 的证据来自加载当前源码的隔离 FastAPI 应用，不把源码通过当成日常进程已更新。下一批完成切换后再统一验证运行实例。

## 实现

- `paper_commands.py` 提供 submit/cancel/match_tick。下单只接受委托并冻结资金，不顺便成交；资金、订单、持仓、成交、回执、事件在账户锁事务内提交。定点金额、100 股、涨跌幅、单笔 30%、单票 40%、买入计划偏离、可卖 T+1、卖出冻结继续执行。单票上限新增计入未成交买单，防止并发申请逐个通过后超限。
- 相同 commandId/tickId 先匹配主人、actor、角色及意图摘要，直接返回原回执；不依赖行情重取。新命令在取行情前校验账户所属主人，进入账户锁后重查控制开关、时钟和行情质量。业务拒绝留下可查询回执与事件。暂停交易/行情不可用时仍允许符合撤单时段规则的主动撤单。
- 角色在领域层再次限制：owner/trader 可下单撤单，scheduler 才可撮合，hunter 无交易权限。HTTP 所有身份来自独立签名上下文，订单 JSON 禁止额外 actor/owner 字段。
- `/paper/v2/accounts/{id}`、`/commands/{id}`、`/orders`、`/orders/{id}/cancel`、`/ticks` 接入真实事务服务。签名绑定方法、路径、原始请求体 SHA-256、主人、角色与 120 秒有效期；要求内部凭证及独立 QUANT_PAPER_SIGNING_KEY。QUANT_PAPER_OWNER_ID 明确绑定本机主人；未配置返回不可用，不推断共享部署支持。数据库和行情同步工作在线程池执行，不堵塞 FastAPI 事件循环。
- `paper_observation.py` 只读实际配置的自选池，不触发旧配置迁移，不使用默认示例股池；取报价期间股池变化会使本轮失效。保留报价原始 updated_at，不能把 fetchedAt 当 observedAt。缺失、不明、过期、未来报价及自选池失效明确等待，不成交。
- `config/paper-market-policy.json` 记录应用轮询预期 10 秒、腾讯源最大报价年龄 30 秒及版本；这是应用控制策略，不是供应商时效保证。锁等待超过年龄上限也拒绝本轮撮合。
- `config/paper-calendar-2026.json` 使用沪深北三所已发布的 2026 休市安排，有发布、覆盖和到期时间。2027 年无配置时明确未知，不能按工作日兜底成交。参考：[上交所公告](https://www.sse.com.cn/disclosure/announcement/general/c/c_20251222_10802507.shtml)、[深交所公告原文](https://dataclouds.cninfo.com.cn/sjother2/regulatory/2025/20251222/50b258f0d89b4076b459eb746a7e100d.pdf)、[北交所公告](https://www.bse.cn/important_news/200027428.html)。
- 事件状态摘要对订单/批次/成交按 ID 排序，使读取时的集合顺序不会造成虚假摘要差异。原始记录及命令意图不因排序改变。
- `paper_trading.py` 的旧 get/read/list 路径统一读取快照，不初始化、不 reconcile、不保存；缺失/损坏快照返回不可用。旧写入口留待下一批整体切换，不能据此称全部 JSON 写入已消除。
