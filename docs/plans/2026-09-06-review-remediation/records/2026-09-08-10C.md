## 实际实现

- URL 的 workId 定位车间，tab 定位可见详情页签；关闭详情移除 tab。用户选择写入 history，首次默认选择和非法值归一化使用 replace，不额外堆积回退记录。
- 只在当前用户的车间列表成功加载后解析可访问目标；缺失/无权限 ID 回退到列表内默认车间，不请求该 ID 的详情。切换车间清除原 runId/reviewId，避免跨车间沿用定位。
- 旧 work/tools/boundary 页签归到 loops，interactions/memory 归到 sources，outbox 归到 review；未知值（包括 constructor）归到 run。
- 列表加载失败与空列表分开。首次失败时保留原始链接；恢复后仍能定位原目标。
- 从存储的详情快照派生当前详情时验证 workshop.id，只显示当前选择的快照；旧车间请求失败也不能覆盖新车间错误状态。保留已有按 ID 合并请求和响应保护。
- 车间选择按钮补充 aria-pressed，让辅助技术能识别选中状态。

## 回测与失败记录

| 场景 | 实际结果 |
|---|---|
| workId/tab 深链接、刷新 | 恢复同一车间和“记忆与资料”页签 |
| 改页签、改车间、连续后退 | 依次恢复前一个车间及前一个页签 |
| 复制链接到新页面 | 恢复同一选择与页签 |
| 外部 owner 的 ID 与未知 tab | 回退到可访问车间和 run；不出现对方名称，不发对方详情请求 |
| 旧 memory 页签 | 归一化为 sources |
| 列表 503 后恢复 | 错误可见、目标 workId 保持，解除故障后正常进入 |
| 先请求甲、切乙、再返回甲的真实响应 | 等待甲响应 body 完成及浏览器两帧后，乙任务仍可见，甲任务不可见 |
| 类型/文本 | tsc 退出 0，修改范围 diff whitespace 检查通过 |

证据：[完整报告](10C-location-recovery-postgres.json)、[浏览器结果](10C-location-recovery-browser.json)、[人工查看的截图](10C-location-recovery-selected.png)。截图为乙被选中、甲旧响应已返回的状态；它不证明其他后台面板已经加载或业务运行完成。

首次 [10C-location-first](10C-location-first-postgres.json) 失败：地址栏改变，但选择仍停在原车间。检查本地 Next.js `app-router.js` 后确认，将 window.history.state 原样传给 pushState 会携带 __NA，触发内部调用分支而跳过 URL 状态同步。改为传 null，由 Next 注入内部状态，随后 [router](10C-location-router-postgres.json) 通过。[final](10C-location-final-postgres.json) 补强旧响应 body 完整返回后的检查；最后 recovery 增加列表失败保留目标用例。全部历史证据保留。
