# 06C3d：事件与 Outbox 草稿事务写入

本步骤把携带执行上下文的事件和草稿写入接到租约事务，并将普通草稿的业务行与事件改为一次提交。06 整包、07 外部发送及全部 12 个方案仍未验收，不能切换日常实例。

## 改动

- `withWorkshopControlWrite` 统一数据库事务入口；有执行凭证时核对 Work/Run，在事务前后校验租约。事件自动关联本轮 Run，并使用宿主凭证写入 actorId、workerId、token，覆盖输入中伪造的执行来源。
- `appendWorkshopEvent` 使用该入口。错误审查投影仍在原始事件提交后执行，投影失败记录警告，不能把已提交事实报告为未提交。
- `createOutboxDraft` 在同一事务内插入草稿和 outbox_draft 事件；普通调用也不再先留下业务行再单独写事件。模型执行上下文会补齐草稿的 Run 来源。
- `executeWorkshopAgent` 整段运行置于不可变执行上下文中，使其现有事件调用也进入事务校验；MCP 继续沿用此前的异步上下文。

## 限制及后续

没有调用真实模型、发送消息或修改日常数据库。草稿创建的事务原子性不等同于跨运行重复创建去重，更不等同于外部发送 exactly-once；幂等键、发送尝试和未知结果恢复属于 07 后续。

本步骤仅在有宿主执行上下文时校验租约。无上下文的主人/遗留写入路径仍保持原语义；它们能否向已领取的 Run 写入，尚需单独封闭和回测。记忆、提案、Heartbeat 等剩余写入仍未全部迁移。消费者尚未接入，不能把本步骤当作完整运行隔离验收。
