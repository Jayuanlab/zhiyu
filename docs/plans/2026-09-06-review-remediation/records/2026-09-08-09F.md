# 09F 理解模块与取消传递

理解队列接入统一 worker，固定每轮最多 20 项、并发 2 项，模块超时 5 分钟。取消后不再领取等待中的任务；活动任务的 Promise 保留到实际结束，宿主不会因发出取消就释放占用。底层 processor 在读事件前、创建/领取前和领取后检查取消，并把信号传到 SDK generateText 和兼容 HTTP 请求，保留原请求超时限制。

模型调用取消后不会继续轮换备用模型，也不会生成 fallback summary 或标记成功。已领取任务通过原失败路径保存失败状态和重试时间。开始处理状态的写入也移入该失败处理范围。已经进入内部结果落库的流程仍等待实际结算，不把取消请求伪装成所有写入已回滚。

worker 计数修正：processor 返回 skipped 时不算完成，fallback_summary 仍计入已产出结果但同时计 degraded，宿主将该轮暴露为降级错误码，不能用摘要替代完整理解成功。五个注册模块为 Loop 排队/执行、车间执行、Heartbeat 排队/投影、理解处理。
