# 06C3a：在现有命令事务中校验执行租约

本步骤完成命令事务层的可选执行凭证接口。整包 06、模型/工具执行链及全部 12 个方案尚未完成，当前不能切换日常服务。

## 改动

- `withExecutionTransaction` 复用调用方的数据库事务，锁定所属 Work、租约和 Run，检查 token、worker、运行状态及数据库时间；回调结束后再次检查原期限。`withExecutionWrite` 复用此接口，避免事务嵌套自锁。
- 命令账本和普通/准备型数据库命令适配器接受独立的 `executionLease` 参数。它不进入持久命令 payload 和哈希，新执行者可保留原 commandId、意图及获选草稿重试。
- 执行凭证目标必须与命令所属主人和 Work 一致。失租异常向外传播并回滚整个执行事务，包括版本、业务数据、事件、审计和结果回执；已接受命令仍可查询为 queued。
- 已完成命令只返回原回执，不重新执行 handler。即使调用者携带旧凭证，也不会由此修改后续运行。

## 边界及后续

本次没有数据库迁移，没有启动模型、外部发送或新消费者，没有升级日常数据库/服务。当前参数仍是可选接口，执行器和 MCP 尚未传入；不能把事务层测试当作真实工具端到端验收。

下一步将执行凭证从执行器传至实际数据库写入适配器，并处理工具内部的混合写入/外部动作。只在工具调用前检查一次不足以防止失租后的写入；“查询”工具也可能持久化数据。外部动作仍需 07/08 的意图、幂等和未知结果恢复，不能放进数据库事务。命令接受和只读准备处于执行事务外，本步骤不宣称它们受执行租约保护。

已定位后续入口：`mcp-tools.ts` 的统一 handler 包装当前只重读归属/边界；`executor.ts` 使用 `bypassPermissions`，而 `lib/ai/extensions/agent/claude/index.ts` 的 `canUseTool` 仅在非 bypass 模式安装。原生工具保护需要贯穿实际生效的 SDK 调用钩子；本地 SDK 类型提供 `PreToolUse`，尚未接入及回测。
