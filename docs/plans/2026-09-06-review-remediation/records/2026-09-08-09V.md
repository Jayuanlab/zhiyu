# 09V 本地依赖启动、失败清理与日志

本阶段核对根目录启动入口与依赖脚本，修复健康请求无限等待、Python 启动日志丢弃、启动失败遗留进程、错误服务占端口仍继续安装启动的问题。保留既有工作区修改；HEAD 为 `a0e94e5f19661895adce29787da85385117f2477`。

## 行为变化

- `scripts/start-local-deps.cjs` 按外部环境、Web `.env.local`、Web `.env`、量化 `.env` 的顺序读取配置；外部显式空值不会被文件覆盖。健康检查有 1500ms 超时，并校验服务响应字段。端口有监听但健康或服务标识不匹配时，报告冲突，不安装依赖或启动替代进程。
- 新增 `scripts/local-service-process.cjs`，量化及微信服务隐藏启动，标准输出与错误写入 `.runtime/dependencies/<服务>-<instanceId>.log`，相邻 JSON 保存本次启动的 instanceId、PID、开始/观测时间及 ready/failed/stop_unconfirmed。日志不写环境变量或启动参数。记录明确只是启动时观测，不能当作当前健康状态或依据旧 PID 自动杀进程。
- 启动进程立即退出、缺少可执行文件、健康超时、启动期间收到 SIGINT/SIGTERM 均返回明确原因和日志路径。失败只停止本次创建的进程树，等待退出；不能确认停止时保留 stop_unconfirmed，不宣称已结束。已健康的依赖继续复用，不随 Web 停止。
- 微信普通启动故障允许 Web 降级启动并明确提示外发不可用；停止请求及无法确认进程停止则让启动链路失败。量化缺失或启动失败返回非零退出码。
- 移除启动期间直接执行的 RSS `ALTER TABLE` 修补；这些字段已有正式迁移 `0074_rss_subscription_error_fields.sql`。启动只检查依赖，数据库结构变更走显式迁移。
- Docker Desktop 隐藏启动并处理 spawn 失败；新建本地 PostgreSQL 容器的端口限定回环绑定，不修改已有容器。
- 根目录补充 `pnpm start`，依赖检查后进入已有 Web/worker 托管入口；生产启动使用已有构建。本次没有运行日常生产启动或迁移。
