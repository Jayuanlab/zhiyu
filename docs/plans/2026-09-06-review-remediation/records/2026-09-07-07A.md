# 07A：微信服务持久发送命令（实施中）

## 本轮改动

- 新增 SQLite SendLedger，发送命令以 commandId 唯一，payload hash 绑定收件人与消息。准入后先提交 started，再调用 GUI，成功保存完整服务回执。
- 同命令成功重试不再消费确认 token 或调用发送；同命令不同 payload 冲突。发送异常记录 unknown；进程退出遗留 started 查询为 unknown，禁止再次派发。
- `/send-status` 使用现有 bearer 认证，提供 sent/unknown/not_found 查询。接收者白名单仍在发送入口检查，账本不授予新权限。
- 默认账本在 LOCALAPPDATA/Zhiyu/wechat-desktop，可由 WECHAT_DESKTOP_SEND_LEDGER_PATH 显式配置。测试全部使用 TemporaryDirectory 和动态端口。
- 兼容旧调用：缺少 commandId 时以确认 token 的 SHA256 派生命令，只能防同 token 重复。Web 稳定 attempt ID 尚未接入，不能宣称新 token、修改内容或整条外发链已幂等。

## GUI 串行化与 Web 传输增量

- 新增按账本路径共享的 OS 文件锁。新发送在消费确认凭证前取得非阻塞锁，发送回执持久化后释放；进程退出由操作系统释放。已有命令回执查询不触发 GUI。
- 共享同一账本的不同线程/独立进程同时发送时，后者收到明确的未派发 busy。锁争用不产生 started 行、不消费授权；锁释放后可重新尝试。不同账本路径不共享此锁，同一 Windows 会话必须配置同一账本路径，不宣称任意多服务配置均安全。
- Windows 上真实文件锁、跨进程竞争和崩溃释放测试通过。Python 12 项通过，均使用临时文件、假发送、临时 HTTP 端口，见 `07A-wechat-tests.log`。非 Windows 锁分支尚未在本机验证。
- Web 客户端支持显式 commandId 及 getWechatDesktopSendStatus；2 项目标测试验证网络重试保持命令 ID、查询 unknown 不调用 /send。类型检查退出 0；全量 1311 通过、0 失败、4 项原有跳过。证据 `07A-client-tests.log`、`07A-types.log`、`07A-unit.json`。
