# 09X 理解派生写入与完成状态同事务

为后续安全继续/重放建立真实事务边界：此前处理函数依次提交笔记、待办、记忆、场景快照和图谱，后一步失败可能留下半批结果。现在模型请求仍在事务外，进入 applying 后将本轮数据库派生写入与任务完成/消息 seen 投影放在同一事务中；失败或进程中断时整批回滚。

## 实现

- `lib/db/client.ts` 增加仅覆盖当前异步调用链的事务作用域，既有仓储通过同一 db 入口使用当前事务；记忆写入、快照写入和完成状态内部的嵌套事务仍作为保存点工作。作用域外及并发请求继续使用原数据库连接入口。调用方必须等待所有工作，不得把网络请求或脱离等待的后台工作放进作用域。
- `processing-jobs.ts` 的 `applyInteractionProcessingWrites` 在事务中锁定指定主人、任务及轮次的 applying 行，执行写入，最后带宿主有效性检查完成任务。使用 ORM 条件更新获取行锁，不引入新的 PostgreSQL 专用 UUID/锁语法到该入口；SQLite/Tauri 整体仍未验收。
- `processor.ts` 的正常理解写入与摘要降级写入均接入这个入口；完成状态统一由事务入口提交。取消、迟到轮次、失效宿主仍服从原有校验。旧任务和结果未知仍进入 needs_review，不根据本次代码改动推定历史数据已经回滚。
