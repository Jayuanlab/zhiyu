# 09B 宿主控制循环

新增 RuntimeHostController，将持久实例租约与进程内模块占用连接起来。首次领取后先写入心跳，确认成功才分发任务；续约串行，不让未完成的数据库请求重叠。暂停后继续报告状态但不启动模块。显式 disabled 不领取，并停止已有调度。

租约确认使用本地单调时间和保守期限；数据库调用挂起或外层不再调用 step，仍由独立期限计时器停止新启动并发送取消信号。数据库错误、拒绝续约或迟到确认均不能重新启用失租实例。停止同时约束模块等待和数据库确认等待；底层工作未结束时保留 stopping，不提前释放；数据库确认未知时显示 lost，不能伪装正常停止。领域动作的幂等与执行租约仍由原有领域接口负责。

## 真实进程与模式边界

新增独立 Node 子进程夹具，直接运行 RuntimeHostController + RuntimeHostStore，数据库地址必须是本机随机 zhiyu_test_ 库。两个进程同时启动，只有一个进入 running 并执行模块；首个持久心跳在 10 秒内出现。挂起慢模块时快速模块仍继续执行。异常终止持租进程后观察数据库租约离线，新进程以递增 token 接管，原竞争失败进程不自动恢复调度。随后关闭新进程实际数据库连接，确认进入 lost、慢模块收到取消、后续快速模块计数不再增加。

`D:/zhiyu/apps/web` 执行 `node --import tsx --conditions=react-server scripts/test-isolated-migrations.mjs --runtime-host --runtime-host-processes --record-prefix=09B-process`，退出码 0，UTC 09:19:58.317—09:20:04.240。138 项迁移、存储检查及 3 组真实进程检查通过，测试子进程和随机库清理完成。见 [报告](09B-process-postgres.json)、[进程事件](09B-process-processes.json)。关闭的是该测试进程的数据库连接，不是停止数据库服务器；尚未覆盖网络黑洞或整个数据库重启，不扩大结论。

新增 runtimeMode / workerConfiguration：ZHIYU_RUNTIME_MODE 支持 embedded/worker/disabled，未配置时保持当前 embedded；ENABLE_LOCAL_SCHEDULER=false 与非法模式均拒绝启动。worker 必须显式提供 ZHIYU_RUNTIME_OWNER_ID。旧页面调度的轻量门禁在 worker/disabled 模式下拒绝启动，即使旧启用标志为 true。日常环境未修改；独立 Heartbeat CLI 的强制启用行为仍待统一入口处理。
