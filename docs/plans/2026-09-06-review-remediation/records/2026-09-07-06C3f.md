# 06C3f：记忆归属不变性与受控写入

本步骤保护 Brain memory 的 insert/upsert；06 整包与全部 12 个方案仍未完成。

## 改动与边界

- 普通 upsert 不再改写 userId、scopeType、scopeId、ownerType、ownerId。冲突更新使用同一 SQL 的归属条件，包含 global 的 NULL scopeId；归属不匹配返回 memory_identity_conflict，不能先检查再被并发请求覆盖。
- 同一身份仍可更新内容、状态等字段；不通过普通写入实现转移归属或作用域迁移。
- 执行上下文存在时，insert/upsert 在租约事务内校验用户、当前凭证及提交前有效期，同时提交 brain_memory_written 事件。事件带真实执行来源和记忆 ID，不复制记忆正文。
- 租约不是资源授权。原有服务层权限检查保留；本步骤不宣称已解决授权撤销与写入间的竞争、其他 Brain 表的写入或审核流水的原子性。
