# 07B：Outbox 发送尝试事务（实施中）

## 本轮实现

- 迁移 0135 新增 workshop_outbox_attempts，保存稳定命令、内容/策略 hash、发送载荷、状态、外部回执和失败阶段；同 owner/command 唯一，同 Outbox 的 sending/sent/unknown 互斥。尝试存在时禁止级联删除证据。
- beginOutboxAttempt 先锁定主人所属 Work，再锁 Outbox；重新核对当前状态、内容和策略。需要审核时必须同时匹配内容与策略 hash，旧的 approved 字样不构成有效审核。
- 首次领取返回 dispatch=true；同命令后续请求返回当前尝试及 dispatch=false，不再获得发送资格。另一命令不能越过未解决或已发送尝试。
- 受控执行器需同 Work/Run 的有效租约，发送尝试和 effect_started 在同一事务记录；主人路径使用可信 userId 和资源归属校验。
- settleOutboxAttempt 记录已存在尝试的 provider 观测，允许 sending→unknown→sent，不允许迟到 unknown 把 sent 降级。尝试状态、Outbox 状态及事件同事务；外部回执可在生产者失租后记入独立观测，不触发新的发送。

## 发送编排增量

- 新增 dispatchOutboxAttempt：先持久领取，再基于保存载荷生成 preview，并以 attempt ID 作为微信 commandId 发送。已有尝试只查询 /send-status，不重新 preview 或发送。
- 已确认 sent 直接返回；响应丢失、旧服务不支持查询、查询无记录或无法确认时保留 unknown。发送前再次检查执行租约；结果落库仍用独立尝试观测事务。
- 底层 sendWechatDesktopMessage 改为单次网络调用，移除发送请求的自动重试。稳定 commandId 仍传给服务端；网络异常后的恢复由状态查询承担，避免旧服务未实现命令幂等时自动重复发送。更新目标测试验证只调用一次。
- 真实 PostgreSQL + fake provider 组合通过：外部产生一次效果后抛响应丢失，首次 unknown，随后查询确认 sent，重复调用不增加发送计数；not_found 查询也不会触发再次派发。
