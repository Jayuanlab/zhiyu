# 06E9：旧执行结果的主人核对闭环

日期：2026-09-08。实现 06E8 遗留的人工核对入口，范围包括持久核对记录、迁移门禁、HTTP、页面与提交恢复。开发及隔离回测通过；生产组合回归、旧导出执行函数退役与正式宿主仍未验收。

## 控制对象与边界

- 旧 job_executions 是原始事实，超时后仍保持 needs_review/unknown，不因主人确认而改写为成功、失败或伪造完成时间。
- 主人必须明确选择“未产生外部动作”或“已逐项核对并处理外部动作”，填写依据，并确认旧执行器已停止。仍无法确认时保持阻塞，不开放自动重试。
- 0142 新增 legacy_execution_reviews；保存主人、Loop、执行、来源、命令、内容哈希、执行快照哈希、结论、依据与核对时间。每个执行版本的记录不可被新提交覆盖；原观测变化时旧记录失效，必须保存针对新快照的核对。
- 同一事务锁定所属 Loop、旧任务和执行；核对记录、旧任务停用及 active Loop 暂停一起提交。归档和异常状态不因核对而被重新打开。查询和处理均校验主人；旧执行仍 running/queued 等状态时拒绝人工关闭。
- 同主人/命令用事务锁串行化，同内容返回原回执，异内容冲突。数据库故障整体回滚。此命令没有模型调用、真实发送或外部重试。

## 页面与反馈

迁移预检显示原输出和诊断（折叠）、核对结论、依据与停止确认。提交前先持久保存请求；响应丢失后通过“核对上次提交”重放原幂等请求，刷新或切页不会制造第二次核对。完成后显示原结论、依据及本地时间，重新读取迁移预检；原始执行历史保留，旧任务停用，新车间迁入后仍暂停。

复用既有客户端命令恢复机制，新增严格的 legacy review 请求/回执契约，不扩大执行或外发的自动重放范围。已应用 Windows UTF-8 写入规则，中文截图及存储回读无乱码。
