# 06D6：定时接受与计划推进事务

## 修改范围

Work 所属 Loop 的定时扫描现在只观察到期状态。`dispatchScheduledWorkLoop` 在同一事务内锁定主人所属 Work/Loop，复核数据库时间和计划游标，接受唯一运行、推进计划并写事件。忙碌不消耗计划，之后可以重试；错过宽限期或非交易日则原子跳过并记录原因。一次性计划使用已消费时刻标记，排队期间不再错误显示已完成，也不会完成后再次排队。

定时身份为 Loop 与计划时刻的稳定组合，其请求与回执保存在关联运行，不借用主人的配置版本账本。相同身份、不同输入冲突；手动命令使用已保留定时身份同样明确冲突。消费者以保存的请求恢复运行，拒绝请求被修改或目标不属当前主人，不重新接受一遍已经排队的命令。

调度状态随关联运行进入 queued/running/idle/needs_review；状态更新核对 lastScheduledRunId，不能覆盖更新一轮的状态。提取数据库接受函数到 `loop-admission.ts`，调度器不直接承担模型执行。普通生产扫描仅排队，显式等待完成的调用才在领取后执行。
