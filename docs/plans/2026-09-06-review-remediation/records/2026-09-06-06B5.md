## 实际改动

模板创建、自检任务命令接入数据库命令账本，Loop、初始状态、创建事件和成功回执同事务提交。相同 commandId 重放返回原结果；不同 payload 或过期版本拒绝。

自然语言创建使用 `runPreparedDatabaseWorkCommand`：先接受并保存用户输入，在事务外调用只读解析器，保存第一个完成持久化的草稿，再用该草稿提交创建。新迁移 `0129_add_command_preparation` 为 work_commands 增加 prepared_payload、prepared_at、preparation_error。解析失败保留 queued 和 preparation_failed；明确重试允许重新解析。草稿已保存后不再重新解析，提交失败仅重试数据库操作。并发解析可能重复消耗模型计算，但只有一份草稿获采用、一个创建结果生效；此处不承诺模型调用次数为一次，也不允许把消息、订单等外部写入放进 prepare。

自检任务通过数据库条件查找，分页前过滤 templateId/已有名称和目标兼容标识，不再在最近 200 个 Loop 中查找。HTTP Loop 创建入口接入 commandId/Idempotency-Key、expectedVersion 和冲突状态码。

主要文件：`lib/work-runtime/commands.ts`、`database-command.ts`、`command-ledger.ts`，`lib/loops/service.ts`、`templates.ts`，`lib/workshops/loop-service.ts`、Loop POST 路由、PG schema 和迁移 journal。
