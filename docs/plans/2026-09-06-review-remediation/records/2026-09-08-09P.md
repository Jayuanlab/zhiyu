# 09P 理解任务宿主关联与崩溃核对

新增 PostgreSQL 迁移 0148、runtime_interaction_claims 表。正式宿主领取理解任务时，在同一事务验证当前主人的活动租约、领取任务并记录 job/attempt/owner/instance 与时间。暂停状态禁止新领取，已有任务允许继续完成。页面手动路径不伪造宿主关联；旧任务无关联时不以时间猜测进程已死亡。

每轮理解模块先检查关联宿主：running/applying 任务的原租约失效、实例停止或丢失时，原子转为 needs_review，并在对应领取记录保存 recovered_at。多轮或并发核对只生效一次，不自动重放未知派生写入。仍在线和暂停中的宿主不触发此处理。

派生笔记、待办、记忆等写入阶段之间检查当前 job/attempt 与原宿主租约；最终完成也验证同一关联。已过期的宿主不能进入新的受检查写入阶段或确认成功。已经进入单个内部写入函数的操作仍需等待/核对，不能将阶段前检查描述为所有内部 SQL 都具备跨表原子 fencing。
