# 06E1：独立 Loop 迁入车间的事务核心

日期：2026-09-07。本阶段实现 PostgreSQL 迁移命令核心；HTTP、页面预检/审核与生产组合构建尚未接入，不计作 06 整包验收。

## 改动

- 新增 0140 迁移和 `loop_runtime_migrations`：保存原 Loop/状态快照、摘要、主人、命令 ID、新车间和迁移时间。保留原 Loop ID、配置、历史 Run 与观测状态。
- `previewStandaloneLoopMigration` 在 Loop 行锁下生成预检：显示来源快照、拟建车间边界及有效权限；列出已归属、异常状态、未结束 Run、待审核/可继续审批、旧 scheduled_job 等阻塞项。
- `migrateStandaloneLoopToWork` 只接受主人命令，要求稳定命令 ID、快照摘要和停止旧控制器的明确声明。声明是主人核实结果，不伪称服务器已确认所有旧进程退出。
- 使用既有生命周期账本。新车间、归属变更、迁移证据、事件和成功回执同事务提交；并发/响应丢失重试返回同一车间。快照变更拒绝旧预检。
- 新车间与 Loop 均暂停，车间默认 draft。原 Loop 禁止外部写入时，车间外发保持 blocked；权限预检使用实际边界合并函数，不将原 deny 改成可审批。
- 当前版本的旧写入口与迁移共享 Loop 行锁；迁移后无 Work 租约的建 Run、完成 Run、状态更新、Loop 更新和审批创建被拒绝。数据库触发器另外禁止迁移对象直接插入 running Run。正常 Work 队列仍从 queued 接受并受租约执行。
- 旧完成入口的可选证据捕获移到事务提交之后，避免独立连接仍读取旧 running 状态。SQLite/Tauri 不开放本迁移能力。

## 验证边界与下一步

隔离测试覆盖历史保留、原拒绝策略、重复迁移、独立双进程去重、过期快照、忙碌/审批阻塞、外来主人/智能体/缺少 ID 拒绝、事件失败整笔回滚、迁移后旧写拒绝，以及明确激活后 Work 队列干运行成功。测试用原始 SQL 激活隔离对象，不计为页面激活验收。

当前仅源码核心；尚无面向用户的迁移操作入口，未迁移日常数据。最新生产候选仍为 61，不包含 D10/E1。旧版本二进制不具备新的写入口保护，切换前必须停止旧控制器；不能仅凭数据库新表宣布混跑安全。迁移记录使用 RESTRICT 保留审计来源，回退不能删除记录后放任旧执行器接管。
