# 09D Heartbeat 持久排队

新增 `lib/work-runtime/heartbeat-admission.ts`：以主人、车间、计划时刻构造稳定命令及 Run ID，在同一事务内锁定车间和 Heartbeat、检查数据库时间和权限状态、写 queued Run、消费计划时刻并写审计事件。重试读取既有结果；暂停、禁用、待核对执行和占用均保留原计划，等待后续处理。超过宽限期的唤醒只消费一次并记录跳过原因。事务等待期间收到取消，获得锁后不再排队。

排队时不执行模型，不建立另一套执行租约，不设置 started_at，也不写“已完成”。消费仍应使用方案 09C 的 Work consumer。该接口尚未替换旧 Heartbeat 扫描入口；后续需完成运行结果投影、旧入口退役和实际消费联调后再注册到 worker，不能把本文件存在当作 Heartbeat 整体接入。
