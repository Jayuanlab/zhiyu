## 改动与边界

核查前端命令接入时发现 `/api/loops/[id]` 的 PATCH 和 DELETE 仍直接使用 Loop service。车间任务修改模型检查器现在进入 `updateWorkLoopModelChecker` 命令，持久化原始修改意图，在 Work 锁内读取和合并其他验证配置。相同命令重放返回原提交结果，不能再次读取新配置构造不同的命令载荷或响应。

通用 DELETE 对车间任务调用 `updateWorkLoop` 归档，保留运行和审批历史；底层 `deleteLoop` 的 SQL 同时限定 `workshop_id IS NULL`，避免其他调用或归属变化绕过历史保护。独立任务继续使用原有删除语义，不声明已获得 Work 命令账本保证。任务页面按钮改为“移除”，确认及成功提示区分归档和删除。

命令冲突保留 409/404/400 与原因代码；未知执行异常返回 500，已接受命令保持 queued，不伪装成确定拒绝。未增加自动重试、消费者或真实外部动作。
