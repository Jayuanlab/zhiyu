# 06F 通用审核命令与桌面恢复

## 范围与实现

处理 10G 登记的通用 review-items PATCH 缺口：单项/批次记忆治理确认、治理提案与模拟变更计划审核、暂不处理及服务错误组处理。只验证桌面 Web，移动端专项暂停。HEAD 为 a0e94e5f19661895adce29787da85385117f2477；沿用当前未提交工作区，不覆盖此前修改。

- 审核业务从 HTTP 路由迁到 `lib/work-runtime/review-commands.ts`，使用现有 `runDatabaseWorkCommand`。路由要求 commandId/expectedVersion，身份来自服务器会话并校验车间主人。
- 同一事务读取并锁定该车间现存审核记录，使用事务连接完成审核状态、派生提案和事件写入；事件关联 commandId/actorId。命令结果与版本按既有账本提交。意外数据库失败保留 queued，显式重试原命令；业务冲突返回持久拒绝结果。
- 普通审核处理直接定位记录，不以最新 200 条列表判断旧记录是否存在；已处理记录不能再次覆写处理结果。
- 六处页面提交改用现有可恢复命令客户端，补充审核响应的记录/车间/状态匹配检查；响应未知保留原请求，刷新后核对，完成后刷新审核及详情。冲突后重新读取详情版本。
- 治理提案与变更计划仍是审核/模拟计划，不执行记忆修改；没有扩大自动执行权限。

## 实际回测与故障记录

- 初次针对性测试 18/18 通过；接入客户端响应身份校验后，审核路由、审核投影和客户端命令合计 34/34 通过，见 [单测结果](06F-review-client-unit.json)。最终 `pnpm exec tsc --noEmit` 于 22:59 退出 0。
- `06F-review` 首次隔离验证失败在夹具写入：审核 metadata 是文本列，传入 postgres JSON 对象导致 ERR_INVALID_ARG_TYPE。改为参数化 JSON.stringify 字符串。原记录保留，临时库已清理。
- `06F-review-checked` 与 `06F-review-final` 的真实 HTTP 检查已执行到桌面阶段：验证第二项提案写入故障使整个批次回滚、命令保留 queued、原命令并发恢复结果一致、payload/version 冲突、跨 owner 拒绝、单项/批次治理、提案拒绝、模拟计划无实际修改、服务错误组处理和事件来源。
- 上述两次整轮失败：复制审核链接到第二标签页并关闭后，原页面的“返回审核列表”不可见。固定源码后仍出现，随后 diagnostic/recovery 两次组合也复现；不能简单归因于改文件热更新。单独的 `06F-review-navigation` 浏览器回测通过，仅作为缩小触发范围的证据。
- `06F-review-recovery-review-diagnostics.json` 精确定位失败资源为 `/_next/static/chunks/app/(chat)/layout.js`，错误 ERR_CACHE_WRITE_FAILURE；实测文件 31,664,912 字节。C/D 剩余空间分别约 66.7/176GB。当前 Next router-server 开发静态默认为 no-cache, must-revalidate，仍会写缓存。将开发静态资源响应改为 no-store, max-age=0，避免多标签页并发缓存写入；生产 headers 配置不增加该规则，独立导入配置断言通过。没有关闭 CSP，也没有改掉真实审核断言。
- **最终隔离回测通过**：`node scripts/test-isolated-migrations.mjs --review-commands-browser --record-prefix=06F-review-no-store` 于 22:57:43—22:58:59 退出 0。146 迁移/131 表/1566 字段通过并清理临时库。上述全部数据库/HTTP 场景、超过 200 条窗口的旧审核处理、复制链接/后退、读取失败重试，以及服务端提交后丢弃浏览器响应、刷新并核对原命令均通过。数据库确认该命令仅一条成功回执和一次 applied 事件。
- 实际 HEAD 请求确认开发脚本 no-store；最终诊断未出现缓存写入失败或 pageerror。开发编译仍可能重新导航，但原页面能够恢复并继续操作，不声称消除了全部 HMR 导航。见 [完整报告](06F-review-no-store-postgres.json)、[桌面结果](06F-review-no-store-browser.json)、[诊断](06F-review-no-store-review-diagnostics.json)、[恢复截图](06F-review-no-store-desktop-recovered.png)。截图已查看，审核状态与返回/重新读取入口可见；尚有技术术语展示留给方案 10。
