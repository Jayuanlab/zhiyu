# 06D9：主人运行核对面板与持久提交恢复

## 实施

车间页面加入独立 `RunReviewPanel`，列出待核对运行、原因、最近人工证据及发送结果阻塞。列表在数据库中先过滤 needs_review 再按运行 ID 分页，每页 20 项，避免较早的异常被最近正常运行挤出；返回明确的 nextCursor，支持逐页查看。

表单读取 owner-scoped 的核对快照，保存原始命令版本和租约观察。后台刷新只更新观测，不替换主人正在填写的提交基线。版本冲突保留输入；“重新读取核对状态”显式更新基线并撤销执行器停止确认，要求再次确认。关闭入口明确写为“关闭本轮并暂停车间”，默认结论仍为不确定。

提交复用既有 `createWorkCommandClient`，共享同一 actor 的 sessionStorage 待处理记录和全局“核对上次提交”入口。新响应契约核对目标 Run、决定与关闭状态；关闭响应必须同时声明 cancelled 和 Work paused。结果丢失时保留原 commandId、版本、租约 token、依据和确认，不用新请求替代。未核对发信返回持久 `unresolved_effect` 拒绝，页面给出处理提示。
