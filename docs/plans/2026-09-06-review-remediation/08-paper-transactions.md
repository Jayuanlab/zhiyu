## 1. 控制目标
账户读改写不丢订单，资金与持仓守恒，陈旧/不明报价不成交；查询不推进交易。

## 2. 被控对象
模拟账户、现金冻结、持仓批次、委托、成交、撮合 tick、价格与交易日事实。

## 3. 观测输入
临时 JSON 探针预期两条订单实际一条。现有 GET account/orders 会 reconcile 保存；撮合未验证报价时间，时段仅按星期判断。这不是已观测到真实资金损失。

## 4. 状态模型
沿用现有订单生命周期，增加 version、commandId、executionId、lastMatchedQuoteId、calendarVersion。金额使用定点精度，股票数量沿用现有规则。
本方案选用同一 PostgreSQL 实例内的独立 paper 领域表，Python 持有受限数据库权限；不通过 JSON 和 PostgreSQL 双写形成新一致性问题。具体驱动在实施时依现有依赖确认。

## 5. 控制器/角色
Python Paper Module 拥有账户领域事务；Web/worker 只提交命令和查询。操盘交易员只能消费当前自选股；猎手不拥有交易动作。Web command 与 Python 成交跨进程用稳定幂等键确认，不假装跨请求一笔事务。

## 6. 控制动作与工具矩阵
submit/cancel/matchTick 为写命令，readAccount/readOrders 为纯读。事务锁定账户行，校验规则，写订单/现金/批次/成交/领域事件后提交；commandId 唯一防重放。网络行情先取后锁，提交时复核质量和当前状态，事务期间不等待外部网络。
matchTick 由调度显式执行，重复 tickId/订单成交键不会重复成交。多个账户按固定锁序；不为每次读取隐式撮合。

## 7. 边界与审核
只模拟，不接券商。保留现金、仓位、T+1、100 股、限价、涨跌幅、偏离度和角色约束。
撮合读取同一版本的交易日事实和交易会话：quoteSessionDate 匹配当前会话、报价时间不在未来且年龄符合配置；报价最大年龄按源刷新频率配置并留版本，不能硬编码“当天即新鲜”。日历未知/过期或质量不足拒绝撮合，可继续显示历史参考。

## 8. 反馈与评价
每次拒绝提供规则、报价标识、日历版本；记录余额、冻结、持仓和成交的可核对快照。目标：重复成交 0、丢失订单 0、资金守恒、非法报价成交 0。

## 9. 异常、扰动和降级
数据库不可用时拒绝命令，不回退 JSON 写入。账户损坏不自动初始化百万资金。源失联保留订单待撮合并显示原因；失租/未知结果按 commandId 查询，不重复委托。

## 10. 页面可观测性
显示撮合器心跳、最后撮合时间、未成交原因、行情日期/质量、账户最后变更时间。查询新鲜与账户变更分开。
