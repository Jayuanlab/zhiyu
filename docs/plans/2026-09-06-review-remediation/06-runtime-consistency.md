## 1. 控制目标
同一个控制命令稳定去重；同一 Loop 不发生未授权重叠执行；旧执行者不能覆盖新状态；关键事件与状态一致提交。

## 2. 被控对象
Work 命令、LoopState、Run、调度时刻、执行 lease 和 workshop 事件序号。

## 3. 观测输入
现有进程 Set、随机 runId、读改写 stateJson、max(seq)+1 为静态风险；未在日常系统验证过重复执行。本包先用隔离双进程构造证据。

## 4. 状态模型
拟议 command 记录：ownerId、commandId、targetId、type、payloadHash、status、result、createdAt，唯一(ownerId, commandId)。
Loop execution：executionId、loopId、scheduledAt/triggerId、attempt、workerId、leaseUntil、fencingToken、stateVersion、status。定时唯一(loopId, scheduledAt)，手动触发由 commandId 去重；同一 Loop 原子 activeExecutionId 防手动/定时重叠。
status 区分 queued/running/succeeded/failed/interrupted/needs_review。超时恢复不等于重做外部效果。

## 5. 控制器/角色
Work Runtime Module 的 Interface 接收命令并返回持久结果。scheduler 只提交 due command；执行器领取/续租/回写。数据库事务 Adapter 和测试数据库 Adapter 验证同一 Interface。

## 6. 控制动作与工具矩阵
1. 接受命令事务：鉴权 → 唯一键去重与 payloadHash 校验 → 检查 expectedVersion → 创建 queued run/command → 推进下一计划时间 → 写 accepted 事件，一次提交。
2. 领取事务：检查 Loop 未占用或安全恢复条件，增加 fencingToken，记录 worker/lease，置 running。网络/模型调用不持有数据库事务。
3. 每次副作用前验证 lease 与 fencingToken；结果回写 WHERE version/token 匹配，否则拒绝旧执行者。
4. 暂停只阻止未来领取；停止当前运行进入 cancel_requested 并等待执行器确认。已有外部动作结果未知交给领域恢复。
5. 定时积压默认合并至一轮并记录 missedCount；不得把错过的交易/发送任务逐个盲目补跑。确需回放由命令显式指定。

## 7. 边界与审核
lease 不是外部系统 exactly-once 保证。外部 Adapter 必须用稳定 commandId 及领域幂等（07/08）。未支持 fencing 的外部系统，一旦失租且可能已发出动作，进入 needs_review，不能换 worker 自动重发。

## 8. 反馈与评价
命令去重命中、版本冲突、失租、恢复次数、重复副作用数、事件提交失败都有结构化记录。事件缺失不得报告 completed。

## 9. 异常、扰动和降级
DB 时间用于 lease 判断；进程退出后可查询已接受命令。重试退避且有次数上限；永久错误与待人工处理不无限重试。序号允许说明性空洞，但不能重复、倒退或无声漏掉已提交事件。

## 10. 页面可观测性
展示本轮 run、触发来源、已排队/执行中/恢复中/需核对、最近心跳与失败原因；将暂停未来与停止当前按钮分开。

## 12. 测试与验收
| 编号 | 故障/并发场景 | 必须结果 |
|---|---|---|
| T06-1 | 双进程提交同一命令/定时时刻 | 单一接受结果，payload 不同返回冲突 |
| T06-2 | 手动和定时争用同一 Loop | 仅一项执行；另一项返回可解释 busy/queued |
| T06-3 | 接受事务每个提交点退出 | 要么未接受，要么存在可恢复 run；不丢计划 |
| T06-4 | worker 失租后旧结果返回 | 不能覆盖新版本，不重复外部动作 |
| T06-5 | 双进程各追加 100 事件 | 200 条唯一有序；状态和关键事件事务一致 |
| T06-6 | 暂停、取消、重启、过期积压 | 行为与记录一致，不盲目补跑 |
| T06-7 | 事件通知丢失、SSE 重连 | 从持久 cursor 补齐，前端去重 |

必须真实临时 PostgreSQL 与独立进程；mock 只能补充错误分支。
