# 11 记忆回填、证据与反馈质量

覆盖 canonical 低覆盖及记忆待办质量；依赖 01/04/05，持久命令接入需 06。

## 1. 控制目标
回填可解释、可暂停和可重跑；旧的重要边界能被找到；主人反馈减少无用待办，而非把所有历史条目自动确认。

## 2. 被控对象
Brain canonical 字段、legacy Adapter、回填批次、来源证据、审核反馈和召回候选。

## 3. 观测输入
生产 migrationReady=true，canonical_kind/group 覆盖 185/1478≈12.5%。这是字段覆盖率，不是召回准确率；旧群聊提取是否误报需要标注集验证。

## 4. 状态模型
回填任务含 batchId、mappingVersion、sourceCursor、scanned/updated/skipped/conflicts/missingEvidence/errors、beforeValueHash、startedAt、checkpoint、status。
审核反馈记录 accepted/dismissed/corrected/completed、reason、actor、sourceEventIds、version；事实确认与任务完成沿用 04 分离。未知来源不填造 observedAt。

## 5. 控制器/角色
回填 Module 转换结构，不改变事实身份或用户确认；理解 Module 产生候选；主人确认。召回 Module 仍受 user/work/scope/grant/过期与 denied 规则控制。

## 6. 控制动作与工具矩阵
dryRun → 展示映射统计与样本 → 分批 apply → checkpoint → 验证。命令按 batchId/sourceId/mappingVersion 幂等；版本冲突跳过并说明，不覆盖回填期间用户纠错。
召回先构造旧而重要边界、冲突和授权变化 fixture，再决定候选排序/上限调整；不凭字段覆盖低就重写向量检索。

## 7. 边界与审核
缺证据标 missingEvidence，不自动晋升长期确认记忆。原始微信事件不可改写。高置信模型值不等于可信承诺；待办至少区分明确指向主人、主人承诺、社交线索。

## 8. 反馈与评价
分别报告总覆盖、可映射记录覆盖和不可映射原因；可确定映射记录目标 100%，其余保留待处理，不为追求 95% 伪造字段。
固定人工核对样本统计采纳/误提取/期限错误/证据可达；基线未建立前不声称质量提升。旧边界、scope 和权限测试必须全部通过。

## 9. 异常、扰动和降级
每批事务；中断恢复 cursor；失败记录不阻塞无关项但任务状态为部分完成。缺少 grant 或来源已撤销时拒绝召回，不能因为 legacy fallback 放宽授权。

## 10. 页面可观测性
诊断区展示迁移就绪、覆盖、回填进度/错误及继续/暂停入口；主界面优先业务查询与需核对项。将“未回填”“缺证据”“已确认”分别标明。
