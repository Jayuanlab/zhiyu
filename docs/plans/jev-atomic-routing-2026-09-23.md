# Jev 原子判断与可验证接入

## 目标与依据

仅修改桌面 Web 必要后端和评测链路。被控对象是回答前的资料来源选择及召回证据判断，不是用户权限或事实内容。依据官方 [Choice](https://docs.typesafe.ai/primitives/choice)、[Confidence](https://docs.typesafe.ai/confidence)、[工作流指南](https://docs.typesafe.ai/concepts/how-to-build-with-system-one)、[1.13 局限](https://docs.typesafe.ai/model-jaggedness/jev-1.13)。

## 输入、判断与控制

1. 端到端评测只发送原始用户问题。工具白名单留在请求配置，期望来源、金标准留在本地评分端，不通过额外问题字段伪装隔离。旧含提示评测保留，不能与新协议直接比较准确率。
2. 路由改为同一请求内四个独立 Noul：是否需要 architecture、records、knowledge、brain。每项明确边界，代码组合 sources；route 只作兼容的摘要，不再用 mixed 展开全部来源。
3. Noul 的值是该问题的 P(true)，没有 Choice confidence。使用独立版本化策略：>=0.8 选择，<=0.2 排除，中间任一来源不确定则整次回退原流程。该初始策略未经校准，不能沿用旧 Choice 0.65 的效果结论。纯知识库需求继续走既有工具流程。
4. 记录 schemaVersion、policyVersion、脱敏输入哈希、模型、各来源原始概率、选择来源、不确定来源、阈值、用量、耗时、降级原因。原始问题留在已有会话/评测记录，不重复写入路由事件；不保存凭证或提供商错误正文。事件进入现有 reasoning 流和 Brain routing 元数据，可与工具结果对应。
5. 充分性检查移除“全文全部问题”额外总判断及重复字段模型判断。显式问题按标点分段，允许调用方提供原子 requirements；不能把标点切分声称为语义分解。每项分别判断有无回答证据、是否有矛盾；代码合并并保留原始模型概率。字段缺失继续由现有结构化检查约束，时间比较不交给模型。无法可靠判断的复合问题仍是后续评测重点。

## 边界、恢复与用户可见性

保留 owner-bound 工具、denied 优先、2 秒路由截止时间、取消信号、异常回规则/正常工具流程。仅执行一次首次只读预取；自动补查仍关闭。来源选择不生成查询、不授权动作、不改写事实。主模型原有纠错工具与用户继续追问保留；现有工具轨迹展示读取来源和结果，reasoning 事件记录降级与决策，不新增页面。BRAIN_JEV_ROUTING=off 回滚路由，BRAIN_JEV_MODE=off 和 BRAIN_JEV_TARGETED_RETRY=false 维持。不得在没有证据时显示成功。

## 验证与反馈

针对性测试覆盖：评测答案提示隔离、多来源精确组合、全否、单项不确定、无权限/拒绝优先、畸形概率、取消/超时、用量/哈希可追溯、字段缺失不能被高概率覆盖、复合问题拆分和矛盾保留。真实 API 使用少量中文问题验证协议与降级，保存输入、原始结果及本地预期，预期不发给模型。不用这些样本调优阈值或宣称准确率提升。

新增离线路由评测入口读取纯问题与独立来源标签，报告接受率、已接受集合准确率、各来源漏选/误选、降级率、耗时及概率分桶；无独立标签的历史题仅作观察。后续独立校准集与保留测试集验证后才调整阈值。完整桌面问答与生产验收需另记真实执行证据，不把单测或 API 冒烟等同完整验收。

## 实施记录

2026-09-23 第一阶段代码完成：

- 评测请求构造独立为 `scripts/lib/pi-memory-eval-request.mjs`，输入协议 `raw-user-question.v2`，本地检查工具要求但不发送来源提示；记录输入构造器哈希。
- 路由协议 `recall-sources.v2`，策略 `noul-conservative.v1`。桌面预取按精确来源组合；Brain 同时需要 knowledge/brain 时可分别补充来源。完整概率和策略元数据沿现有事件持久化。
- 证据协议 `evidence-atomic.v2`，支持显式 requirements，分别保留回答支持和矛盾概率。`support=min(modelSupport,1-contradiction)` 是保守策略分数，不是联合概率；字段/截断约束保留。评测脚本改取所有要求的最小策略分数，不只看第一个问题。标点分段不是通用语义拆解；任意日期新鲜度判断尚未新增，不声称解决所有复合问题。
- 新增 `node --import tsx scripts/eval-jev-routing.mjs [--cases=path.json]`。案例格式为数组，每项含 id、question、可选 expectedSources；只将 question 送给模型。概率分桶含回退案例，来源错误只统计接受案例并明确分母。

验证：9 个针对性测试文件、78 项测试通过；全项目 `pnpm exec tsc --noEmit --incremental false --pretty false` 通过。测试覆盖既有 Brain service、query retry、platform recall 与新增输入隔离和概率审计。

真实官方 API 开发检查保留两轮，不挑选结果：

1. `.runtime/evals/jev-routing/2026-09-22T20-58-36-184Z/`：6 题、1 个明确判定、5 个不确定回退。发现泛化英文来源描述仍造成类别混淆。
2. 改用明确的中文业务边界后，`.runtime/evals/jev-routing/2026-09-22T20-59-17-168Z/`：同 6 题、4 个明确判定且集合符合预期、2 个不确定回退；无接口失败。阈值保持 0.8/0.2。两题分别为上传文档和混合需求。完整问题、概率、来源、耗时均留存。

这些是用于修订提示词的开发样本，不能算独立测试集，也不能宣称 100% 业务准确率或性能提升。后续优先验证混合需求和知识库/个人记忆区分，再用独立来源标注集评估召回率和弃权率。尚未重新执行完整 100 题桌面 HTTP 回测、浏览器和生产验收；未重启服务或修改本地环境开关。充分性和自动补查保持关闭。

## 第二阶段实施（2026-09-23）

- 新增 `answer-requirements.ts`：保留原问题作为主体上下文，分解明确问句及受限的记录字段清单。不能确认完整拆解的复合要求进入 `unresolved`，仍保留原句；模型高分不能把它变成已充分覆盖。该实现是保守的领域规则，不是通用语义解析器。
- 新增 `evidence-time.ts`：只接受带时区的有效时间，代码判断过期、未来、缺失元数据和历史时点不匹配。当前状态要求可信实时观测；记忆更新时间和刚查询到的旧快照不能替代它。历史状态需要有效版本区间，单个 `createdAt` 不充当历史版本。未解析的“当时”“评测快照”显式返回 unknown。
- `platformRecall` 结果及 Brain 重试轨迹始终提供子问题和时间检查，关闭 Jev 充分性服务时也可观测。证据协议更新为 `evidence-atomic.v3`；无时间合格证据的覆盖分上限 0.34，未拆解要求上限 0.64，不覆盖原始模型分数。暂按整个问题采用保守时间约束，混合不同时态的要求仍可能过度弃权。
- 纯个人记忆或知识内容问题交给原有内容检索工具，避免用平台快照/目录预取假装完成内容检索。多来源预取仍按准确来源组合，平台返回 `ok:false` 会显示为失败工具结果，保留部分证据并禁止自动扩大重试。
- 内容完整性离线成对实验明确关闭时间约束，只验证字段内容；不把语料采集时间伪造成历史有效区间。现有服务开关和运行阈值不变。

### 校准与验证

真实结果目录：`.runtime/evals/jev-routing/2026-09-22T23-34-39-546Z/`。原策略全体 48 题接受 20 题、回退 28 题，接受的来源集合均符合事先标签；验证组仅接受 8/24。候选阈值 0.75/0.2 在验证组仍接受 8/24，没有达到至少接受 10 题的试验门槛，`passesPilotGate=false`。因此保留运行阈值 0.8/0.2，不宣称校准成功，也不把已接受集合的正确率等同全量准确率。样本由 Agent 编写，未由人工核验，不代表生产分布；后续调优需另备未使用的验证集。

代码验证：11 个测试文件、90 项测试通过，覆盖旧快照伪装实时、关闭模型时的轨迹、复合要求遗漏、来源失败事件、纯内容检索回退及原有权限边界。最后补充记忆/原始观测的时间分类后，相关 3 个文件的 34 项测试再次通过。全项目类型检查通过；最终代码执行隔离 `ZHIYU_REVIEW_BUILD=95 pnpm exec next build --webpack` 成功（退出码 0，149 个静态页面），包含 TypeScript 检查。构建成功不等于真实业务运行验收。临时开发进程已停止，Next 自动添加的 94/95 类型目录配置已恢复，保留构建产物以便后续验收。
