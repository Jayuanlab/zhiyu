# 量化能力内置迁移方案

## 目标与现状

目标是让桌面 Web 项目启动后即可使用量化功能，无须另行运行或监控 8766 端口的 FastAPI 服务。量化仍是模拟实验环境，不接真实交易。当前 Web 已管理模拟盘的定时撮合与持久命令，但行情、自选池、历史恢复和账本命令仍通过本机 HTTP 调用 Python。Python 依赖 AkShare 等数据生态，直接重写行情和账本会扩大风险。

被控对象是行情采集、自选池配置及模拟盘账户。观测来自行情提供方、账户账本、命令回执和运行心跳；行情必须保留来源、采集时间、范围与降级警告。账户及命令事件保留在 PostgreSQL，原始历史恢复文件只读。

## 目标结构

Web 保留现有量化客户端入口，由主项目管理一个按需启动的本地 Python 执行进程。进程经标准输入和输出收发结构化请求，不监听端口。初期复用原 FastAPI 路由的校验、身份签名和业务实现，以降低账本迁移风险。后续可将纯业务逻辑从路由中提取，但不以重写为本次切换前提。Web 在运行时直接调用这一模块；启动脚本只检查 Python 环境和依赖，不启动量化服务。

控制动作包括自选池修改、模拟订单、撤单、撮合和历史恢复决定。现有 `denied` 优先的角色权限、主人身份签名、幂等命令 ID、数据库事务及恢复审核必须原样生效。传输失败的订单结果标为未知并通过同一命令 ID 查询或重试，不自动生成新订单。

## 切换顺序

1. 记录当前调用点、环境配置和账户读写路径；为传输层建立单一入口及隔离测试。
2. 加入本地进程传输，保留旧 HTTP 方式供已有隔离夹具使用。先验证只读行情和诊断，再验证签名账本读、订单幂等和调度撮合。
3. 将日常启动改为检查 Python 依赖；默认本地传输。更新错误提示和诊断页面，显示进程运行、失败详情、最近请求时间。异常时显式返回不可用，不以旧数据冒充实时数据。
4. 用隔离账户做端到端回测，比较现金、持仓、订单、成交和命令回执。确认重启、超时与进程退出后可恢复，随后才移除独立 HTTP 依赖。旧账户不自动审核或导入。

## 异常与用户控制

Python 缺失或依赖损坏时，量化入口给出明确错误及修复提示；行情采集失败保留提供方和降级说明；执行进程退出后可按需重建，未确认的写命令继续使用原命令 ID。用户仍在量化页审核恢复、查看账户和订单，在车间及 Loop 页暂停相应自动任务。停止 Web 后不留独立量化监听进程。

## 验收

- 日常启动不监听 8766，量化页面和车间读取可用；桌面浏览器刷新、缩放和键盘操作无回归。
- 账户、持仓、订单、成交在切换前后相同；重复提交同一命令不重复下单或成交。
- 签名错误、越权角色、旧行情和不可用数据源被显式拒绝或降级；`denied` 不被 `allowed` 覆盖。
- 进程退出、超时及主项目重启后有可见错误与恢复路径，命令结果不被伪造成成功。
- Python 隔离测试、Web 量化单测与隔离端到端测试通过；日常账户文件和数据库不由测试改写。

本方案只覆盖桌面 Web 和必要后端链路，不开展手机端专项优化。
