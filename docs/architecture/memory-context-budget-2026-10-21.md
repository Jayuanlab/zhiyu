# 完整安全约束与有界上下文预算治理

日期：2026-10-21。延续“通用核心 + 项目适配 + 业务策略”的分工，不改变知语的记忆分类、审核、权限或业务执行角色。

## 原因与控制目标

实际桌面查询“项目的约束与边界”选中 16 条约束，仅完整正文已有 12,771 UTF-8 字节；页面固定请求 8,192 字节，因此即使消除重复元数据也无法装下。旧字段 `maxTokens` 的真实单位一直是 `utf8_bytes_upper_bound`，不能把 8 KiB 误当成 8K 模型 token。

控制对象是本次 ContextPack 的序列化字节数与完整约束集合。观测来自同一次已授权、带固定版本的召回快照；测量包括引用、回执、问题和预算说明，不能只量正文。核心状态通过预算元数据、最终准入日志、读取回执与反馈事件保存。原始记忆、用途分类和生命周期不因预算治理而重写。

目标是在调用者明确给定的窗口内保留全部已选约束，优先保证理解可用，再装载证据摘录；不足时明确拒绝。这里“全部”指本次有界、授权且适用的选择，不宣称已遍历全项目所有约束。scope 不扩大，denied 始终优先于 allowed。

## 两种预算合同

旧请求不变：`{purpose:"recall",taskIntent,maxTokens:8192}`。它仍受 1–8 KiB 的原有校验，在完整约束放不下时返回 `memory_context_budget_insufficient`，不会隐式扩容。旧消费者和原来的出站窗口不因页面升级而改变。

新增显式协商请求：

```json
{
  "purpose": "recall",
  "taskIntent": "项目的约束与边界",
  "budget": { "preferredBytes": 8192, "ceilingBytes": 65536 }
}
```

preferredBytes 为 1–8 KiB，ceilingBytes 不低于 preferredBytes 且最多 64 KiB；必须同时填写，不得与 maxTokens 混用。未知字段、负数、小数、越界或互相矛盾的窗口在读取前拒绝。这个请求只协商 owner 预览 Pack，不增加候选、来源、权限或模型动作能力。

通用核心 `negotiateContextPack` 根据固定快照测量完整约束、有限问题和序列化元数据，加上调用方声明的最终审计/告知预留。首选窗口足够就不扩大；不足时按 1 KiB 粒度增长，并留少量辅助内容空间，严格受 ceiling 限制。预算元数据记录 preferredBytes、ceilingBytes 和保守 requiredBytes。知识/来源版本没有因打包改变。

所有约束保留原文和独立引用、回执；即使正文相同，也不合并来源不同的约束。已经标记为截断的约束不能作为完整约束通过打包。不能适配硬上限时返回 unavailable，附所需预算、上限和约束数量；不返回“部分安全上下文”。没有采用模型摘要、语义改写或切走约束的分页方案。

## 预算分配与最终使用

协商模式按“完整约束 → 显式当前状态 → 理解与经验 → 历史证据摘录”分配，避免重复证据挤掉可用理解。旧固定模式保持原有可选内容顺序。可选正文只能取 Unicode 完整码点构成的原文前缀，并保留固定引用和截断标识；问题列表仍有限量说明。未知来源不变成已核验来源。

最终准入仍重读当前版本、权限、适用性、期限和待审变更。若已选安全约束在最后核验中变化，协商模式返回 `memory_context_changed`，提示重新召回，而不是把剩余部分当成完整约束。最终 Pack 重新量取序列化字节，超出有效预算必须失败。网络/模型调用不进入该数据库事务；审计和精确读取失败不能退回旧成功快照。

真实模型使用继续受原有出站保护和消费者自身窗口限制；桌面 64 KiB 上限不是向每个模型下发 64K token 的授权。包体完整也不等于依赖覆盖完整、事实独立核实、模型已采用或业务动作成功。

## 桌面反馈与纠错

页面主动声明 8–64 KiB 预览范围，成功后展示完整约束数量、实际占用、有效预算及扩容原因。完整约束默认折叠，用户可以展开全文及每条版本/准入回执；折叠只影响展示，返回 Pack 中仍是全部原文。

辅助信息限量呈现单独说明，不把问题列表限量误写成约束正文裁剪。若超过硬上限、来源不可用或约束变更，明确展示对应失败，允许缩小任务或重新读取；不能以静默删除约束换取成功。用户仍通过已有记忆中心审核、纠错、查看回执与反馈，不新增平行管理入口。

反馈关联最终 contextLogId、固定选择和查询；重复点击沿用 feedbackId，不重复计数，不自动修改记忆、策略或审核。它只表示对召回的评价，不能作为模型或业务完成证明。

## 验证与回退

先保留实际 8 KiB 请求的失败证据；新增测试先失败，再验证显式协商保留所有约束。检查固定窗口拒绝、硬上限拒绝、Unicode 前缀、未修改输入、完整引用与回执、理解优先、截断约束拒绝、错误预算格式和最后版本变化。

真实 PG 验收沿用审核/修订、当前来源、依赖变化、撤权、过期、审计故障、出站与 SDK 的闭环，并增加协商后的完整约束与持久回执检查。G4/G5 独立项目验证通用核心没有被知语页面策略污染。实际桌面核对成功召回、展开、回执、反馈幂等、键盘、窗口缩放和控制台。

回退可恢复原页面和固定预算合同；不能回滚已记录的审计或反馈。保留上一套桌面生产构建，产物总计最多两套。最终结果、源码摘要和真实装载记录见 [验收记录](../verification/memory-context-budget-2026-10-21.md)。
