# Pi 唯一智能体执行器迁移

本次变更以 fadefe0 为基线，按用户“项目不再使用 Claude Agent SDK，所有功能实现都迁移到 Pi”的授权实施。控制对象是项目智能体的模型请求、工具动作和最终交付。只改变引擎及其适配层，不扩大角色权限和桌面 Web 的来源准入。

## 单一执行链路

- 唯一注册的引擎是 Pi。聊天、车间、车间 Loop、独立 Loop 和跨平台消息入口均使用同一个模型配置解析器。旧客户端显式请求 claude 返回错误；历史保存的引擎值按 Pi 选择，并保留 migratedFrom。
- 模型协议、地址、密钥和模型作为一个连接快照使用。支持 OpenAI Chat Completions、OpenAI Responses、Anthropic Messages；Anthropic 模型协议与已删除的 Claude Agent SDK 是不同层。
- Claude Agent SDK、平台二进制锁项、旧执行器、受控 SDK 代理和旧适配器已删除。业务工具不再导入 SDK 的 tool/createSdkMcpServer。退役检查同时扫描源代码、依赖清单和安装树。
- 保留独立 Anthropic HTTP SDK 与 sandbox-runtime 隔离工具库；它们不是 Agent SDK，也不创建 Claude 智能体。

## 功能与边界

Pi 负责 run、真实模型生成的 plan、消费主人批准方案的 execute、流式反馈和 stop。规划阶段不注册工具，返回 JSON 经过结构校验并由服务端生成标识；模型不能写入审批权或完成状态。来源校验入口执行方案时必须提供主人端的当前计划，不能凭内存计划 ID 恢复权限。

平台及车间业务工具保留原始处理器，改为宿主的中立工具定义，再转换成 Pi AgentTool。参数校验、denied 优先、明确空白名单拒绝、审核、租约、实际处理器错误和回执仍生效。车间工具在执行时重读当前能力配置；Task 子任务继承父任务的请求、工具和审批回调，只能使用受限只读工具，禁止递归委派和业务写入，并有时间与工具次数限制。TodoWrite 只维护本轮状态，不代表业务完成。

Skill 直接读取已安装的指引和有界引用，不再向 .claude 目录复制或同步。历史技能目录仅作为已有用户内容的导入来源。技能文字不授予工具权限。

MCP 通过独立官方协议客户端连接宿主配置的 stdio、Streamable HTTP 或 SSE 服务，只注册明确选中的完整工具名。子进程不继承模型密钥。远程写工具需要宿主审批回调。LSP 等外部能力由宿主明确注册工具或 MCP 服务提供，不能通过模型名称自动获得。

Pi 可由受信宿主注册本地文件工具、显式图像字节和独立隔离提供者的脚本/命令工具。沙箱必须显式选择已注册 provider、有审核回调和白名单，拒绝降级为宿主进程。**当前桌面聊天仍沿用来源与权限边界**：动态 MCP、沙箱、原始图像、任意文件路径和放宽权限的客户端请求需要独立宿主授权；文本/PDF/Word 与 RAG 走已注册来源。迁移不把此前被安全边界阻断的功能变成默认可用。

## 可观测闭环与恢复

每次物理模型请求都重新校验来源和租约，包括底层传输的再次派发；关闭 SDK 自动重试并拒绝重定向。失效先中止，后续请求不能绕过。模型解释、工具动作及业务回执继续分层；既有运行、来源、预算、方案审批和结果审计事件保留，不把模型终止当业务完成。

外部 MCP、沙箱资源关闭后才发布完成终态。资源清理失败明确失败。跨平台入口只交付通过 completed + cleanup completed + done 确认的最终候选，草稿、缺失终态和失败清理不能发送为成功答复；长回复分块保留。会话准备阶段也占用会话标识，重复请求不能覆盖取消目标。

用户仍从配置中心检查实际连接与修订，从原有方案审核、车间/Loop 状态和事件入口审核、暂停和纠错。配置不可解密、用途禁用、权限查询失败、模型失败和清理失败均保留可见错误，不静默选另一引擎。

## 验证与回退

实际验收结果记录在 pi-only-validation.json。单元回归覆盖当前 Pi Harness、工具、审批、计划来源、租约与来源校验、工作记忆和最终交付；真实 PostgreSQL 与本地 HTTP 夹具验证物理派发和三协议；生产构建及隔离配置中心 HTTP 检查另行留证。没有真实模型密钥时，不能把本地协议模拟成功当成真实供应商业务成功。

旧 SDK 专用测试由 Pi 对应契约测试取代；原测试源码保留于 Git 基线和本地退役备份，历史验收收据不改写为当前结果。开发验证失败日志保留，包括测试边界 mock 更新、隔离夹具环境补齐和一次中断的构建；最终仅以最终验收日志为准。

回退点是 codex/before-pi-only（fadefe0）、.runtime/zhiyu4-before-pi-only.dump和本机环境备份。构建产物遵守仓库保留策略，回退应从 Git 基线按原锁文件恢复依赖并重新构建，不假定旧构建仍在。本次没有数据库结构迁移。若出现真实业务回归，先停止当前 Worker 和 Web，保留事件与运行证据，再回到已知版本。运行期间产生的新业务数据不能用旧备份盲目覆盖。
