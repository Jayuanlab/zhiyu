# 对话指挥长期智能体车间闭环设计

主人通过普通对话指挥长期留存的车间：找到合适的智能体，交办工作，补充资料，调整本轮或长期要求，获取结果，验收与返工，暂停及恢复持续任务。对话页只呈现文字和普通链接；工作卡、进度面板、详细证据和管理操作集中在车间页。

现有 [26 项接口契约](workshop-agent-operation-interface.md)提供观察与控制动作。要完成上述过程，还必须实现宿主的对象关联、授权绑定、事项状态、输入交接和异步结果投递。接口 schema 通过不能证明这些链路已经闭合。

2026 年 10 月 9 日首批代码实现与测试记录见[实现验收](../verification/workshop-chat-control-implementation-2026-10-09.md)，实际可调用的有限工具见[运行契约](../contracts/workshop-chat-control.runtime.v1.json)。下文仍是完整分阶段设计，不表示全部接口、阶段或生产装载已经完成。

本设计根据 2026 年 10 月 9 日工作区源码与契约审查修订。代码证据说明现有路径和静态风险；没有据此宣称生产已复现、配置凭证已泄漏或候选方案已装载。`workshop-agent-operation.v1` 的 26 项 JSON 契约保持原样；下文扩展是待编入后续契约版本的设计要求，不能直接向 v1 传入新增字段。

## 控制目标与范围

控制目标是让主人在同一对话中完成“交办—执行—回报—纠偏—验收—继续”，并能在下一次对话中找到同一个长期智能体及其工作。Work 的身份、职责和权限保持稳定；任务、运行、指令及产物各有明确关联和生命周期。

范围限于桌面 Web 和必要后端，复用 `work-runtime.v2`、命令账本、租约、运行、Loop、审核和协作。新增必要的持久关系与状态投影，不新建另一套任务执行器，不把主对话智能体变成所有领域工作的执行者。发起对话结束不结束业务任务，后台报告抵达也不自动触发新业务动作。

用户明确且符合权限的命令直接受理。目标、范围或待审对象有歧义时，只用普通对话补充必要信息。具体审核决定也可在对话中作出，由宿主绑定到已展示的对象与版本；车间审核页用于查看详细证据和人工接管，不增加重复按钮确认。

## 被控对象与控制范围

| 对象 | 稳定标识与控制范围 | 不得混淆的事实 |
|---|---|---|
| Work | 长期身份、使命、配置版本、能力与权限。 | 修改一次任务不自动修改使命。 |
| 工作事项 | 宿主签发 workItemRef，关联目标、验收、修订和所有尝试。 | run completed 不代表事项被主人接受。 |
| Run | 一次执行，绑定事项版本、输入与有效要求快照。 | 取消本轮不自动取消持续排期。 |
| Loop | 排期、触发、有效执行窗口、错过策略。 | 暂停调度不自动停止已运行进程。 |
| 长期要求 | Work、事项或 Loop 范围；版本、有效期与状态。 | 本轮采用不能替代长期要求仍有效的证明。 |
| 产物、审核和协作 | 各自的精确引用、版本、来源及授权。 | 查看、交付、验收与外部发送分别记录。 |

“本轮、本周、以后、每周、直到某日”必须解析为结构化范围。“本周”绑定具体事项或明确的有效时间，不能泛化为当前 run 或永久要求。“以后”区分长期要求与使命修改。未指明暂停范围的“停一下”，在多对象场景用一句普通文字澄清。

## 观测输入与新鲜度

控制前读取当前 Work/Loop 状态、命令版本、目标事项与 run、租约心跳、阻塞对象、输入 hash、审核版本、工具实际装载及来源 grant。控制后回读同一对象和原命令回执。记录 observedAt、版本、provider、完整性与降级原因；缓存正文和模型总结不作为写动作基线。

主任务、必需输入、验收标准和有效边界属于不可裁剪上下文。预算不足时裁剪辅助历史、分段读取或返回 needs_input/budget_exceeded。不能静默删除主指令后按默认使命运行。安全检查点采用新指令时读取独立增量快照，保留原快照与采用事件。

发现 `unique` 必须基于当前授权范围内的完整匹配判定；翻页覆盖不足时保持未决。精确 ID、用户明确名称、时间、产物及后台已确认关联共同定位。改名不改变 Work 身份；删除、归档、版本变化和 grant 失效须重新校验。环境浏览器 URL 不建立控制目标或授权。

## 持久状态与数据模型

以下是宿主内部记录，身份、授权和命令键均不由模型提供。可映射既有表、事件 metadata 和索引；必要的新记录必须持久化，不能只存在浏览器缓存或 prompt。

| 记录 | 最小内容 | 更新规则 |
|---|---|---|
| ChatControlContext | owner/chat、revision、明确目标与候选、workItemRef/runId/artifactRef、最近已核验命令、待审引用、来源消息及事件。 | 主人明确选择或已核验交办更新指向；后台迟到报告不能切换当前指向。 |
| OwnerCommandPlan | 原主人消息、意图 ID、目标、动作清单、范围、内容 hash、依赖、授权依据和失效条件。 | 原消息与首个已绑定计划保留；新的语义变更另立修订。 |
| ControlStepAttempt | stepId、attemptId、commandId、目标基线、payload hash、状态、结果与旧尝试关联。 | 同尝试只回读；失败后的新尝试由宿主验证条件后建立。 |
| WorkItemProjection | workItemRef、来源指令/周期/协作、目标、验收、revision、输入、关联 run、阶段、阻塞原因与主人决定。 | 使用既有 Runtime 执行；事项状态从事件投影并保存主人决定，不由模型自行结案。 |
| StandingRequirement | directiveRef、作用对象、revision、validFrom/validUntil、active/superseded/retracted/expired、替代链与来源。 | 替换与旧要求停用原子提交；每轮采用另写 Adoption 事件。 |
| ChatDelivery | 原 chat/用户消息/事项/run/事件、投递去重键、稳定 messageId、正文版本、pending/delivered/blocked/failed 和重试信息。 | 接收方固定为原获准对话；投递重试不触发业务重试。 |
| InputArtifactBinding | 原始对象、hash、格式、提取完整性、目标 grant、寿命及 staged/used/failed 回执。 | 临时输入不自动变成常驻资料或记忆；后续复用重新核验。 |

新对话只根据主人明确条件检索其有权访问的历史工作，建立本对话关联。没有明确对象的“它”不继承另一聊天的最后目标。刷新或切回聊天按服务器 revision 同步，而不是因本地存在缓存就跳过回读。长对话用分页近期历史与精确来源消息定位，避免前 1000 条成为授权或工作关联的限制。

## 宿主模块与调用链路

```text
主人普通文字
  → 对话智能体提出意图与候选参数
  → Control Host 解析对象、范围、版本与授权
  → 保存有限步骤计划，装载本步骤的具名工具
  → Adapter 调用既有 Work Runtime
  → 命令、输入、执行与结果事件
  → 事项与采用状态投影 / ChatDelivery
  → 原对话收到结果文字，车间页回读同一对象
  → 主人继续、纠偏或验收，形成下一次有来源的控制
```

Control Host 是一个深 Module，集中承担目标解析、引用核验、版本、授权、子步骤幂等与回读。模型继续使用已登记的具名 Interface；Adapter 只绑定实际实现过的有限 handler。宿主内部提供解析、准备、受理和观察四类职责，不接受模型指定身份、执行器、handler 或批准状态。

发现后绑定流程必须落地：发现候选 → 获取唯一选择 → 观察当前条件 → 保存具体步骤计划 → 宿主安装对应 Adapter → 下一次模型调用执行该步骤。原主人指令已经明确覆盖的目标和动作不重复确认；新目标、长期范围或正文变化重新核验。工具无法在当前 provider 装载时返回具体 not_loaded/not_implemented，保留意图并停止执行，不把检索说明当作可调用权限。

主对话智能体负责协调和解释；车间负责自身领域执行；worker 负责租约与执行；结果投递器只负责内部文字回传。车间角色、资料 grant、denied、有效审核与运行权限共同约束动作。普通对话的主人命令不会把另一车间的控制目标并入当前车间。

## 必要的接口扩展

保持原 26 项为 v1 基础，不用一个接受自由动作名和参数的通用执行工具代替具名控制。下一契约版本需要以下有限扩展；在 schema、Adapter 和宿主绑定完成前，工具目录必须标记不可调用。

| Interface | 候选扩展 | 生命周期要求 |
|---|---|---|
| discoverWorkshops / describeWorkshop | 完整候选判定依据、读取覆盖、实际输入输出契约、支持控制与接纳策略。 | 声明能力不替代已核验接单资格。 |
| observeWorkshop | work_items/work_item/directive 视图；精确 workItemRef/directiveRef；事项状态及采用证据。 | 引用按 owner、Work、事项版本和 grant 解析。 |
| assignWorkshopTask | create/continue/rework；原 workItemRef 与 expectedWorkItemRevision；选择的 continuationRef；是否只保存要求；有界执行参数。 | 默认新事项；补充与返工必须绑定旧事项，不能静默另造无关联任务。 |
| 新增 manageWorkshopDirective | replace/retract、精确 directiveRef 与 revision、替代内容和作用范围、有效期。 | 仅改变已授权要求，不扩使命、工具权限或审核标准；旧新切换可追溯。 |
| 新增 decideWorkshopWorkItem | accept/request_changes/cancel、workItemRef、revision、具体产物与结果 hash、理由。 | 主人接受与程序验收分别记录；在执行事项先呈 cancel_requested，停止与效果核验完成后才结案。 |
| proposeWorkshopLoop / setWorkshopLoopStatus | 执行窗口、错过策略、恢复时积压选择及预览。 | 仅重启明确的计划与获准积压，claim 前重新核验新鲜度。 |
| 所有观察与写回执 | 控制计划/步骤引用、工作关联和可回读对象；异步投递由宿主记录。 | 不暴露内部授权凭证；重复请求回到同一步骤。 |

有界参数只允许在平台与车间现有上限内缩小时间、工具调用或结果规模；不能通过“灵活控制”扩大权限。实际执行器须硬校验支持的限制，未支持的限制返回具体缺口，不能只写进 prompt。持续任务的内部汇报目的地与汇报频率由主人要求绑定，不复用外部发送权限。

## 事项与长期要求的闭环

事项阶段建议为 queued、running、needs_input、awaiting_acceptance、rework、accepted、cancel_requested、cancelled、failed；这是业务投影，原 Run 状态仍按既有 Runtime 保存。澄清轮完成只结束该次运行，事项保留 needs_input。主人回答后用同一事项的新修订交给已获准的后续运行。

产物生成后按原验收标准独立验证。程序通过可进入 awaiting_acceptance；主人明确接受具体产物后才记录 owner_acceptance。请求修改关联原事项与结果，保存旧产物，产生返工尝试。未满足的事实、输入缺口和部分交付保留，不能由模型自评分结案。

长期要求创建、替换、撤销和到期各写事件。运行采用时固定要求版本并记录阶段；撤销后未产生的新动作须重新核验，有效期结束不能继续领取依赖该要求的任务。当前执行受不可逆动作和安全检查点约束，不能承诺历史动作回滚。当前轮指令另设采用截止阶段与 waiting/adopted/too_late/expired 终态；未采用时保留明确后续事项，不无限等待。

## 暂停、取消、恢复与并发

“暂停后续、当前继续”只建立指定 Work 或 Loop 的接纳/领取屏障。“当前与后续都停”先确认屏障，再取消精确运行，再核对执行器与效果；屏障建立失败时不能承诺后续已停。旧 queued 任务仍单独列出，禁止因恢复 active 就无条件消费全部积压。

当前 Work 按既有租约串行，声明 maxConcurrentRuns=1。明确 reject/queue 接纳策略、阻塞运行和等待状态；只允许有实际消费者及有效输入的队列。每个 queued 事项保持自己的主指令、验收、资料和要求版本；不能把多个任务合并到同一自由 prompt。优先级变化也须有明确事项和版本，不假装能抢占正在执行的工具。

Loop 在领取时再次检查 scheduledAt、执行窗口及 skip/coalesce_latest/owner_approved_catch_up 等明确策略。过期任务留下 skipped 回执。恢复排期前用文字说明积压处理方案；涉及新的补跑动作时按主人命令或已批准策略办理。

复合命令记录所有步骤、依赖与各自结果，不宣称跨外部动作的原子事务。传输断线、浏览器刷新和“继续生成回复”复用原主人消息、plan、step 与 attempt，不能插入一条新“继续”作为业务重试授权。原尝试已经成功或效果未知只能回读；宿主证实原尝试终结且未执行后，才可在原意图下生成关联的新尝试，重新校验当前对象及授权是否仍适用。expectedVersion 更新不是覆盖原 payload 的理由。

## 原对话的文字反馈与结果投递

受理时持久化原 chat、来源用户消息、plan/step、workItemRef 和实际 runId。运行终态事务或具备持久游标的事件消费生成 ChatDelivery；业务完成与通知完成分开。投递使用稳定 messageId 和唯一事件键，向原对话幂等追加普通 assistant 文字，保留来源引用。不得覆盖用户原话，也不得冒充主人授权消息。

浏览器关闭、切页或刷新不停止投递。在线传输仅用于及时展示，离线重新进入按 revision/游标补收。若 chat 删除、归属变化或授权失效，阻止投递并在车间记录原因；不把结果送到用户当时另一个活动聊天。通知失败重试通知本身，绝不重跑车间。迟到报告不得替换本对话当前工作指向。

默认只回报交办受理、需要主人输入、终态结果和重要异常；进度由主人询问时以文字回答。持续 Loop 的汇报对象与频率需明确，只汇总需要反馈的变化，不逐个心跳刷聊天。完整报告可按用户要求分段呈现或提供普通安全链接。运行文本、文件或工具输出中的“继续”“批准”等不构成新的控制命令。

例如，预期交互为：“已交给强化学习学习者处理本周研究；这条要求只作用于本周。”之后同一对话收到：“研究已完成，报告还有两项数据缺口；完整报告可在车间查看。”若进入澄清，则先说明缺少哪项输入，主人回答后继续原事项，不宣称报告已完成。

## 输入、产物、协作与人工接管

聊天附件、知识文档和运行产物统一经宿主映射为目标范围内 inputRef。映射包含原始对象、内容 hash、实际可读格式、提取完整性、暂存寿命与 grant。仅有截断摘要时明确 partial；需要完整文件却未暂存成功时不启动依赖该文件的执行。补做重新核验原版本，不把文件名或正文绝对路径当授权。

结果读取复用现有产物下载的 owner、Work、run/event、realpath 与 SHA 检查。cursor、hash、offset 和已读范围绑定同一对象；替换、跨 run、跨主人、路径穿越或授权失效均拒绝。模型读到报告尾部才可声称已完整读取。空结果、解析失败、预算不足和来源过期分别解释，不能用摘要伪装完整正文。

协作保存原对话→原事项→请求→实际接收 run→答复产物→验收→综合结果。创建请求不代表对方已执行；reply 不代表 verify；接收轮完成却无答复仍是缺口。主人给既有请求投递、补资料、取消及验收都关联原请求。共享的是明确获准的资料与产物引用，不能转移整个车间权限；取消请求不替代取消接收运行。

主人可在普通对话中阅读具体差异、作决定、暂停及纠错；需要详查时打开对应车间对象。决定绑定 reviewRef、目标版本及内容 hash，文本“同意”必须有唯一且仍有效的待审对象；多个审核项先文字澄清。保留强制领域审核和 denied，不依靠口头扩大权限。模型可见 inspection、旧降级入口、错误与嵌套配置一并使用字段白名单和脱敏。

## 验收场景与反馈指标

以下是待实现后的验收要求，本次审查未运行这些业务场景。先使用隔离数据与可记录执行器，再做必要的桌面生产验收。

| 编号 | 场景 | 必须满足的事实 |
|---|---|---|
| C01 | 明确名字交办一次研究。 | 唯一 Work、原用户消息、命令、事项和实际 run 完整关联；受理不冒充完成。 |
| C02 | 跨页有两个同名或同能力车间。 | 不从首屏单项推出 unique；普通文字澄清，未选前零写动作。 |
| C03 | 超过 1000 条消息、刷新或进程重启后说“继续”。 | 定位原事项和版本，不依赖前 1000 条全文。 |
| C04 | 先审 A、后交办 B，再说“它”。 | 指向经核验的 B；有冲突时不执行 A。 |
| C05 | 新聊天有明确名字与时间，或仅说“它”。 | 前者授权检索并重建关联，后者不继承另一聊天写目标。 |
| C06 | 关闭页面后完成；重复投递或投递器重启。 | 原对话出现一次结果，业务运行数量不增加。 |
| C07 | 切到另一聊天、原 chat 删除、通知失败。 | 无串聊天投递；保留阻塞原因，业务结果可回读。 |
| C08 | 本周要求和永久要求写在同一句。 | 分成独立范围；临时要求到期，长期要求版本可查。 |
| C09 | 替换、撤销长期要求并恢复旧运行。 | 不让旧新冲突要求同时生效；恢复原快照如实说明。 |
| C10 | 当前轮迟到纠偏或执行器未采用。 | waiting/adopted/too_late 有证据；不能只凭 stored 宣称生效。 |
| C11a | 澄清轮完成，主人补充所需输入。 | 原事项继续，不误结案、不丢输入与目标关联。 |
| C11b | 主人验收不通过，再要求返工。 | 原事项新修订保留验收条件、旧产物和返工尝试。 |
| C12 | 超过 50 条 active 指令和多个 queued 任务。 | 每项主指令精确读取；缺失时阻止执行，不退回使命。 |
| C13 | 当前 A 运行、B 排队，命令要求都停。 | 先暂停屏障，再取消 A；B 在中间不被领取。 |
| C14 | 暂停后恢复有过时 Loop 队列。 | 明确 skip/合并/获准补跑，claim 前核验有效窗口。 |
| C15 | 受理后响应丢失、复合命令部分成功。 | 重放同 plan/step；已成功部分不重做，逐项文字反馈。 |
| C16 | 版本冲突后重试、效果未知后重试。 | 新尝试仅在证实原尝试无动作且授权有效时建立；unknown 只核对。 |
| C17 | 附件同名、只提取摘要、跨日补做。 | 原对象/hash/完整性可核验；不把摘要说成读完原文件。 |
| C18 | 关键内容放长报告尾部，续读时替换文件或跨 run。 | 能按范围完整读取；变更、穿越或跨范围拒绝。 |
| C19 | 资料 grant 撤销、含提示注入的文件、伪造批准。 | denied 优先，零越权动作；回执说明具体拒绝原因。 |
| C20 | 含内联 key 的构造配置，调用新旧 inspection。 | 原值不进入模型、工具输出、错误或聊天消息。 |
| C21 | 协作创建无投递、接收完成无答复、reply 未验收。 | 不报完成；真实阶段、缺口和原事项关联可查。 |
| C22 | 新旧聊天消息、刷新及未确认提交。 | 对话无工作卡和控制按钮；文字回执与车间同一命令。 |
| C23 | 限时、工具预算、过期输入与 provider 降级。 | 实际执行器遵守支持的硬限制；说明部分产物与停止原因。 |
| C24 | 一句“同意”对应两个审核，或内容被修改。 | 不猜目标、不复用过期批准；有效已有批准不重复确认。 |

硬性验收为零越权、零重复副作用、零错误目标、零虚假完成；模型准确率不能抵消硬性失败。另记录目标定位、范围识别、结果投递成功与延迟、采用确认、事项续办、主人验收和恢复结果。测试同时核对持久回执、运行数量及产物，不能只检查回复用词。异常反馈按观测、状态、规划、执行、治理分别定位，不把所有失败改成追加 prompt。

## 分阶段交付与停止条件

第一阶段先完成最小闭环：发现与安全 inspection、后台具体关联、主人命令绑定、交办与必要输入交接、原回执回读、异步文字回传、结果续读和原事项补充。开放写动作前解决 P0 的停止竞态、主输入完整性和配置脱敏；旧聊天卡的回执迁入后台，普通对话不再依赖卡轮询。验收 C01 至 C07、C11a、C12、C13、C15、C17 至 C20、C22。C13 先验证底层屏障与取消的安全顺序，第二阶段再贯通完整自然语言组合控制。

第二阶段完成日常灵活控制：长期要求替换/撤销/到期、纠偏采用截止、暂停取消组合、安全新尝试、主人验收与返工、排期恢复与积压处理。完成对应 schema 与 Adapter 后，才扩大真实可调用工具集，验收 C08 至 C10、C11b、C12 至 C16、C23、C24。

第三阶段贯通配置、记忆、创建删除及协作的完整对话控制，保留各领域既有审核。协作最终以 C21 验收，配置和记忆另做真实保存、装载及业务效果核验。

每阶段以固定场景、相同输入与预算验收，记录功能和桌面实际使用效果；通过后冻结范围再进入下一阶段。未实现的原地恢复、输入转换、实时采用或 provider 绑定保持 unavailable，不用新运行假冒原地恢复。保存失败证据和适用条件，必要时退回已验证 Adapter 与文字受理路径；不得删除历史回执或回滚已经发生的外部效果。本次交付为设计修订，不进行生产部署或真实业务运行。
