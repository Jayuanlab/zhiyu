# 智能体空间中的临时对话

## 目标与边界

每个 Work 的工作桌提供同一个对话入口。主人临时交代任务、补充信息或追问结果，回复和交付物回到该空间。Work 的长期职责与权限继续生效。

常驻资料仍用于长期上下文；临时文件不登记到 `workshop_sources`。移除文档清洗专用上传入口及工作桌的“追加方向”输入。长期配置继续在管理区修改。

“临时”指用途和上下文范围：对话、运行及核验回执仍持久保存，用于刷新恢复和审计；不承诺无磁盘副本或零记录。临时内容不自动转为记忆、Brain 状态快照、Loop、唤醒或发信草稿。

## 受控对象与状态

- 受控对象是当前 Work 的一次执行；每条用户消息对应一个 `workshop_runs`，触发类型为 `conversation`。
- 原始观测：主人消息、明确引用的绝对路径；只接受运行机器能访问的文件，不递归扫描目录。
- 结构化状态：`triggerReason` 保存消息、显式路径、父运行编号；运行状态和事件保存排队、执行、取消、失败及产物证据。
- 回执分层：路径出现不代表读取；`staged` 表示已读入本轮副本并核验 SHA-256；`used` 需要实际工具消费回执；`failed` 显示读取或处理错误。
- 产物遵循通用 `WorkPresentationV1`，复用带鉴权及哈希核验的预览接口。

## 输入与执行

`POST /api/workshops/:id/conversation` 通过现有命令账本和 `startWorkRun` 入队。命令 UUID 支持断网重试，事务内验证 Work 处于 active。父对话必须属于同一用户的同一 Work；命令重试恢复原来的运行。

单轮最多 12000 字、20 个绝对文件路径。Windows、POSIX、file URI 均可识别；含空格路径使用引号或反引号。路径是本轮输入引用，运行时复制到该运行 inputs 目录，不修改原文件。单文件上限沿用现有 100 MiB 边界，不支持的格式和空内容由转换器明确报错。

追问在真正执行时读取所选父链，最多 8 个祖先、20 个文件，超限要求发起新任务。新消息明确引用文件时替换本轮输入；未引用文件时沿父链继承最近一条消息的文件。新任务不继承旧文件。仅临时输入进入本次处理清单，常驻资料只提供参考上下文。历史指令不再次执行。

同 Work 使用既有执行租约串行消费队列；原有角色及工具拒绝项始终生效。临时对话的持久化记忆、持续任务及通知工具额外禁用，结构化输出也有相同限制。普通运行上下文过滤临时对话事件，防止它们变成未来的默认指令。

## 老板可见反馈与人工接管

工作桌显示用户消息、真实运行状态、路径回执、Markdown 回复和产物。支持“接着交代”“新任务”“停止本次”与打开具体运行记录。读取失败显示最后核对时间，旧状态不会冒充最新状态；活跃运行自动刷新。

浏览器按用户和 Work 保存尚未确认的提交及命令编号。超时后核对原请求，避免重复任务。暂停或归档时禁止新提交，仍能核对已接受请求。停止结果不确定时保留取消请求编号。

异常路径包括：跨 Work 父链、循环父链、输入超限、文件缺失、文件变化、模型/工具失败、执行租约丢失及部分动作待核查。错误保留在原轮对话；主人可纠正后继续或另起任务。失败/停止优先于智能体自述成功。

## 验证

定向测试覆盖：鉴权与归属、暂停边界、同命令重试、父链隔离、路径解析、跨运行输入拒绝、读取/消费状态、无源普通问答、清洗回执、跳过记忆/唤醒/快照、原指令流程回归。实际验收用合成中文文档，检查发送、刷新恢复、追问、新任务和 Markdown 预览，并核对常驻资料数量不变。

本次只改桌面 Web 及必要后端。Pi 本地 shell 沿用既有授权边界；本功能没有新增操作系统代码沙盒，也没有声称文件暂存等于沙盒隔离。
