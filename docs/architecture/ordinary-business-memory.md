# 普通业务的工作记忆与 Loop 检查点

本方案控制的是同一个 Work 内持续执行的任务。记忆承担“上轮做到了哪里、哪些问题还没证实”的状态估计，不直接授予动作权限，也不把模型笔记变成已确认事实。生产效果以独立的验证记录为准。

## 保存与继承

| 层次 | 保存内容 | 下一轮如何使用 |
|---|---|---|
| 原始观测 | 工具结果、来源事件、网页原文快照和正文窗口 | 作为可追溯的依据；续读同一快照，不偷偷重新抓取 |
| 当前工作笔记 | `workingMemory` 接受的 LOG 更新、版本、来源目录和原文投影回执 | 合格成功轮次在同一 Work/Loop 内按权限、策略、来源和时效接续；仍标记为未经核验 |
| 业务检查点 | 报告的完整 `checkpoint` 及宿主保存回执 | 仅提取下一轮问题、待核验项、复查条件和时间窗；不继承事实断言和执行动作 |
| Brain 长期记忆 | 单独写入的版本化候选记忆及审核记录 | 经过既有审核、状态、权限和时效检查后召回；工作笔记不自动晋升 |

普通 Pi Work 只要有合格的只读观测工具，就可以获得内部 `workingMemory`，不再要求绑定论文验收合同。关闭、拒绝、需审核、无合格读取工具和无效策略配置仍会阻止准入。调用使用本来的工具与时间预算，没有无限追加的记忆整理轮次。

模型先读取目录和当前版本，再按任务需要保存 LOG；不要求每轮压缩正文，也不以“调用过工具”代替保存成功。原始记录、笔记、报告和执行结果分别留存。报告中的“已保存”只有在实际回执存在时才成立。

常规工作流程还需要区分两种留存职责：长期候选用于送审认知增量，LOG 用于本任务的实际进度。在策略允许的阶段，有新增观测、纠错、未决问题或下一步变化时，先读取目录和版本，保存简短 LOG 后再写长报告或进入下一阶段；失败明确披露。无变化时允许不写，不为凑轮次制造记录或新增无关取证。这是持续生效的通用流程，具体业务命令不附验收提示，也不另加每轮必写 LOG 的业务通过条件。是否稳定仍须核对真实回执及后续输入。

保存请求省略 `pruneToolCallIds` 与提交空数组含义一致：不移除任何原文正文。笔记的最终引用必须绑定到实际目录中的 `toolCallId`，任意事件编号或未观察的源码哈希不能充当依据。字段错误与未知来源会给出可修正的反馈，失败请求不会增加笔记版本或冒充保存回执。

2026-10-19 的接口修复允许有界、无控制字符的中文笔记键，与公布的字符串 schema 一致。引用优先使用 `toolCallId`；若模型提交本轮目录中已经出现的 `evidenceId`、`sourceEventId` 或源码 `sha256`，宿主先精确绑定到当前获准读取回执，再保存规范工具编号。相同不可变来源的多个读取窗口可共同绑定；来源身份不同、冲突、读取失败、目录不可见或越界时拒绝，不根据摘要猜测来源。模型自己写出的普通观察事件不因此成为读取证据。原始调用参数与规范化后的保存事件都保留，可逐项追溯。

业务检查点在受执行租约保护的完成事务中写入事件和 Loop 状态，保留当前轮、Work、Loop、内容校验值及七天有效期。加载时必须查到同一范围的原始保存事件，且状态与事件内容一致；继承不会延长有效期。过期、跨范围、回执缺失或内容不一致时，数据库审计仍保留，模型输入跳过该检查点并记录原因。

业务未通过的轮次可以保存待核验问题，但明确保留未通过状态，不能据此继续传播未经核验的结论。当前主人指令、当前 Brain 修订和当前权限始终优先。

## 来源与网页续读

研究任务默认优先直接读取公开来源并保存原文。最多跟随三次跳转，每跳重新检查公开地址，拒绝循环、缺失目的地址及 HTTPS 降级，整段共享读取时限。最终地址与实际响应目的地址一致，才标记 `finalUrlVerified`；这只表示目的地址经过核对，不表示文章内容、提取结果或模型判断已经证实。

直接读取失败时可以使用原有代理回退，但保留 provider、失败详情、警告和“最终地址未经独立核验”状态。代理正文不能借另一次请求冒充已经验证。

返回值提供完整的 `nextRead` 参数。续读可以仅提交同一 Work 的 `evidenceId` 和偏移，宿主从已保存快照恢复 URL，核对正文和原文校验值；不存在或跨范围时显式失败，不以重新抓取掩盖证据身份变化。定向搜索的域名与日期参数进入实际搜索查询。

源码 `Read` 也返回当前实际 `citation`（路径、原始字节 SHA-256、展示的起止行）、`nextOffset` 和完整 `nextRead`。文件总行数不是已读取覆盖范围；行数按物理行计算，末尾分隔符不增加虚拟行，真实空行保留。引用仍须覆盖实际展示行，不能自动补齐未读内容。单行超过字节预算时明确告警，不提供原地重试的续读参数；源码权限和秘密排除保持原边界。

## 校验、恢复与用户控制

报告解析按 JSON 字符串与对象边界处理，正文内的 Markdown 代码块不会提前截断结构化输出。应为对象或数组的业务字段不再由报告散文自动填充。提交前执行原有业务证据检查，在有限预算内返回具体错误；来源不足时如实报告降级，不能改成“充分”来通过。

普通研究交付最多两次字段或证据修正，共享最多四次追加模型转发，仍在本轮原有总时限和工具次数内；修正令牌另有固定上限并写预算事件。最后一次转发移除工具并显式发送 `toolChoice=none`，专门保留给最终报告。若提供方仍发出工具调用，或报告仍不符合原标准，继续显式失败，不把部分输出包装成通过。

自由研究报告的正文只在 `reportMarkdown` 中交付一次，保留原论证要求，不再在 JSON 外复制。普通长报告的修正总上限由 32768 调整为固定 65536 token，至多四次转发各预留最多 16384 token，不因工具输出较短而退还额度或重新授予预算。受专门交付合同保护的原短任务配置不变；物理请求、工具次数与整轮时限不扩大。该调整可能增加实际模型成本，费用与请求需单独记录。

宿主按 SDK 上下文估算，在取证空间触及模型窗口减去报告额度及 32768 token 读取余量时，关闭进一步大篇幅取证。最多两个后续请求保留当前已获准的工作笔记与工作日志工具，并允许一次原有 `webSearch`：必须 `limit=1` 且含 `site:domain`，用于补齐定向搜索，不能继续读网页。随后只交付报告；工具执行层核对最终实际参数、次数和名单。原始消息、工具配对、主人规则和来源警告均不删除，也不自动批准 Brain 候选。无法留下至少 4096 token 的完整答复空间时显式失败，不发送只剩一个 token 的报告请求。完整运行仍服从原工具、请求与时间上限。此保护旨在防止上下文耗尽，不能保证任意长度的正文都能完成，也不把缺证据改成充分。

为补足普通任务中模型漏调 LOG 的留存缺口，原业务校验通过后，在工作记忆策略为 `apply` 且本轮仍为版本零时，宿主可以提交正常报告 `checkpoint` 中已有的待办问题。只取有界 `nextQuestions/openQuestions` 和 `pendingVerification`，不生成事实、假设、行动或来源；没有检查点或问题就不写，模型已经编辑的笔记也不覆盖。提交仍经过租约、权限和工具预算检查，审计落盘失败会阻止成功交付。

这类事件明确标注 `commitOrigin=validated_report_checkpoint`，同时记录原报告 SHA-256 和检查点 SHA-256。它是宿主提交模型写出的进度，不是模型主动调用工具，不产生伪造 `tool_use`，也不等于当轮模型已经使用该状态。生产验收分别统计模型 LOG、宿主提交和后续轮次真实输入；跨轮接续仍要求原运行成功、同范围、未过期、策略一致及当前纠错优先。现有业务检查点与工作记忆账本互相核对，长期候选仍需审核。

普通自由研究 Loop 另启用有界的保存状态反馈：只有 apply 模式、存在当前可见且可引用的读取回执、工作记忆工具仍在本次获准工具集时，才向实际模型请求提供本轮版本、已接受 LOG 次数和当前回执编号。历史检查点版本与本轮版本分开；尚无 LOG 时说明阶段进度的保存协议，已有 LOG 后停止保存建议。无变化不要求记录，不增加模型转发、工具权限或业务验收条件。

同一条件下，每次提供方请求独立复制工作记忆 schema，将当前版本写入 `expectedVersion.enum`，将当前可见或合法投影集合中仍可引用的 canonical `toolCallId` 写入笔记证据字段的枚举。原工具注册、其他工具、原始消息与审计事实保持原样；只枚举可信状态，不把来源正文提升为指令。模型仍自行决定并真实调用，提供方 schema 是描述而非授权：宿主继续核对版本、来源、可见性、租约、权限、幂等及持久化，不猜测或替换未知引用。记录模型保存须匹配实际调用、持久回执及后续实际输入；宿主兜底单列，不能据此宣称模型自主稳定。

普通自由研究报告使用单独的有界提供方配置：每次逻辑请求最多等候五分钟，仍服从 Loop 整轮十五分钟的上限。原短交付配置保持两分钟。两种配置都只允许原有的一次不透明空错误恢复，不重试超时或不完整流，不扩大工具权限，也不修改 TLS 或代理保护。

宿主把实际装载的记忆策略写入运行快照。Loop 最终动作检查读取该范围内的真实快照并重算当前策略，模型报告不能自行增加授权。车间的硬拒绝规则传到 Loop，拒绝优先于允许。保存事件不重复执行旧业务动作，不发送消息、不交易，也不代替主人审批。

用户通过现有运行事件查看保存、加载、跳过和失败原因，通过任务入口暂停或调整 Loop，通过记忆审核入口处理长期候选及纠错。输入预算不足时整项跳过检查点并记录原因，不截断成另一条指令；存储或租约异常沿用既有显式失败与恢复路径。回滚保留原始运行证据，切换经过核对的源代码与生产构建，不回放外部动作。

验证分别检查：真正落盘、下一轮实际模型输入、来源与续读身份、当前拒绝覆盖旧授权、无自动晋升，以及独立业务校验结果。通过隔离测试表示程序路径成立；通过生产观察还需要同一车间的真实连续任务证据，不能互相替代。

报告经历多次修正时，原始 `text` 草稿继续保留，但不能将多个草稿拼接后作为最终结构化交付。启用最终验证的 Pi Harness 路径只采用完整收尾后唯一非空的 `candidate_final` 结果，持久记录选中报告 SHA-256 和主要业务字段的规范化哈希；缺失、重复、选择回执保存失败均显式失败。普通研究还比较整形前后 `reportMarkdown`、`researchProcess`、`projectAssessment`、`checkpoint`、`warnings` 的一致性，不用散文修复掩盖字段丢失。生产验证同时核对原批准报告、宿主提交来源及最终入库字段，兼容执行器仍保留原文本回退契约。
