## 通用智能体进化论

已创建 `skills/agent-evolution`。工程框架的核心为：观察真实行为 → 建立原因假设 → 生成有限候选 → 匹配条件评估 → 授权选择与上线 → 观察、保留条件性经验或回滚。

通用部分区分目标、观测、状态、上下文、工具、验证、调度与治理；按原因更新对应层，避免不断堆 prompt。区分运行内适应、跨轮记忆、版本化更新和模型权重训练；skill 不宣称 YAML 可以创造未实现能力。硬边界先于总分，健康时允许不改，缺证据时 inconclusive，回滚配置不能撤销外部副作用。

支持分析、已有主人授权更新、自主候选提案三种模式。既有授权无需重复确认，但不能绕过实际平台审核和保护机制。通用变更记录和评估方法不绑定模型、行业、特定窗口或固定样本阈值；Zhiyu 工具和车间约束单独放在可选适配文件中。

## 遗留优先级

1. P1：Work completed 与 Loop blocked 的状态投影一致性，以及历史 queued/running 的租约/心跳/回执恢复。先核查真实执行占用，不能自动补做过期交易任务。
2. P1：核心来源与实际工具事件、所选题目、时效之间的语义关联；避免无关官方 URL 充当主证据。
3. P1：逐任务核查有效工具集与 requiredSources 是否一致，尤其自选股猎手不同任务要求的跟踪/复盘工具；权限拒绝不得自动通过移除 denied 解决。
4. P2：在受控输入和预算下执行角色匹配的基线/候选评估，收集用户效果与成本，避免把提示词修改本身当已进化的证明。

较大的运行机制与权限变更进入后续方案，当前验收保留其未完成状态。脚本 `audit-agent-evolution.ts`、`improve-agent-fleet.ts`、`verify-agent-evolution.ts` 是此项目的盘点、幂等更新和回读辅助，不是通用 skill 必须依赖的运行时。
