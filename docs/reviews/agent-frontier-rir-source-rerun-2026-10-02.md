## 原报告必须修正的地方

1. **接管不等于跨 Run。** `loop-consumer.ts:34` 将发现的旧 runId 作为 acceptedRunId 传入；`loop-execution.ts:60` 后复用该运行，`execution-lease.ts:69` 要求匹配 current.run_id。本质是同一运行的 worker/租约 token 更换，报告反复称“跨 Run 执行权转移”不准确。
2. **不能概括为只有完整结果重放、否则从头执行。** `loop-execution.ts:19` 的 readLoopExecutionStep 和 `:28` 的 applyLoopExecutionStep 已提供 recorded-step 结果复用入口；`:88` 后读取已保存执行结果，必要时才进入 execute。它们仍不等于任意工具步或环境的完整检查点恢复；实际覆盖需要继续读 recorded-step、harness 和完成链路。
3. **多个行号引用偏移。** 原文结果回放实际在 `loop-execution.ts:68` 后，retryContext 在 `native-executor.ts:640` 后；effect_started 的审核分支在 `execution-lease.ts:60` 后。评审时以函数及保存的哈希版本为准，不能照抄报告行号。
4. **事件不等于语义记忆。** workshopLogEvent 记录事件，不能单靠其存在证明可复用知识已经进入记忆或在重试中被召回；记忆实现不在本次 8 文件范围内。
5. **“无 rollback 消息分支”不足以证明无 rollback 工具。** 应检查工具注册和执行链路；标准 tool_use 本身可承载多种工具。本轮未发现 RIR 式回滚实现是有限范围结论。
6. **消融数据支持互补性，不证明知遇收益。** [RIR Table 3](https://arxiv.org/html/2609.18304v3) 的 Reflection only 70.48、Rollback only 69.37、RIR 76.75，与原文数字相符；它不能证明将 loop_states 改成四字段就会提高知遇成功率，也不能证明这是最小改动。
7. **实验建议不能直接落地。** 不应覆盖 loop_states 的控制字段或仅恢复代码就声称数据已回滚。应先做独立、带版本的 reflection 记录/影子上下文，保留原事实与控制状态；匹配相同任务和扰动对照，使用业务验收结果，而非 completed 状态作为唯一成功指标。20 次重试、5 个百分点不是统计显著性的充分标准。
8. **上轮结论对照表未经逐条核验。** 报告列出的“上一轮结论”不能直接作为对旧报告的准确引用，需对照保存原文；本次只确认新读取的证据范围。
