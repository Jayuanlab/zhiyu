## 已修改的控制链路

1. **协议适配**：将 OpenAI Completions 的兼容选项放到实际 SDK 读取的模型配置中，让既有配置意图进入真实请求：使用 `max_tokens`、默认不发送 `include_usage`，保留 store、会话头及显式调用覆盖策略，以及原有 API Key、请求头传递。用实际 SDK 序列化后的请求体断言，不以配置对象本身作为成功证据。
2. **终态准入**：先保留原始 SDK 终态、草稿与用量，Pi Harness 默认执行中的 `length` 转为宿主明确失败 `provider_output_truncated`，不能执行其中的工具调用或进入隐式长度恢复。已有明确启用最终校验与有界压缩的报告流程保留狭窄例外：仅无工具调用的截断结果可交给原有溢出判断；每次摘要请求仍须通过请求用途、正数预算预留、次数、子预算、期限和审计门槛，摘要本身必须完整结束。最后仍须通过完整报告校验，长度截断不构成成功。
3. **失败解释**：内容检查错误保留原文并标记为 `provider_content_rejected`；界面解释区分凭证过期、内容检查、输出截断及缺少结束标记。明确拒绝和截断不建议原样盲重试。没有改变提供方内容检查或绕过其拒绝。
4. **用量诊断**：没有实际正数用量证据时显示 `unknown` 与 `null`，保留真实报告的正数及部分字段，不以默认零冒充已知用量。
5. **Loop 完成回执**：原 Loop 会忽略底层 `runtime_terminal`。现在对实际 Pi Harness 运行保存带租约保护的原始结束回执，同时核对运行与清理均完成；缺失、重复、格式错误、失败、终态后继续输出或空答案均拒绝成功。`done` 只是流结束，不能替代该回执。Claude 与显式回滚适配器保持原有契约。

原始请求/观测、SDK 结果、宿主准入结果、持久任务结果保持分层。修改没有扩大工具权限、跳过审核、修改主人纠错正文或提高其置信度。生产 Web 尚未装载本次修改。
