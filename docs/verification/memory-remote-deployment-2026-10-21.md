# 独立记忆服务部署与知语远程接入验收

## 实际上线状态

2026-10-21，知语日常桌面 3515 已切到 stage41；独立记忆服务在本机 127.0.0.1:3640 常驻，由独立监督进程启动、重启和写心跳。服务、Web 和业务 worker 的生命周期分开；本轮没有启动原先停止的业务 worker。

独立库 zhiyu_memory_service 使用新建的专用登录角色，保存身份凭证摘要、权限纪元与只追加的传输审计。部署配置、令牌与日志保存在忽略且限制 ACL 的本机目录，没有上传 GitHub。服务仅监听回环地址，没有开放公网。

## 覆盖与兼容边界

- owner 统一保存、精确读取、候选/审核/修订、依赖绑定与当前核对、文件合同、召回/ContextPack 和回执恢复，经过独立服务中的知语项目安装模块执行。
- 旧候选新增、审核、修订、更新提案及决策入口也接到远程适配；owner runtime recall 在远程执行后，仍在实际模型进程登记并最终核验来源。
- 非序列化 proof、SDK hook、Work/Loop lease 和最后的来源/版本/授权检查保留在实际运行进程。owner chat 使用记忆时额外检查远程 project.use；JSON Pack 不成为授权。
- 旧管理列表、部分治理工具与业务观测生产者仍在项目本地适配层；本轮没有把所有 SQL、旧业务表或运行控制器搬到独立服务。业务主记录仍只有原来的一套，不做双写，也不复制到研发示例表。
- 服务身份库与业务库没有分布式事务。业务已提交但响应丢失时，传输状态可能为 failed_or_unknown；按原 commandId/receipt 对账，不能换命令重复写入。

## 操作与恢复

在 D:/zhiyu 运行：

```powershell
node scripts/memory-connection.mjs status
node scripts/memory-connection.mjs local
node scripts/memory-connection.mjs remote
```

切本地即时生效，读写同一主记录，不重放失败命令。恢复远程先验证服务已就绪；远程错误不会自动降级。刷新记忆页的“检查连接”可核对模式。服务连通状态不等同于所有业务来源都健康；读取和使用仍分别执行原来源检查。

私有部署目录包含 service-status.json 心跳、最近启动/退出和重启次数，service.log 为脱敏日志，service-stop.json 请求显式停止。日常 Web 启动器通过 ensure-memory-service 启动监督进程，但尊重停止文件；未新增操作系统开机计划任务。身份凭证有期限，过期会阻断远程；到期前通过本地管理员 CLI 换证，不把令牌交给前端。撤销远程服务凭证不等于撤销知语本地 owner 登录权限，停用用户需分别处理。
