## 修改与边界

前一版三轮业务全部失败，69 次物理请求、模型 LOG 一次；没有观察到输出长度截断。实际失败暴露了收尾未明确禁止工具、仅一次报告修正，以及补查定向搜索被交付保留规则阻断的冲突。原记录见[前一版真实观察](./memory-log-workflow-production-2026-10-19.md)，不改写旧成绩。

随后修复版只运行一个普通诊断任务：22 次物理请求，明确 none 的收尾请求正常结束，没有长度终止；业务仍因源码引用范围失败，模型 LOG 和宿主提交均为零。其余两个计划命令未执行。具体回执显示两个已读到末尾的文件被多算了一个换行哨兵，模型按总行数引用了未展示的虚拟行。该失败仍原样保留。

本次进一步按物理行计数，保留真实空行及原始字节哈希；源码读取直接提供当前 citation、nextOffset 和 nextRead，工具说明区分文件总范围与已观察范围。超长单行显式告警且不返回原地续读。源范围校验仍拒绝未展示内容，没有把旧报告自动修成有效。原始同字节离线回放验证了 251→250 和 147→146 两处回执边界；离线回放不是生产通过。

最终报告转发同时移除工具并发送 toolChoice=none，执行层仍拦截越界调用。普通报告最多两次字段或证据修正，共享原四次转发、65536 token 总额度、900 秒整轮时限与 40 次工具预算。交付保留阶段只允许一次原有 webSearch，必须 limit=1 和 site:domain 查询，随后只提交报告，不新增网页读取。

原业务校验通过后，若本轮工作记忆尚未编辑且策略为 apply，宿主可以提交模型在正常报告 checkpoint 中已经写出的待办问题。没有问题就不编造；已有模型笔记不覆盖；只保存问题，不新增事实、假设、行动或来源。先经过租约、权限及预算检查，再持久化审计；失败会阻止成功交付。事件明确标记 validated_report_checkpoint，记录原报告和检查点 SHA-256，页面显示“由宿主提交”。它不是模型 tool_use，不算自主 LOG，不自动批准 Brain 长期记忆。

## 判定与限制

稳定进度留存要求三轮业务均通过，每轮有真实 LOG 审计、持久业务检查点，后两轮实际输入含对应历史工作检查点与业务检查点，没有长度终止或自动批准；宿主提交还必须逐条匹配报告问题及检查点哈希。该判断只在观察器执行，不进入业务提示。原标准允许如实报告证据不足或降级；这类业务通过只证明处理符合约定，不等于获得了充分研究证据，逐轮状态另列。

主人已明确选择优先稳定落盘、区分模型与宿主提交。本阶段模型记忆命令被拒 6 次，失败尝试仍保留，不能算保存成功。版本冲突、无效参数和未观测来源的引用不会因希望保存而被放行；宿主只提交业务校验通过报告中已有的有界待办问题，不补造事实或伪装模型自主调用。

三个宿主 LOG 都在报告通过后写入，证明的是持久保存和下一轮接续；没有证明同轮模型已经消费新版笔记，也没有证明原始正文已被压缩。原观察器中要求同轮再次请求使用笔记的指标仍未通过，不以跨轮结果改写该指标。

提供方在显式 none 的请求中仍返回工具调用 2 次，相关不准入工具由宿主执行层拒绝；正常结束 SSE 不代表提供方遵守了工具选择。此类行为仍属遗留扰动，不能声称已靠请求参数完全消除，当前通过依赖有限预算、执行拦截和真实校验共同成立。

本样本未证明模型每轮都会自主调用 LOG；宿主兜底不能替代这一结论。 进度保存与继承的小样本验证通过，但不保证长期或所有车间稳定。 当前纠错保护可能清除旧事实、假设与行动，只接续未决问题；这不证明旧结论已核验，也没有新增主人语义纠错的生产样本。
