## 问题与修改

第一候选三轮业务 2/3、模型保存 1/3、宿主兜底 2/3，共 72 次请求，见[第一候选记录](./memory-autonomous-log-production-2026-10-19.md)。随后引用接口候选只运行一个诊断任务：33 次请求，26 次 schema 输入匹配，上一条模型笔记确实接续；但内层校验通过后，最终存储缺少必需字段，业务失败。模型 0、宿主 1，其余两个计划命令未执行，见[诊断停止记录](./memory-reference-schema-diagnostic-2026-10-19.md)，不改写旧成绩。

原因是原生执行器累计所有 text 草稿，却忽略 Harness 在完整收尾后发出的已批准 candidate_final result。多个 fenced JSON 首尾直接拼接后，最终解析可能为空或混入早期稿。针对性重放先失败，再验证修复；原始草稿与失败证据保留。

现在启用最终验证的 Harness 路径必须收到唯一非空已批准结果，只从该结果解析交付。选择回执记录原报告 SHA-256 及主要业务字段的规范化哈希；普通研究在整形前后核对 reportMarkdown、researchProcess、projectAssessment、checkpoint、warnings，缺失、重复、持久化失败或字段变化均显式失败。兼容路径保留原文本契约。

工作记忆当前版本和可引用 canonical toolCallId 仍按请求写入 schema，来源、权限、预算、幂等和租约仍由宿主重复校验。没有新增强制 LOG 条件、工具选择、额外转发或验收任务提示。原目标、Skill、模型、权限及业务检查保持；每轮仍为 40 工具、48 物理请求、900 秒，每个命令只运行一次。宿主兜底与模型真实工具保存分开统计，长期候选不自动批准。
