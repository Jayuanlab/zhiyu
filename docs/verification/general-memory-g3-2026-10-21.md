# 通用记忆 G3 验收

日期：2026-10-21。分支：`codex/general-memory`。目标：迁移审核修订、依赖失效、召回、ContextPack 与出站控制，维持知语原有合同和拒绝规则。

## 模块与控制闭环

- 通用 `governance`：事务内先授权、再锁定、查幂等回执、执行、保存审计；异体命令冲突，审计缺失不返回成功。审核与修订状态转换检查版本、待决提案、退役状态、主人核验；依赖判定始终以 denied 优先，未登记覆盖不能变成 current。
- 通用 `context`：对已经授权的候选执行预算选择、分组去重与保留位；优先级、相关修订和具体分值由项目给定。ContextPack 预算保留完整限制，正文按 Unicode code points 裁剪并标注；单位继续为 UTF-8 字节保守上界，旧 DTO 的 maxTokens 字段不改为虚假的精确 token。
- 通用 `use`：独立实例的进程内作用域，累计已进入上下文的固定版本，合并召回和精确来源证明；绑定实际运行时，每次 provider 请求前调用宿主事务重验与审计。失败使当前作用域持续阻断；关闭后的异步续作、冲突版本、超预算及准入期间新增来源均拒绝。宿主提供 namespace 限定键、来源真实性与事务 Adapter；JSON proof 无授权能力。
- 知语 Adapter：`memory-zhiyu/revision` 持有 PG 审核、提案、修订、依赖读写及旧命令映射；`memory-zhiyu/retrieval` 持有现有召回编排与旧 DTO 映射；`memory-zhiyu/context` 持有项目投影、最终准入、精确来源重验与实际模型 hook 装配。原路径仅转发到唯一实现，旧 writer、身份发行器、版本算法、锁顺序与事务关系保留。
- 来源观测、理解状态、审核动作和准入回执继续分层保存。源变化的权威阻断不依赖异步通知送达；模型正文交付以后不能撤回，下一次请求重新核验。模型调用不持有长事务。
- 主人继续在现有桌面记忆中心审核、分类、纠错和查看回执；不另建一套管理入口。业务策略版本仍为知语 `2.0.0`，本次实现拆分不冒充策略更新。

## 范围与恢复

G3 是复用模块与知语实际接入，不是所有项目的完整远程 K/U 服务。G1 的公开观测 client 能力没有被扩大为未经验证的 K/U；其他项目仍须提供自己的持久事务、来源读写、权限、namespace、审核界面和 provider hook，G4 再验收完整外部消费者。未改造旧知语共享租户、未发布 npm 包、未启用跨进程 bearer 使用凭证。

退回前一生产产物即可恢复代码；原表与旧接口保留，没有破坏性迁移。回退代码不撤销已提交审核，也不回滚数据库；撤回需用有回执的版本命令处理。日常 worker 保持停止，正向审核、真实模型 hook 与异常注入在隔离数据库和本地合成 transport 验证。

## 失败与修正

首轮使用未安装的 workspace 包名造成导入失败，已改用项目现行源码接入方式。通用 guard 的一次异步调度改写改变了原准入启动时点，原并发审计测试暴露后已恢复同步进入宿主 admission，仍捕获同步异常并持久阻断作用域。

扩大验收时发现旧 T4 夹具直接将 DB 返回的 JSON 字符串交给场景规则，缺失场景后被正确阻断。夹具改用实际 `getWorkshop` 读取链并断言绑定仍等于原 alpha 场景；未放宽项目召回规则。另一轮夹具私有文件路径不符合既有测试保护，已改用既有隔离目录约定；未修改安全检查。失败与重跑证据保留本地。
