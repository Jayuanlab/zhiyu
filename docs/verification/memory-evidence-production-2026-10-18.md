## 本次改变及适用范围

## 严格证据如何对应

1. **展开确实由模型发起。** 审计把实际主请求中的工具调用及参数，绑定到同车间、同 Loop、同轮的运行时调用事件，目标必须是当前纠错记忆。宿主探测、失败轮次或其他记忆的调用不能满足这一项。
2. **不是只返回一份记忆摘要。** 回执包含已解析的 `brain_observation`，其来源类型为主人版本化纠错。审计核对原始内容 hash、原命令、原提交内容、目标记忆及确切当前版本；只证明主人曾提交该纠错，不把它当作外部业务事实已经独立证实。
3. **原始观测进入了后续请求。** 调用、完成回执、宿主准备事件须按顺序发生，后续实际主请求须包含匹配的工具结果。只在数据库存在一条事件或模型口头声称已读取，都不算通过。
4. **同一任务实际成功。** 两轮正式入队回执、执行租约、完整持久轨迹、业务结果、校验、运行终态和清理终态均匹配，且来源展开出现在成功任务内。上一阶段失败 LOG1 的展开不会替本阶段充数。
5. **保存与继承同时成立。** 模型主动提交的真实新来源 LOG，与实际已提交宿主快照一致；候选最终结果和运行结束后分别核验交付。下一轮输入核对确切来源运行、检查点、根、创建时间及原有效期，不能续期或回退到无关祖先。
6. **纠错与边界保持。** 完整 323 字符当前记忆、真实置信度 25、active 状态及匹配版本保留；历史事实、假设与行动建议按当前纠错抑制，仅保留真实未决问题。历史来源引用不能冒充本轮来源 ID；新来源观测产生新 LOG，不等于旧检查点续期。
