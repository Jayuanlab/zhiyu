## 不透明输出中断的有界处理

新增恢复只在正式租约、工作记忆启用、确切官方 Go Qwen Messages 连接下装载。每个 Harness 运行至多恢复一次完整读取的 `HTTP 200 / SSE / event:error / data:{}`；两次物理传输共用 120 秒期限，正文、URL 和请求头保持一致，每次都须先通过租约检查并持久化审计。第一份失败草稿及工具调用不会交给 SDK 或执行器。认证错误、明确拒绝、长度截断、EOF、网络或解析错误、取消、写审计失败及恢复预算耗尽继续失败。最终仍由实际 SDK 和严格终态门槛决定任务成功。

物理恢复不等于重新执行领域任务，也不等于已定位上游原因。审计分别记录逻辑调用、物理传输和恢复决策，实际每次传输都占验收请求额度；失败流中的 usage 仅为部分观测，金额继续未知。实际请求审计按 `new Request(input, init)` 合成后的有效 bytes 校验，覆盖 `Uint8Array` 覆盖原 Request 正文的情况，保留该漏洞的红测试。

恢复相关 15 个测试文件、357 项通过，覆盖实际 SDK、主机工作记忆、租约审计及原有终态行为。最后两处 TypeScript 类型修正后，41 项 helper 测试再次通过；全量 Web 类型检查通过，154 项源码检查前后无漂移。最终验收四工具的 47 项离线测试及语法检查通过，独立复核通过。测试存在包含关系，不相加为总数。
