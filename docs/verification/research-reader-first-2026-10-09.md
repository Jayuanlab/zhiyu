# 研究报告改为价值优先交付（2026-10-09）

主人新方向：减少生成内容的限制，目标是可读、有价值，避免让严格约束主导产品。此授权修改报告交付政策；不把新的交付通过冒充旧科学验收通过。

本阶段范围是桌面 Web 的研究报告生成、完成、展示和回执链路。停止点：一个有限候选、匹配离线回放、关联回归、一次生产运行与实际阅读检查；不靠重复增加 prompt 或运行次数刷成功。

## 政策与实现

- 默认直接生成 Markdown 正文。问题、机制、区别、例子、学习意义与阅读建议随内容组织，不固定章节、字数、每篇结论种类或数量。
- 按问题选读资料。读取进度继续记录真实窗口和同版身份，未读齐可以提供阶段性报告，并明确范围。
- 不再强迫模型先通过全文补读阶段，也不因引文格式、证据缺口或覆盖不足而循环重写整篇报告。
- `researchEvidence` 是可选的额外核验材料。旧 `grounded-report/v1` 核验函数及标准保留，原始观察、失败记录与科学审查不改写。
- 新 `reader-report/v1` 独立记录 `delivered/rejected` 和 `verified/unverified`。模型正文不会自行获得核验身份；科学语义状态始终独立。
- 来源与核验细节置于折叠依据中；主文仅显示简短范围提醒，避免用一屏检查错误取代阅读。
- 空输出、半截序列化内容、开工承诺及运行错误检查点不当报告。失败、取消、中断及真实终态不因新政策改成成功。

原始模型答复、来源回执、交付理解及完成结果继续分层保存。交付哈希与同轮宿主事件绑定；展示层只接受真实宿主交付回执。放宽报告解析不会执行夹带的记忆、发信、唤醒字段，工具、预算、权限、暂停和外发审核仍按原链路控制。

## 评估口径

分别观察：

1. **交付**：是否形成可阅读正文、同轮完成与交付回执、正确对话及展示入口。
2. **价值**：是否回答问题、解释机制与区别、产生学习认识及可继续阅读的方向。用实际内容审查，不用固定章节、字数、工具次数或模型自评分代替。
3. **核验**：实际阅读范围、引文对应、数字和条件、独立科学语义分别记录。未核验可以交付，不代表结论全部正确。

- 默认完成校验与执行器回归保留半截 JSON、错误检查点、失败/中断终态、空正文和工具预算边界。

## 阶段结论与后续顺序

本阶段交付政策已上线且真实报告可读，至此停止修改和模型重跑。后续评估以能否回答需求、解释清楚、提供有条件的认识和实际阅读体验为主；发现内容问题作为改进反馈，不新增一组固定生成格式或逐条拒绝门槛。

明确保留的遗留项：

1. 优先改善模型解读：上述结论的适用范围与推断语气需校准；保留本轮原报告和审查，不事后改写为正确样本。
2. 桌面预览和普通对话摘要会将 Markdown 表格、标题压成一行，完整阅读弹窗正常。应从正文提取可读短摘要；原 provider 提醒仍含英文内部代码，也应改成可理解说明。
3. 多个车间标签常驻 SSE，可占满同源连接，导致普通读取排队。此次仅关闭旧智能体测试标签并新开结果页后恢复，未修改用户标签、服务或数据；需另一个有限阶段实现后台页释放连接、回到前台按游标补读，以及读取超时与重试。[EventSource 的连接限制](https://developer.mozilla.org/en-US/docs/Web/API/Server-sent_events/Using_server-sent_events)支持这一诊断，当前记录为强证据而非抓包结论。
4. 静态复核发现：普通 Markdown 中夹带完整 JSON 示例，可能被宽容解析器误当结构化报告。尚未在本轮实际输出中出现，应在后续解析维护时补针对性验证。

以上没有宣称已修复，也不扩展本阶段重新构建或重复运行。

## 恢复与边界

源码回退应恢复本阶段基线快照并逆向撤销本阶段有限差异，删除新增 reader wrapper 后恢复旧调用点；共享工作区已有改动不能整体重置。发布回退可在无未完成运行时按原隐藏 launcher 恢复 review59。回退不改写新旧运行、来源或交付历史。

本轮不修改车间使命、模型、角色、工具授权、持续任务排期或配置数据库。后续生成内容的产品判断以阅读价值为主，接口安全、真实状态与实际执行回执继续独立负责。
