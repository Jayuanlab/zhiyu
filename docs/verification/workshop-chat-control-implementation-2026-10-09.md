# 对话指挥车间：首批实现验收

本批实现桌面 Web 普通 Pi 对话的最小控制闭环，沿用既有车间执行器、命令账本、租约、权限和临时问答隔离。运行协议见 `docs/contracts/workshop-chat-control.runtime.v1.json`；原 26 项设计目录仍然仅为设计，不会自动装载。

## 已保存的功能

- 发现车间、安全查看配置、观察具体运行及按 hash 分段读取完整运行正文。
- 主人当前已保存指令绑定具名工具；交办、原事项补充、临时问答、暂停后续和取消精确运行。普通文字命令无额外 UI 确认，已有领域审核与 denied 仍有效。
- 默认 Pi Harness 权限回调只放行实际装载的读工具与本轮已绑定的具名写工具；核验 owner/chat/turn/action、空对象参数和当前授权后才派发。计划模式的 execute 阶段不开放新写工具，运行时 denied 仍在执行前硬检查。
- `workshop_chat_contexts` 保存原对话指向，`workshop_chat_work_items` 保存事项修订和运行关联。指代词不再从旧 YAML 审查或浏览器 URL 猜车间，参考资料中的另一车间名字不会覆盖目标。
- 澄清轮结束后事项保持 needs_input，补充生成同事项新修订；成功运行保持 awaiting_acceptance，无效果中断映射 failed。原运行结果由同车间、run ID、hash 和完整输入快照固定，不依赖最近事件窗口。临时续问保留 conversation 与 parentRunId，不能升级为长期业务任务。
- 完成事务生成持久 ChatDelivery，worker 向原对话幂等追加普通 assistant 文字。失败只重试通知；原 chat、来源消息或 Work 不可用时保留 blocked 原因。后台结果不改当前工作指向。
- 对话移除车间卡片与管理按钮；每 10 秒及重新进入、重连时回读消息，保护流输出及尚未确认保存的消息。不再自动合成新用户“继续”重发业务。
- 当前与后续都停时，在同一事务先暂停接纳屏障，再取消精确运行。原队列保留暂停；不宣称进程已经退出或外部效果已撤销。
- 明确保留后续的取消命令只取消原运行；单个 Loop、排期或局部任务的暂停不能扩大为整车间暂停。重复受理的文字明确是历史回执，不能冒充当前状态。
- 主指令独立精确读取；超过 50 条辅助指令也不能遗漏。规划和执行的主输入、续办输入及报告合同不静默截断，预算不足明确失败。inspection 使用字段白名单，异常不透传原配置错误。
- 消息读取改为最近 1000 条并保持时间顺序，超过 1000 条的聊天能收到后台新结果。精确主人指令核验独立于全文窗口。

## 本批支持的对话方式

普通 Pi 对话中，可使用“让强化学习前沿学习者研究本周论文”“问一下强化学习前沿学习者解释这份报告”。成功交办后，同一对话中的“它”绑定该车间；“继续，补上对比表”仅在原事项需要补充或已结束时续办同事项。车间追问研究范围时，“只看上周的新论文”可补充原事项。

“暂停后续任务，当前继续”暂停整个车间的后续接单；“停止当前这轮，后续不要暂停”仅取消原运行；“停止当前和后续运行”先建立整车间暂停屏障再取消原运行。当前入口不支持单个 Loop 暂停与恢复，不把“暂停每周扫描，其他任务照常”扩展为整车间暂停。

这些是有明确宿主绑定的有限命令入口。发现候选后动态选择、新聊天重建旧事项和任意表述的自动控制仍须后续实现，不能宣称所有自然语言或全部 26 项设计接口已接通。
