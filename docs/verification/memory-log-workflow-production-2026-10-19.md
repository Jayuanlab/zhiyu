# 长报告交付与普通业务 LOG 连续生产观察

本次完成修复与真实观察，但普通任务稳定保存与继承尚未整体通过。 不把机制可用、报告自述、长期候选和正式业务通过混为一谈。

## 修复与边界

原三轮只有一轮业务通过，LOG 为零。原始失败请求显示：一轮上下文挤占报告空间，最后请求只剩 1 token；另一轮的修正报告被等分到 8192 token。LOG 更新还受到中文笔记键与 schema 不一致、来源编号接口不匹配影响。原失败数据保留在[上一阶段](./memory-ordinary-business-production-2026-10-18.md)。

修复后，打印文本形式的中文键按有界笔记键接收；本轮已经观察且身份一致的网页编号、原始读取事件编号和源码 SHA-256 由宿主精确绑定到当前获准工具回执，最终保存规范工具编号。未知、冲突、跨范围、被拒或不完整的来源不能绑定；模型自己写的观察事件不获得读取证据资格。

普通长报告只在 reportMarkdown 中保存一份正文，不要求缩短论证。修正共享原 65536 token 总额度，单次最多 16384 token；取证靠近上下文上限时停止继续业务取证，保留至多两个当前笔记/日志转发后只交付报告。原消息、警告及工具配对不删除，不自动补造 LOG。至少 4096 token 答复空间无法满足时明确失败，不派发一 token 的伪交付。完整方法见[记忆框架](../architecture/ordinary-business-memory.md)。

## 常规进度留存规则

先部署的 review88 用同一车间运行一个普通诊断任务：完整报告通过原业务校验，没有长度截断，21 次物理请求、17 次工具调用；写入一条长期候选，LOG 为零。这个结果原样保留，剩余两个诊断命令未执行。它证明交付问题已有改善，但接口修复没有消除工作 LOG 与长期候选之间的流程歧义。

本阶段进一步更新共享工作流：在已获准的策略触发阶段，有新增观测、纠错、未决问题或下一步变化时，先读取目录和版本、保存简短实际 LOG，再进入长报告或下一阶段；无变化时不凑条目，不增加无关取证，保存失败明确披露。长期候选送审不能替代工作进度留存。任务正文没有额外验收文本，没有新加必写 LOG 的业务校验。此项是持续生效的通用流程修改，不能称系统提示完全不变。另保存了本阶段三个原 review88 源码文件用于回滚。

## 装载与验证

生产 reviewmain，构建和构建后类型检查通过，525 项针对性测试、28 个测试文件及 17 项观察器检查通过。原失败 LOG 离线回放已能绑定真实工具回执并保存；原第三轮协议重建结合记录的用量回执，约 79967 输入 token 时触发保留交付空间。离线回放不是模型生产调用，不改写旧成绩。七个旧源码文件按原 review86 哈希完整核对，可与旧构建一起回滚。

沿用同一研究车间与 Loop、原目标、Skill、模型、业务权限和校验规则，运行三个普通命令。没有专门验收提示，没有植入纠错，没有新加“每轮必须保存 LOG”的业务条件；通用运行时的工具接口、输出组织和有界交付提醒发生了变化，效果无法单独归因于其中一项。每轮仍限 40 次工具、48 次物理请求和 900 秒，不重复失败命令追求通过。

## 准确口径与遗留

稳定通过要求三轮实际业务交付均通过、每轮有接受的 LOG 回执、后续轮次实际输入有对应持久检查点，且没有输出长度失败、自动批准或来源身份退化。这个判断只在观察器中执行，没有注入业务提示。未满足就不标记稳定通过。

当前 Brain 纠错信号可能使旧事实、假设和行动建议被抑制，只传递问题；问题接续不能称整份旧结论已获认可。没有新增主人语义事实纠错的生产样本。三轮不证明长期稳定、真实收益或所有车间自发保存。此前缺失回执与失败样本保留。既有桌面通用交易措辞、目标摘要不完整仍未处理，不涉及移动端验收。

临时观察器已移除；生产 worker 在线，无本次在途任务，原任务状态保留，源码与当前构建一致。
