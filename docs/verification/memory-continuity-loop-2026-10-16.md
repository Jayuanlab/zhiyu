# 跨轮与 Loop 记忆接续：实施和真实任务验收

日期：2026-10-16。用户授权接通跨轮和 Loop 记忆，并在同一车间连续运行真实任务，验证保存、召回和纠错；期间用户另行明确授权修复 Docker。

## 本次实现

1. 同车间、同 Loop 或经过认证的显式父运行，读取持久历史工作检查点。历史内容单独标记为未核实材料，不放入本轮工具证据目录，不伪造旧工具结果或恢复原 SDK 会话。
2. 中间轮次不重新 LOG 时，可以沿已持久接续回执继续读取；逐跳重核归属、策略、来源和时序，最多 8 跳。根检查点默认 7 天有效期不因继承延长。失败、恢复清空、过期、来源撤销、历史截断均显式停止，不倒回旧状态复活笔记。
3. Brain 的真实替代、停用或冲突信号优先于历史判断。普通偏好和常规召回不冒充纠错；实际纠错会抑制历史事实、假设和旧行动建议，保留未解决问题。
4. Loop 已结束运行可以通过显式 `runKind=loop`、`loopId` 和运行编号提交精确笔记为 Brain 待审候选。校验来源事件、实际调用、快照 hash、读取范围及同版本请求准备回执，保留主人审核。候选与送审审计分两次提交；第二步失败明确报错，可用同一命令恢复，不复活已审核候选。
5. 桌面工作记录显示历史接续来源、有效期、抑制与跳过原因，并提供 Loop 送审入口。历史准备回执与模型实际使用分开显示。

## 实际发现与修复

- Docker 启动被两个遗留、不可访问的 runtime socket 阻断。保留日志、设置及磁盘元数据，将仅包含这两个 socket 的运行目录同盘备份后重启。原数据库容器与原卷均存在，日志显示跳过初始化并进行 WAL 恢复；未恢复出厂、删除卷、重建数据盘或改数据库连接配置。
- 原 Loop 风险识别扫描整个动作策略，连 denied 中的发送和交易工具也误算高风险。现按实际有效 allowed 动作判断，denied 优先；真实获准的高风险能力保持原有门槛。
- 规则降级对记忆、经验、假设及策略类请求漏选 insight/lesson。补充通用类型路由，保留权限、候选排除和真正高风险的置信度门槛，没有抬高测试记忆分数或绕过审核。
- 历史笔记与现有 Loop 持久状态共用已有状态窗口，避免将固定系统说明重复计入状态预算。达到额度时显式跳过。
- 宿主拒绝错误引用时明确区分工具调用编号、来源快照编号与来源事件编号，并列出本轮实际可引用的工具调用编号，减少盲目重试；来源校验没有放宽。
- 原研究 Loop 未把研究契约传入工具层，直接读取降级没有不可变正文快照，长期送审被正确拒绝。补齐契约传递和受限纯文本快照，仍保留实际来源类型、降级警告与精确 hash/窗口校验；既有失败事件不回填、不改写。
- Brain 最新状态读取失败时，历史判断不能作为当前知识继续使用；此时仅保留历史问题进度，显式抑制事实、假设和旧行动。健康 Brain 的普通召回与辅助路径降级不冒充主人纠错。
- Brain 正常选择会过滤已停用记录，另增本车间近期停用身份查询：只读取身份与状态，经过权限重核后进入 omitted/纠错信号，不读取退役正文，不扩大正常选择范围。查询失败、异常或超过 200 条即进入未知状态保护；审计记录查询范围与覆盖情况。

## 验收方式与边界

使用专用验收研究车间及其手动 Loop，沿用实际本地 owner 和 Qwen 配置。通过正式 Work Runtime、实际 Pi Harness、公开 RFC 2119 网页、Brain 晋升/审核/版本化修订及真实 PostgreSQL 执行。每轮单独启动进程；不手工复制前轮答案，不启用调度，不外发、不交易、不删除。

任务明确标记为机制验收：来源中的客观事实与演练专属策略分开。更改的是仅适用于验收车间的决策规则，不能写成 RFC 客观事实发生变化，也不写入用户通用稳定知识。它验证真实系统链路，不是自然研究质量或收益的对照实验。

首轮尝试保存在 `.tmp/memory-continuity/20261016-joint-loop/`：A 保存成功并送审；B 实际载入历史笔记，但长期召回漏选且主请求超时，失败回执完整保留。该尝试中 A 后修复过接续预算，不能称全程同源码。

第二次尝试 `.tmp/memory-continuity/20261016-final-loop/` 在 A 的主模型连接阶段失败，没有保存笔记。随后复现本地代理间歇 TLS 断开与默认直连选到不可达地址的问题。验收进程使用当次探测成功的公网 IPv4，仅覆盖原模型域名，保持域名、SNI 和证书校验；未修改系统代理、DNS 或提供方配置。

第三次尝试 `.tmp/memory-continuity/20261016-verified-loop/` 的 A 成功，5 个主请求均 HTTP 200，Loop verification/checker 均通过；送审发现直接读取没有原文快照，返回 `source_window_conflict`。保留成功 A 和失败送审，不计作完整四轮通过。该尝试 plan 后仅有一处 TypeScript 类型断言变化，单独记录，不称严格 plan 源码冻结。

第四次尝试 `.tmp/memory-continuity/20261016-complete-loop/` 的源码严格冻结，但 A 再次在主请求连接阶段失败，没有执行工具。TLS HEAD 预检成功不能证明随后带正文的模型请求成功，故未送审，也不计作通过。

修复后的完整验收目标为 `.tmp/memory-continuity/20261016-stable-loop/`。验收临时偏好地址必须属于当次 DNS 公网候选并重新通过 TLS 检查，不写入系统配置或产品默认值。原始请求、事件、候选/审核/修订和用量回执仅留本地；公开结果需脱敏，不能包含凭证、私人消息或其他车间资料。

用户要求单次检查密钥后，独立最小请求实际发送一次、无重试，返回 HTTP 400 `MissingSessionID`（缺少提供方会话头），单凭此请求不能判定鉴权是否可用。同时完成的同配置 A 有 5 个主请求 HTTP 200、真实工具和最终模型结果，证明当前 Key 可用；未将 400 误记为成功，也未将连接超时判为 Key 过期。探测日志不保存 Key、请求头或原始响应正文。

## 结果

原 A–D 四轮均返回真实成功，持久 Loop checker/verification 均通过，19 个主模型请求进入实际运行。但独立核验判为失败：C/D 的完整纠错正文未送达，只送达了片段。模型采用了新标签不能替代完整规则验收。原始失败审核保存在 `independent-review-2026-10-16T08-01-59-139Z.json`，补充审核为 48/50 项通过，失败项目不改写。

随后在原车间、原 Loop 中修复上下文预算和 typed Brain 证据读取；以独立修复计划冻结新版本，不称 A–D 与修复后运行使用同一源码。E 实际通过工具展开完整新正文与主人观测，但提供方在最终输出阶段返回流式 `data_inspection_failed`，整轮失败，不能以 10 个 HTTP 200 冒充完成。

E 还暴露健康规划器的软筛选可能在候选查询阶段排除主人当前纠错，导致既有“近期修订保留”逻辑看不到它。新增修复限定于正常风险、本车间、已应用的近期主人纠错，保留真实置信度与权限，不扩大候选审核或真实高风险门槛。最终补验限定一次显式 E2 恢复尝试和后续 F；失败 E 的历史不能回退为 D 的旧检查点。未完成的轮次不记作通过。

E2 再次在最终流式输出阶段被提供方以 `data_inspection_failed` 中断，因此停止追加模型调用，F 未启动。正式后续审核为 **`incomplete_evidence`，不是通过**。同车间共完成 6 次真实尝试：

| 轮次 | 执行与持久状态 | 记忆核对 |
| --- | --- | --- |
| A | 成功，checker/verification 通过 | 实际来源、LOG、精确待审候选与主人审核通过 |
| B | 成功，checker/verification 通过 | 新进程收到原长期记忆及 A 检查点 |
| C、D | 执行成功，严格核验失败 | 采用新标签，但完整纠错正文被截短；typed 证据展开失败 |
| E | 提供方流错误，失败 | 已修复的工具成功返回完整正文、版本与主人原始观测；自动初始召回仍漏选 |
| E2 | 提供方流错误，失败 | 自动收到完整 323 字新正文、精确版本、真实置信度 25 和 active 状态；旧版排除，失败 E 的历史正确跳过，typed 证据展开成功 |
| F | 未启动 | 前置 E2 未成功，不伪造后续验证 |

E2 的真实 Brain 日志显示主人纠错预留查询已启用并选中相关记录；该轮规划器超时后使用规则回退，因此“主动置信度 60/错误类型过滤下仍可预留”的效果目前由程序测试覆盖，不能写成已在该轮真实模型中证明。排名分数与置信度已分开，数据库与模型输入均保留 25，不将主人陈述包装成已验证的业务事实。

原审核和后续部分审核都保留。E2 部分审核为 31/32 项通过，唯一附加标记问题是 `reasons.slice(0,5)` 截掉了未验证事实警告；该项随后仅做程序修复和回归，不追加真实模型调用，不改写 E2 的原始输入或审核。

该同车间 6 次尝试共观察到 47 条模型提供方请求，其中 33 条主请求的 HTTP 状态均为 200，但 E/E2 的流终态失败；**HTTP 200 不等于模型完成**。SDK 31 条已报告、2 条未知，711,815 仅是已报告 token 子计，不能当作完整用量或计费量；完整 token 总数和货币成本均未知。辅助超时及原证据工具失败另留降级警告。

Docker 原数据库保持可用；4 个废弃验收车间已通过正式版本化命令归档，其原运行、记忆与事件内容指纹不变，仅追加归档审计。当前车间保留，Loop 为手动触发，没有启动后续自动任务。README、方案与本报告同步更新，生产 Web 未切换。

## 已知边界

- 接续的是持久检查点和进度，不是上一次 SDK 会话、思考过程或旧正文投影。
- 当前长期晋升仍要求精确持久网页来源；本地文件不可变快照的晋升没有在本次扩展。
- 辅助召回规划或资料路径的失败保留为降级警告；它们不等于主记忆机制失败，也不能伪装成全部依赖健康。
- 真实用量缺失保留未知，不根据字符数推算 token 或货币成本。
- 停用身份信号目前仅覆盖本车间自有 work/workshop 记忆的最近 30 日（覆盖当前最大接续有效期）；不覆盖跨车间或全局授权记忆的停用。近期任一自有停用会保守抑制历史判断，精细的逐条依赖传播仍待后续实现。
- 本次运行使用开发源码的真实服务执行链。已有生产 Web 未在本次部署切换；组件渲染验证也不冒充生产浏览器验收。
