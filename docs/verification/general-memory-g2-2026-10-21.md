# 通用记忆 G2 验收

日期：2026-10-21。分支：`codex/general-memory`。范围：知语项目适配、来源目录与精确 reader、纯业务策略、通用限制合并；G3 的审核/召回/出站实现迁移仍未开展。

## 实施边界

- `packages/memory/src/policy.ts` 定义无知语依赖的策略输入、输出、限制合并及脱敏策略痕迹；策略只能提出建议，不能生成授权、来源核验或免审凭证。未识别/异常策略拒绝使用，denied、未核验来源、待审、到期和硬期限优先。
- `packages/memory/src/sources.ts` 提供宿主装配的只读来源注册表，拒绝重复/缺失声明；请求 JSON 不能动态注册来源。G1 观测核心与知语来源目录均使用该接口。
- `apps/web/lib/memory-zhiyu` 持有主人身份发行与执行身份检查、旧格式 codec、PG 事务 Adapter、来源配置及精确 reader。原路径保留显式转发；旧表、旧 ID、版本和回执不改写，只有一个权威 writer。
- `apps/web/lib/memory-policies/zhiyu` 持有行情/日报/混合内容、检查点及验收分类，经验片段和波动事实识别，以及 24h/7d/30d/90d 数值；这些没有进入通用核心。
- 研发示例有自己的 2 小时运行记录窗口与 90 天默认、180 天最大复查期，未知记录进入待治理。没有要求其他项目提供 Work、Loop、微信或行情字段。
- 新分类的 `recordLifecycle.policy` 保存策略 ID/版本、输入 hash、决策 hash 与脱敏摘要；不把策略痕迹当作事实审核或出站证明。既有分类不自动追认新版本。主人显式分类与策略建议分别可追溯。
- 记忆中心显示后端实际返回的当前分类策略版本；异常策略元数据报错，不显示为有效配置。已有审核、依赖失效、ContextPack 和出站保护仍调用知语已验收实现。

## 兼容与反馈

拆分前保存 1743 条实际记忆的分类、窗口、阶段、召回排除原因、版本及来源目录；拆分后逐项对照，既有语义一致。新策略痕迹只出现在新分类，旧记录与时间未迁移。

原有拒绝语义要求坏期限应停止使用而不是让整个依赖查询抛错。首轮回归发现该差异后，Adapter 保留分类建议的可检查性，核心仍报告无效约束并拒绝使用；现有 reader 和依赖检查继续拒绝该期限。没有为通过测试放开读取。失败记录与修改前后迭代保留在本地运行目录。

闭环检查包括分类、提炼候选、主人审核、审核后读取、到期阻断、来源变化导致审核/召回/出站失效、精确撤回恢复，以及幂等和跨 owner 拒绝。正向业务事实确认仅在隔离数据库执行，日常候选保持待审。

私有原文与完整数据库摘要保留在 `.runtime/memory-g2-20261021`，不上传。
