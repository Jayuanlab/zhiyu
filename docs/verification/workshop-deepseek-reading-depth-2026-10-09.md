# DeepSeek 本轮资料阅读深度独立审查

本记录只审查运行 `c23c3748-2dc2-8a3e-a860-55a25a0a3cee` 的真实行为与结论证据边界，不重新执行智能体，不修改生产配置、记忆或任务。采用 agent-evolution 的“观测事实、原因假设、未验证项分开”方法。

## 结论

本轮完成的是以搜索摘要为主的初步综述，不足以支持“深度阅读 DeepSeek 核心技术工作”的验收。缺口主要是原始来源正文覆盖，不是已经打开的唯一网页没有读完。

## 预算与原因的证据边界

1. 真实 `context_budget_report` 显示 `maxToolCalls=30`。最后一次外部调用事件显示 `budgetedToolCallCount=7`。本轮没有工具预算耗尽或超时错误。
2. 执行器 `executor.ts` 的 `isWorkshopTool` 将 `webReadPage` 归为车间域工具，不计入该外部调用预算。因此没有证据支持“30 次预算用完，无法继续读正文”。
3. 已知的规划器异常是 `directive_plan_failed`：Workshop planner LLM 未配置。执行随后使用开放探索流程继续成功。这是确定的降级事实；它是否导致本轮少读正文，尚未做匹配条件对照，不能认定为唯一根因。
4. 初始 prompt 报告约 11,773 字符、2,944 估算 token，不能据此证明整个执行最终上下文的大小。也没有本轮上下文超限事件，因此不应把缺读简单归为上下文窗口限制。
5. 从行为与现有控制器指令看，模型连续扩展搜索主题，随后在只打开一篇综述的情况下结束。已核代码说明“有用且有边界”以及引用真实证据，但没有本轮必读原始来源覆盖清单与逐结论正文验收。最直接的待验证假设是：停止条件允许搜索综述被当作深读完成，而不是检索/提取工具不可用。

## 可检验改进方向

下一轮验证宜限定为 DeepSeekMath、R1、GRM/SPCT 三项核心工作，先从官方论文、官方仓库或作者报告建立必读清单，然后阅读全文或任务相关的完整方法、训练与实验章节。DAPO 等关联工作单列为生态背景；R2 未确认信息单列待核，不能充当已验证贡献。

把当前读取状态结构化为“发现、正文已取、分页完整、相关章节已核、结论支持/未支持”。每个数值、机制和实验比较关联实际 evidenceId、内容哈希、正文片段或章节。页提取失败时保留失败与替代来源；预算不够时交付阶段结果与未读清单，继续状态可恢复。停止条件由核心来源与关键结论覆盖决定，不由报告篇幅或自评分决定。

验收应观察：三项核心工作是否实际读取原始正文，分页是否有遗漏，关键结论是否可对应证据，未确认信息是否明确降级，候选记忆是否引用正文事件，以及界面是否如实显示“初步综述/精读完成/仍缺资料”。这是一轮需要后续实现与匹配评估的候选方案，本次没有进行代码修改、重跑或上线。
