# G5 通用记忆服务化与跨进程接入验收

日期：2026-10-21。分支：`codex/general-memory`。实现范围与部署步骤见 [远程接入协议](../reference/general-memory-service-v1.md)。这是可选服务入口；知语继续使用本地 Adapter，不安装新通用表、不共享旧表，不增加网络依赖。

## 实现与安全边界

- 通用核心增加持久化远程使用凭证：固定 ContextPack、256 位随机凭证、数据库仅存摘要、身份 id/epoch、tenant/project/principal、消费者、用途、Pack hash、固定版本集合、策略版本摘要和 60 秒期限。
- HTTP Adapter 及独立 Node 示例提供观测、审核修订、召回、精确读取、prepare、dispatch 与凭证状态查询。普通 JSON Pack 无法获得出站权限；身份、来源和接收端都由受信宿主装配。
- PG 凭证记录、成员/来源授权与来源版本在最终准入事务中重验；凭证单次消费与 `use_admitted` 原子提交，事务结束后才调用登记消费者。
- 身份发证、改权、撤权通过本地管理员 CLI；改权/撤权递增 epoch，事件不可改写。令牌写私有文件，不打印到日志；Windows 私有目录 ACL 由部署运维设置。
- 消费后不自动重发；服务重启可恢复未消费凭证，admitted/dispatched/outcome_unknown 可对账。测试接收端的确认不是业务完成。

## 独立真实进程验收

`examples/memory-project/service-acceptance.ts` 在新建空 PostgreSQL 测试库中显式初始化通用及研发示例 schema，不运行知语迁移。两个服务进程共享同一数据库，客户端为另一进程；测试中关闭一个服务再启动新进程，总计启动 3 个服务进程。只有本地合成 HTTP 接收端，共发生 4 次预期交付；没有调用真实模型或外部业务。完成后全部进程退出，测试库删除。

14 组通过：

1. 无认证/伪造认证/浏览器 Origin 拒绝，跨进程认证身份绑定。
2. 观测保存、精确读取、Unicode 回读及跨进程幂等；相同命令在不同 project/tenant 下隔离。
3. 候选→审核→召回→使用；拒绝替换 Pack、namespace、消费者、用途及同主体另一身份凭证。
4. 两个进程并发消费只交付一次；使用回执和状态按 namespace 隔离。
5. 签发进程退出后，新服务恢复未消费凭证与命令回执。
6. 来源摘录以外的正文变化仍阻断最终发送。
7. 来源/成员 denied 优先于 allowed，最终出站零发送。
8. 使用凭证到期、来源到期、改权/恢复后的旧 epoch 凭证均不能发送。
9. 接收端异常记 outcome_unknown，凭证仍已消费，查询可对账且不自动重发。
10. 延迟到 COMMIT 才失败的审计触发器：凭证消费回滚、零发送；故障移除后原凭证可安全准入。
11. 管理员撤权阻断旧身份的读取、命令重放和出站。
12. 修订产生新候选，旧知识停止召回，新版本重新审核后恢复。
13. 真实管理员 CLI 私有文件发证、最小权限、身份到期、撤权及身份事件不可改写。
14. 通过 pg_stat_activity 确认发送请求正在等待真实来源行锁，让使用凭证、身份凭证分别在等待中到期，再释放锁；两种情形均由最终时钟重验阻断，零发送。

最终复核补上了锁后时钟重验，并汇总全部已锁定知识/来源的期限，防止某条来源已检查后又等待其他锁而跨过到期时间。先前 stage36 构建因此不作为最终交付通过证据；重跑独立闭环、包测试、固定回归与类型检查后重新构建，最终证据绑定新的源码摘要。

G4 独立项目 14 组、通用包 27 项 Node 测试、独立包 TypeScript 与无知语/Next/Work 依赖检查亦通过。独立源码另存逐文件摘要，因为桌面发布源码摘要不覆盖 examples。

首次并发验收曾因预期错误码过窄而失败：竞争发生在最终准入阶段时由现有 guard 返回 `knowledge_dispatch_blocked`，与提前检测消费时的 `use_already_consumed` 不同。两者都拒绝第二次发送；测试按实际阶段接受这两种明确拒绝，并仍严格断言只有一次交付。失败原因记录于本节，最终通过证据只采用修正后重新执行的结果。

## 已知限制与回退

日常广泛查询“项目的约束与边界”仍因完整安全约束超出预算而明确拒绝；这不是成功生成 ContextPack，未通过删减约束掩盖问题。新服务正向知识使用在独立项目中完整验收。

后续治理已在 stage39 完成，见 [完整约束与召回预算验收](memory-context-budget-2026-10-21.md)：桌面显式协商窗口后保留全部 16 条已选约束，旧固定预算不足仍明确拒绝。本节保留的是 G5 当时的限制与真实失败证据。

当前只覆盖登记网关、注册来源依赖与有界召回。跨库来源、文件、向量缓存等新 Adapter 未经同等测试不能宣称共享租户或原子重验；旧知语表不具备因此自动获得的多租户能力。生产公开部署需另配 TLS、网络访问控制、并发限流及监控；本次没有开放公网服务。

使用凭证过期不会自动删除私人快照或审计，保留清理须按项目政策另行配置。撤权阻止之后的准入，无法追回已交付内容。出现 admitted/unknown 时先对账，禁止自动重新签发凭证重做同一业务动作。

可停止独立服务并保留其数据库与历史；知语本地模式继续使用。桌面实例保留上一套生产构建作为回退，不回滚历史审核、不删除审计。证据区分“已编辑、程序验证、实际装载、真实桌面效果”，不把接收端 200 当成业务效果。
