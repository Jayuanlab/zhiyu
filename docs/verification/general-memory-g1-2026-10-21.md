# 通用记忆 G1 验收

日期：2026-10-21。分支：`codex/general-memory`。范围：通用核心的观测追加、固定版本读取与幂等重试，知语旧入口兼容；不包括 G2 的业务策略迁移和 K/U 能力。

## 实施

- `packages/memory`：通用 DTO、严格输入、可信宿主装配、观测核心与事务接口；仅 Node 标准库，无知语依赖。
- `packages/memory-postgres`：独立表、项目隔离、命令与来源幂等、事务内审计、原文数据库保护。
- `examples/memory-project/record-loop.ts`：独立消费者验证保存、精确读、重试与命令回执，不导入 Next、知语 schema、Work 或 Loop。
- `apps/web/lib/memory-zhiyu/observations.ts`：固定项目映射、真实主人/租约检查、旧表事务和版本/hash codec。原 client 的观测实现替换为兼容适配，其他记忆能力仍走现有路径。
- 已切入的生产路径是主人的观测命令与 current/evidence 读取；`createObservation` 的 Work/Loop 与已有采集路径仍保留原执行租约和事件审计，不宣称所有 writer 已经通用化。
- 日常库不新增通用表、不改变旧 ID 或历史正文。默认 `gobsrv1` 与知语 `obsrv1` 分开，历史 command hash 与回执可重放。

## 验证范围

独立核心 8 项契约检查；真实隔离 PG 12 项闭环检查；沿用 T1 的历史兼容、真实读取锁、延迟提交失败与执行租约检查；知语原回归 210 个测试文件。最终通过记录和生产部署信息在下方补齐，不把开发运行等同生产装载。

初次隔离联调用错宿主测试用户表名，修正后通过；初次兼容测试暴露回执时间未按持久化返回，已改为由 Store 返回真实回执。类型检查中有一次源码格式化期间的 sourceStable=false，不作为最终通过证据。失败日志保留于本地 `.runtime/memory-g1-20261021` 和测试迭代目录。

G1 只具备 R 级记录接入，未迁移知语策略、审核、召回与出站到通用核心；这些能力在知语现有链路继续工作。新模块不声称完成独立通用知识系统。
