# 真实业务连续运行观察（2026-10-18）

本次没有证明自然业务中的整个记忆闭环。旧记忆召回和 Loop 运行反馈接力已有真实证据；新增持久记忆、自然纠错及新研究检查点继承仍未证明。此前受控练习的严格通过结果保持原样，不能外推到本次未加提示的业务任务。

## 范围与方法

选择既有技术研究车间的既有“项目理解与技术机会”Loop，沿用真实目标、原 Skill、来源、模型、工具和校验规则；不植入记忆、纠错或专门验收提示，不代替主人审核。每轮正常工具预算 40，最多 48 次物理模型请求、900 秒。原始事件、数据库状态、实际提供方请求、工具回执和下一轮输入分别核对；日志、报告、候选记忆和可召回持久记忆分开判断。

## 首轮故障与修复

BIZ1 一次手动命令在主模型前失败，被自动恢复三次，实际四代执行、九次辅助请求，主请求零次；已正式取消并确认旧进程退出。原始单代证据收集器拒绝恢复后的 fencing token，失败记录保留，没有改写成通过。

带真实配置的离线重放复现了定时 cheap 档 6,000 字符上下文不足。自由研究员在没有显式预算时改用 full 默认档，完整角色、权限和既有硬上限继续生效；其他控制器及显式档位不变。另修复执行器抛错后结果未持久化、终态提交冲突导致重复恢复的问题：先在有权事务中写失败结果和事件，再后处理，恢复只重放结果。原始包装错误没有保存内层异常，不能声称已唯一还原首轮的全部原因。

99 项针对性单测、13 项观察器边界测试、隔离 PostgreSQL 真实事务、构建前后类型检查和生产构建通过。隔离事务确认失败释放占用、同命令重放不重复执行。修复后的生产构建为 review92；BIZ2、BIZ3 使用相同程序，数据库业务配置和 Skill 均未修改。

## 四项结论

- 保存：原始事件、报告与运行状态存在；本次新增持久记忆回执为 0，不声称新经验已保存。
- 召回：观察到原有记忆进入真实模型请求，并核对当前修订版本。召回并不证明结论正确或模型正确使用。
- 纠错：没有新持久纠错样本完成版本化采纳与后续复用，暂不通过。运行失败反馈不是主人记忆纠错的替代证明。
- 跨轮：运行反馈接力成立；新增研究经验接力未证明。这个未修改业务配置没有 workingMemory 工具，LOG 保存和源绑定检查点接续均未观察到。

## 遗留与下一步

P1：定位正常业务结构化输出及提取问题；让普通业务的研究检查点通过明确的持久化与审核路径进入后续上下文；设计通用 workingMemory 准入，解除与专门研究合同的耦合。不得用新增验收提示、自动审核或降低来源标准代替修复。

另有真实工具失败：网页续读曾遗漏必填 URL，第三轮还出现一次证据快照不可用。同类参数错误没有在下一轮稳定避免，部分调用靠模型重新读取后继续；因此“主执行正常结束”也不表示所有辅助工具调用均成功。

P2：桌面运行记录中的部分研究步骤被解释成交易场景，报告解析失败时摘要也失真；本次已现场观察，尚未修复。当前窗口没有扩大到其他业务车间或手机端。

收尾已移除临时模型观察钩子，生产 Web 与 worker 在线，所选车间没有未结束运行，原目标和数据库状态保持原样。当前 worker 仍仅运行所选车间的 loop-execution 模块；没有开启其他车间或定时准入，不代表完整后台生产组合已经回测。
