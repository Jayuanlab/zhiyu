## 已实现的闭环

- 桌面侧栏「首页」及根地址展示每日计划，旧 `/?page=personal-day` 兼容到同一个结果页。日常只需自然语言反馈，不逐项选择完成比例、临时事件、生成或采用。
- 首页只读不创建、启用或恢复车间。首次设置建立一个真实 Work 绑定；已有档案、食物、资料、历史和旧关联车间复用。开启维护时明确授权内部事实整理、计划发布和模型数据范围。默认每日 21:00 检查明日安排，时段可在车间修改。首次开启会在每日任务设置完成后立即请求同一个车间维护初次计划，不需额外输入生成指令。
- 身体档案、资料采用、详细记录、每日 Loop 和人工接管在关联车间。车间使命、模型档位、权限及其配置指纹实际参与每次领域执行；共享 Pi 模型配置中心，不复制密钥。规划工作方式以车间使命、档案与已采用资料为准；专用 Loop 负责调度和权限，其通用目标/上下文元数据保留不代表新增第二份有效规划规则。
- 新增加密 `personal_daily_feedback`：原文、来源日期与来源入口独立于理解结果、计划及回执。原文先保存，再通过 Work Runtime 的真实命令进入持久化队列。暂停或排队异常不伪装理解完成；明确重试保留原记录及关联。
- Work/Loop 共用同一领域控制器、租约、心跳和写入围栏，不运行通用外部工具。开启维护不删除已存在的硬拒绝或禁用工具，修改既有 Loop 时段不重置动作和上下文规则；旧草稿车间若仍有禁止发布策略，会明确失败，不通过强制放开换取启用成功。宿主校验来源引用、明确数值、纠错目标、训练与过敏限制、时间冲突、资料范围、当前版本及 denied 优先。角色边界不靠 prompt 单独保证。
- 模型提议事实、当天条件与计划；宿主在一笔领域事务内保存理解、观察投影、计划前后版本、事件及处理结果。迟到结果不能覆盖并发档案编辑或已经更改的车间配置。已处理任务恢复时重放回执，不再次调用模型或写事实。
- 没有报告的行为、时长、份量保持未知；不把计划食材当作实际摄入。未明确时间的建议标为弹性安排，不填虚构钟点。更正追加关联，原始事实不改写。日计划发布保留已锁定事实和固定事项。
- 首页反馈摘要以实际写入计数及计划变更回执为准；模型说明单独展示。原始反馈、理解依据、当前计划、模型协议、模型中心版本、车间配置指纹可回溯。内部 Loop 与资料提取任务不冒充用户反馈展示。
- 档案或采用资料的主人编辑会请求同一个车间重新核对；待核对原计划在首页明确标识，不继续当作当前可执行建议展示。详细记录统计自然反馈理解层，旧逐项记录单独保留。
- 资料上传与采用继续受主人控制；模型提取作为真实 Work 任务运行，原则候选与加密处理回执原子保存，不能提取后自动采用。只覆盖前 12000 字符，限制明确展示。
- 传给模型的固定事项标题在当天条件、有效计划、草稿与计划变化字段中一并隐藏；只提供占用时间，服务器原始标题保留。新增隐私投影回归测试，不仅检查最外层时间条件。
- 车间内保留暂停、自然语言纠错、旧计划可行部分恢复、草稿人工确认、完整导出与明确文字确认删除。暂停维护同时暂停每日 Loop。恢复工作方式不会删除后来发生的实际事实。

## 适用范围与遗留

- 桌面 Web 及必要后端；未做移动端、原生客户端专项验收。
- 当前动作/食谱仍是有限宿主目录，不把任意资料自动变成可执行医学处方。导入资料只有主人采用的原则在其授权范围内进入模型；OCR、设备同步、外部日历和消息仍后置。
- 读取窗口为最近 60 个计划日期、1000 条事件、200 条反馈；完整历史保留，可导出。未知实际份量不提供伪精确热量或完成率。
- 维护范围以主人已授权的内部数据和建议为限。长期目标、权限、外部动作仍须原有主人配置或审核机制，模型不能自行扩权。
- 首页原文加密保存且不复制进通用 Work 运行日志。用户主动在车间原有对话入口发送的内容仍遵循原有对话存储；删除领域数据不会删除这些独立对话、通用审计、部署备份或外部模型已接收的数据。
- 正式账户已有档案，实施不预填或覆盖其身体事实；发布前保存最新数据库备份和档案指纹。原有量化 `paper_migration_required` 不在本次范围，不掩盖或标为修复。

后续体验事项（P2）：关联车间被物理删除后的受控重建入口、多窗口编辑档案的变更提醒、餐食克数及训练组重的更细标准化。当前自然语言事实保留原文、日期、明确时长/体重/睡眠和更正依据；不把原文自动冒充已完成的营养核算。旧的详细记录与原始数据保留于完整导出，后续统一细项展示。
