# 统一记忆入口：证据展开验收

## 实施范围

本阶段增加 askMemory.reads，支持已公布的平台源码 ID 和知识库文档 ID；复用最终授权工具，不创建独立的所有者读取器。检索域可以为空，但至少需要一个有效读取请求。搜索、展开共用每轮八次委托预算，重复页不重复读取，正文预算用尽则返回可继续读取的缺口。每个子读取使用不同调用 ID，保留审计对应关系。

文档增加可选 offset / expectedHash：每次返回至多 8,000 个 UTF-16 单元、内容 SHA-256、nextOffset、文档 ID 和读取时间。哈希不匹配时返回 version_changed 并停止返回正文，避免混合版本。未传分页参数的旧调用保持原行为。底层仍加载全文后切片，尚不是数据库层流式分页；源码读取原有行号分页未增加历史版本存储。

统一入口返回 requestedDomains、observedDomains、gaps 和 answerCompleteness:not_verified，既标明获取证据的进度，也明确未自动证明答案充分、全部需求已选中或所有运行路径已验证。失败和缺少工具不自动改用其他来源。

## 测试与开发验证

- 六个相关测试文件，81 项通过。覆盖文档分段无遗漏重建、版本变化、空内容、非法偏移、权限检查先于正文读取、委托工具拒绝不可穿透、来源展开和重复页抑制，以及桌面和车间现有接线回归。
- 开发环境记录：`.runtime/evals/memory-access/2026-09-23T02-34-09-948Z/`。源码题通过 askMemory 两次读取 memory-policy，确认同用户检查先于 owner_override，并明确不能由此证明所有调用路径或部署状态。工具错误 0。
- 同轮文档题仅执行 listKnowledgeBaseDocuments，返回当前所有者知识库为空，模型如实停止。该请求完成不代表真实文档分段已验收；没有为了测试向用户知识库写入虚构文档。非空、长文档和版本变化由接口测试覆盖，真实非空文档回测仍缺少数据。
- 初始 Next CLI 开发启动因其子进程未保留 hostname 参数而被现有绑定检查拒绝；改用项目已有 start-local-development.mjs，以明确回环地址启动，没有放宽绑定规则。

本阶段不等于整体目标完成：自由问题需求拆分、全部历史版本、语义检索恢复、跨来源完整性和长期反馈闭环仍需后续开发。只读查询没有改动真实车间授权，也未启动后台调度和外部消息发送。

## 真实源码读取输入

```json
{
  "question": "请读取 platform_source memory-policy 的完整内容，确认同用户检查和 owner_override 的执行顺序",
  "domains": [],
  "reads": [{ "kind": "platform_source", "id": "memory-policy" }]
}
```

返回来源为 `apps/web/lib/brain/policy.ts`，首段 1–120 行，带 contentHash 与 nextLine:121；模型随后提交 startLine:121。完整原始输入输出保留在上述 source-expansion.json。此题点名接口，属于能力验收，不作为自然问题自动路由准确率证据。
