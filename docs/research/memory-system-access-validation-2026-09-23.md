# 记忆系统整体访问能力：实施与真实验证

本轮目标由 Jev 调优扩大到智能体对自身、平台、长期记忆、文档及已授权外界的信息访问。方案见 [整体方案](../plans/memory-system-complete-access-2026-09-23.md)。本记录不将“查询完成”当作“知道所有事实”。

## 实际修改

- 新增 `askMemory`，组合 self / platform / memory / knowledge / external。返回每域证据、来源工具、时间、覆盖限制、缺口、截断和剩余读取预算。每个实例最多委托 8 次读取，相同域及查询不重复执行；单次证据正文总量受限。没有自动写记忆或新增后台任务。
- 桌面 Pi 和 Pi 车间复用最终授权工具；底层拒绝仍有效。车间入口不包含需要审批的来源工具，并记录外层与实际来源调用事件。已配置严格工具清单的车间不会自动新增 askMemory 权限。
- self 返回本轮身份、工具目录；桌面对话还返回实际模型配置标识。平台模板目录明确不等于运行时权限；桌面 platformRecall 的 tools 部分使用本轮权限投影。配置标识不等于独立验证供应商身份。
- 新增 `readPlatformSource` 固定白名单读取实际架构、记忆策略、选择逻辑、召回与运行权限代码，返回行号、下一页和内容哈希；拒绝任意路径及指向其他文件的链接。用于核对来源片段，避免拼造仓库 URL。部署环境没有源文件时明确失败，不假装已经读到。
- 文档限定检索不会顺带读取个人记忆；memory-only 与空/无效来源数组不再自动扩大检索源。
- 桌面对话的所有者记忆查询使用既有 owner_override 路径；Work 查询携带真正的 Work 身份、使用 strict，并禁止降级到 owner-wide 遗留发现源。未修改 grant，也没有让 Work 冒充系统/所有者。
- 记忆列表返回明确的未知总数和非全量标记。桌面统计问题在工具执行层禁止通过当前记忆列表计算，指向数据库聚合或历史快照证据；该检查覆盖已有会话，不依赖首轮澄清。
- 区分控制约束与答案候选证据：保留规则并不证明主题已回答，尤其不能用其他业务域规则证明记忆系统设计。
- 知识检索失败不再伪装“没有结果”。语义读取失败时在同一所有者和文档范围内进行有界数据库关键词降级，显式返回 degraded、provider、reason、warning，不伪造向量相似度。
- 桌面新增指定公开网页读取：验证 URL、连接时验证实际 DNS 地址、每跳验证重定向，禁止私有/本地/特殊地址、URL 凭证、非标准端口；不携带 cookie，不用第三方阅读器。15 秒超时、512 KB 输入上限、16,000 字正文上限，支持章节锚点。每轮最多 4 个不同页面，不反复读同一地址。
- 外部域必须提供单独的公开查询或公开 URL，内部查询结果不会自动拼进外网请求。工具结果是非可信证据，不能授予权限或触发写操作。

## 总体完成标准与尚未验收的部分

统一入口和上述恢复机制已实施，但整体目标尚未最终验收：

- 自由问题的需求拆分和主题相关性不能仅靠召回数量证明；仍需独立真实问题集、跨轮任务验收以及精确引用检查。
- 全部历史时刻不可从当前表重建。缺少有效版本/快照时继续报告不可验证，未伪造历史存储。
- 当前搜索供应商仍有 403；指定官方页路径可用，但动态页面、非 UTF-8 文本、全文超过读取预算的网页仍可能不完整。
- 关键词降级可用，但不能代替语义检索效果；当前知识题只验证了零命中及失败语义，未证明所有文档都可召回。
- Work 的统一入口沿用现有授权工具集合；该轮没有修改真实车间授权、自动运行真实任务或发布配置。
- 尚未新接未授权第三方账号/数据源；不存在的连接会返回不可用。没有把抓取内容直接晋升为已验证长期事实。
- Jev 继续保持原保守策略。上一轮 100 题高弃权率结论不变，本轮不能视为新的完整对照实验。

回测只使用隔离本地端口、关闭启动监听及调度；保留每轮问题证据，不覆盖失败记录。
