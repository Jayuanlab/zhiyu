# Jev 记忆证据检查实测

结论：Jev 在明确指定字段的证据检查上表现较好，但自然语言复合问题存在漏判，暂时保持旁路模式。尚未证明最终答案充分命中率提升。

## 数据与方法

- 来源：2026-09-19 的真实平台评测快照 `platform-memory-real-100/2026-09-19T04-07-03-002Z`。
- 从原集选择所有满足条件的 48 个单记录案例：必须有至少两个参考字段，且字段都存在于原始语料。覆盖 24 个数据域，包括车间、Loop、运行、审批、Brain、交互记录和交易计划。未覆盖全体架构、统计和权限题。
- 每个案例构造完整字段与移除一个字段两种输入，共 96 例。字段值直接来自 corpus，未向模型发送标准答案或预期分类。参考字段名用于构造受控实验，所以这属于理想证据投影测试，不是实际召回重放。
- 第一轮提问明确列出字段，允许显式 null 回答“未记录”；第二轮改为原评测自然语言问题，并明确历史快照时间。
- 使用线上集成的同一检查函数，固定模型 `jev-1.13.0`、并发 2、2 秒超时，不重试。充分阈值 ≥0.65，不足阈值 <0.35，中间记为不确定；阈值未按结果调优。
- 共 192 次真实 API 调用，不修改业务数据，不启用主动模式。

## 第一轮：明确字段，96 例

| 指标 | 结果 |
|---|---:|
| 总体符合预期，包含不确定及截断失败 | 90/96，93.75% |
| 完整证据判充分 | 45/48，93.75% |
| 缺字段判不足 | 45/48，93.75% |
| 缺字段误判充分 | 0/48 |
| 缺字段判不确定 | 3/48 |
| 完整证据误判不足 | 3/48 |
| 超时或接口失败 | 0/96 |
| 耗时中位数 / P95 / 最大 | 283 / 346 / 765 毫秒 |

六个输入受到当前单条 2,000 字符上限截断。三个完整证据误判不足均属于截断案例：REAL-008、REAL-012、REAL-029。未截断子集符合预期 87/90（96.67%），这只是诊断分组，不能替代整体结果。

三个不确定案例分别缺少 resolved_at（0.61）、source_event_ids（0.50）、content（0.59）。现有主动模式仅在 <0.35 时触发覆盖补查，因此这类灰区也不会自动触发该补查。

## 第二轮：原始自然语言问题，96 例

与字段缺失自动标签一致 73/96（76.04%）；完整组 38 个判充分，5 个判不足，5 个不确定；缺字段组 35 个判不足，9 个判充分，4 个不确定。中位数 290 毫秒，P95 375 毫秒，最大 748 毫秒；接口失败 0/96。

**这个一致率不是经人工验证的自然语言准确率。** 人工检查发现至少两处标签不适用：REAL-025 删除 model_tier，但原问题只问引擎、适配器和模型；REAL-030 删除 canonical_kind，但原问题问所有权、范围、证据与替代关系。REAL-004 的剩余 action_policy 中也包含 requiresApproval，不能仅凭删除 approval_policy 就断言证据不足。这些案例不应直接算 Jev 错误。未对全部案例重新人工标注，因此不发布修正后的准确率。

仍存在明确的危险漏判：

- REAL-013 问事件何时发生，移除 created_at 后仍给充分概率 0.73；capturedAt 是语料抓取时间，不能代替事件时间。
- REAL-034 问状态快照何时生成，移除 created_at 后仍给充分概率 0.87；抓取时间同样不能代替生成时间。
- REAL-033 问保存了什么状态，移除 content 后只剩类型与范围，仍给充分概率 0.96；知道状态类型不代表知道状态内容。

这说明“知道主题/类型”和“所有子问题都有证据”仍可能被混淆。

## 对当前接入的判断

1. 保持 shadow。速度适合作为辅助检查，但不能据此开启自动停止补查或丢弃低分证据。
2. 下一步把自然语言问题拆成明确的证据要求，并显式区分字段不存在、显式 null、抓取时间和事件时间。拆解自身也需要验证，不能靠本实验的参考字段在线作弊。
3. 修复证据打包时的粗暴字符截断：按结构保留关键字段，并显式报告缺失内容；不能把截断当事实不足。
4. 灰区采用保守处理，结合成本预算决定补查或说明缺证，不能默认充分。
5. 再做实际检索与最终回答的对照评测，包括原 100 题和未参与调优的新题；当前实验没有生成最终答案，没有验证召回率或答案命中率提升。

## 字段完整性修复与回测（同日）

实现 `evidence-requirements.ts`：在明确记录上检查所需字段，区分 present/null/empty/missing/truncated。显式字段问题按字段清单检查；自然语言目前仅识别常见的发生/生成时间、状态内容、来源记忆和范围表达。这是有限规则，不是完整语义拆题；不从评测答案导入运行时字段映射。带目标 ID 时仅检查匹配记录，其他记录不能补齐目标记录的缺字段。

保留模型原始 `modelSupport`；程序发现必要字段缺失时将用于决策的 `support` 上限设为 0.34。这个值是策略信号，不再代表纯模型概率。长字段使用带来源、字段名和偏移的 JSON 片段，短字段优先保留，不再直接切断 JSON；超出 12,000 字符单字段预算或整体预算时显式标为不完整。截断样本不能判充分。主动模式下不确定区间也允许一次已有替代表达补查，权限、警告及来源异常仍优先阻断。shadow 不向模型传递字段检查结论。
