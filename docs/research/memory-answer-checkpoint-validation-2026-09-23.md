# 完整快照后的回答核对验收

## 实现

brainListSnapshots 的精确读取增加 answerCheckpoint。仅在 status=read、offset=0、nextOffset=null 时出现，表示本次交付完整记录；部分页、末尾续页、来源失败和版本变化均不附加。快照原文和哈希表示不变。

桌面入口将可信原始问题传入读取器，模型工具参数不能覆盖。复用既有问题拆分器，保留未解析义务，最多处理 4,000 字符与 16 条要求，截断显式标记。没有原始问题时 questionKnown=false，不猜测任务要求。

节点只报告完整读取的来源、问题要求和若干运行字段的可用性，不给完整性分数。null 为 not_recorded，undefined 为 missing，有值为 present；字段存在不意味着语义支持。模型需要逐项核对：一个例子已经支持全部问题时回答，额外读取先明确未回答条款、时间要求、矛盾或原文缺页。比较、当前状态、全量历史等要求仍可能需要更多来源，不能被一个快照强行终止。

这是随结果交付的建议，未新增强制终止、自动事实写入或权限放宽；已有读取预算继续兜底。Work 等没有传原始问题的入口仅获得通用核对指引。本阶段没有承诺覆盖其他来源、跨页全文拼接或全局语义完备性判断。

## 测试

六文件 69 项针对性测试通过，覆盖完整与部分窗口、版本变化、不可信源文本不进入节点指令、null/缺失区分、原始问题不可改写、复合问题要求保留、未知/截断问题，以及既有快照/目录/预算/桌面工具接线。

真实验收使用原自然失败题，并新增“失败原因＋该次运行后来是否恢复”的复合问题，后者不能只凭失败快照给恢复结论。模型输入没有注入预期答案。开发与生产均关闭 scheduler/startup listeners，只走桌面 HTTP 读取链路。
