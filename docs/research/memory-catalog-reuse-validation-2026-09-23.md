# 目录观测复用与内容覆盖验收

## 本轮实现

新增实例内目录读取复用，仅用于成功的 brainListSnapshots(view:catalog)，按用户、Work、保存时间上界和类型过滤区分。相同查询 30 秒内保留原结果，返回 readReuse.reused、ageMs、sourceReadAt；coverage.observedAt 不刷新。每个实例最多八项、每项正文至多 64,000 字符。refresh:true 强制读取；失败不回退旧成功结果。精确快照、版本分页和列表始终读取来源，不受该复用影响。

复用执行于已有权限检查之后，重复调用仍有授权检查和工具审计。无跨用户或跨实例缓存，没有新增数据库或后台任务。目录 contentCoverage 明确标记 type_metadata_only、snapshotContentsRead:0，列明支持的数量/保存时间结论，以及不支持的内容不存在、类型不可能包含某事实、平台无历史能力等结论。

## 测试

五个相关文件 92 项通过，涵盖相同查询复用、过滤顺序归一、用户/Work/时间隔离、30 秒过期、强制刷新、失败不回退、空间上限、实例隔离、正文读取不复用以及缓存填充后工具被拒绝时不能读取缓存。另验证 null 非法过滤值不能与省略过滤条件共用键，避免复用键抹掉输入错误。未将复用误称为阻止模型再次调用工具；它减少的是同一观测的重复数据库读取。

## 开发环境真实回测

目录 `.runtime/evals/memory-access/2026-09-23T03-46-44-422Z/`：catalog-reuse 连续两次相同调用，第二次 reused:true、ageMs:2127，sourceReadAt 为 `2026-09-23T03:47:02.271Z`，模型正确报告目录只读取类型元数据、正文读取数量为零。该题明确指定两次调用，是接口验收，不是自然效率指标。

同轮 history 自然回归两次工具调用，无工具错误、未返回实时数量替代历史统计，但仍根据目录类型名推断没有专门记录所需统计的类型。不能将这题标为完整正确。结构化覆盖信息提升可观测性，尚未构成答案语义验证器。

本阶段没有改动桌面布局、真实权限、快照数据或调度。整体记忆目标仍未完成，尤其是事实缺失结论的可靠验证和跨来源问题完整性。
