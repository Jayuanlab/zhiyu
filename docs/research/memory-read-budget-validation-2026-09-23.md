# 共享读取预算验收

## 实现

在 Native Pi 工具创建时包装明确列出的证据读取 handler，再交给既有权限守卫。权限检查先于预算和去重；直接工具与 askMemory 使用相同实例，因此不能通过换入口获得新额度。每实例最多十次实际读取尝试，单次格式化结果至多 24,000 字符，累计至多 64,000 字符（UTF-16 单元）。并发完成时同步检查并提交支出，失败尝试也计数。

参数按对象键规范化后计算摘要，完全相同且成功/正在执行的请求不重复读取。超大结果整体扣留，重复同一超大请求也拒绝；来源异常可重试，但消耗尝试次数。目录保留显式复用和刷新，返回内容仍计入字符预算。分页游标、offset 和 expectedHash 均参与请求键，正常续读可用。

超限通过原工具守卫报告错误，trace 保留错误码和已用预算，不输出被扣留的原文。不静默截断 JSON，不将限制当作事实不存在。错误恢复指引提示历史运行先看有界快照样本中的原始词语，再精确展开或做字面搜索，未硬编码目标错误文字或快照 ID。

该预算保护指定读取工具的模型证据输出；不涵盖静态 manifest、车间自定义工具、错误消息、askMemory 包装开销或模型输出，也不约束一次读取的服务器成本。Work 复用 Native 工具实例时继承这些读取限制，但不是全 Work 的统一硬上限。每个新实例重新计数，未跨请求共享缓存或凭证。

## 测试

五文件 95 项通过。新增测试覆盖直接/委托共享、权限拒绝优先及错误审计、参数顺序去重、续页、新实例隔离、超大内容不泄漏、并发累计预算、十次失败重试后不再调用来源，以及目录复用。

初版测试暴露静态 manifest 结果大且无分页入口，套用本预算会使既有能力目录不可读，因此明确排除，保留原工具行为；不把这一排除声称为已完成预算治理。
